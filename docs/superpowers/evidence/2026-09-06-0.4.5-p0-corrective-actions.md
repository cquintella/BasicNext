## C-P0.1 & C-P0.1b (D1, D13): Module Honesty & Native Boundary

### As-Is Issue
`modules/bn/BNData.bn` and `modules/bn/BNMath.bn` contained placeholder return bodies (`RETURN 0`, `RETURN 0.0`, `NEW DataFrame()`) while real behavior is executed via `bn_rt` native intrinsics and the reference execution runtime. Furthermore, `BNMath.bn`'s `Limits` class contained floating-point constant initializers with scientific notation (`e38`, `e308`), which violates the BasicNext 0.4 lexical grammar (`docs/language/0.4/0.4.ebnf`), breaking LSP export parsing.

### Corrective Action
- Reverted invalid scientific float literals in `Limits` in `modules/bn/BNMath.bn` to standard grammar-compliant literals `0.0`. Compiler lowering already folds all `Limits` constants directly via `lowering/helpers.rs:math_constant` (`MAX_FLOAT32`, `MIN_FLOAT32`, `MAX_FLOAT64`, etc.).
- Embedded explicit `[NATIVE BINDING BOUNDARY]` governance headers in both `modules/bn/BNData.bn` and `modules/bn/BNMath.bn` referencing `docs/architecture/native-stdlib-binding.md` and approved AQ-22 direction (`EXTERN` with explicit stdlib and foreign-C profiles).
- Clarified that until AQ-22 syntax lands, the function and class signatures define the verified semantic API, while computation is dispatched directly to `bn_rt` and intrinsic runtime providers.

## C-P0.2 & C-P0.5 (D2, D12): Upfront Target Support & Mid-Emit Collapse

### As-Is Issue
`bn_llvm` previously allowed mid-emission support errors in `emission1.rs` and `emission_tail.rs`, mixing target support failures with code emission. Duplicate entry point string checks existed after `validate_for`, and comments referenced speculative future work.

### Corrective Action
- Every LLVM target capability and construct is now checked upfront in `analyze_function` / `validate_for` (`crates/bn_llvm/src/llvm/analysis.rs`).
- Mid-emit `unsupported_instruction` invocations in `emission1.rs` and `emission_tail.rs` were collapsed to clean `unreachable!` assertions with descriptive context, since `validate_for` strictly gates emission.
- In `crates/bn_llvm/src/lib.rs`, duplicate string lookups for `Start` were removed in favor of `expect("validated entry point")`.
- Target support rejections emit stable `TARGET_UNSUPPORTED_*` diagnostic codes:
  - `TARGET_UNSUPPORTED_ENTRYPOINT`
  - `TARGET_UNSUPPORTED_HOST`
  - `TARGET_UNSUPPORTED_TYPE`
  - `TARGET_UNSUPPORTED_OP`
  - `TARGET_UNSUPPORTED_LLVM`

## C-P0.3 (D3): Physical Ownership Extraction

### As-Is Issue
Modules were logically attributed to crates but physically located in root `src/` using `#[path = "../../../src/..."]`.

### Corrective Action
- `src/frontend_session.rs` was physically relocated to `crates/bn_frontend/src/frontend_session.rs`.
- The `#[path]` reference in `crates/bn_frontend/src/lib.rs` was removed; `pub mod frontend_session;` now resolves locally within `crates/bn_frontend/src/`.
- The root `src/frontend_session.rs` was deleted, and `src/lib.rs` exports `frontend_session` from `bn_frontend`.
- Physical extraction roadmap established for remaining frontend modules (`host_spec`, `token`, `ast`, `lexer`, `parser`, `semantic`, `module_graph`).

---

## C-P0.4 (D11): Language IR Validation Hardening (GC-IR)

### As-Is Issue
`crates/bn_ir/src/validate.rs` had contract validation gaps: `Member` and `SetMember` checked empty strings but lacked exhaustive opcode checks for identifier non-emptiness across all member-like and class-like instructions.

### Corrective Action
- In `crates/bn_ir/src/validate.rs`, added explicit validation ensuring class names, member names, and field paths are non-empty for:
  - `Instruction::Member`
  - `Instruction::SetMember`
  - `Instruction::SetField`
  - `Instruction::Allocate`
  - `Instruction::StoreStatic`
  - `Instruction::Delete`
- Added comprehensive negative test fixtures in `tests/validated_ir.rs` (`member_and_class_identity_names_cannot_be_empty`, etc.).
- All 32 IR validation fixtures pass.
