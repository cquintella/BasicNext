# 0.4.5 Expressive diagnostics (Fluent) and GATE G4 evidence

## Summary

This document records the completion of Section 4 activities (4.1–4.5) and the closing of GATE G4 for BasicNext 0.4.5.

## Architecture and catalog implementation

BasicNext diagnostics now follow the rustc-like expressive diagnostics architecture:
- **Registry and DiagId**: `bn_diag` maintains a typed `DiagId` registry covering 64 stable diagnostic identities across lexical, syntactic, semantic, IR lowering, target support, runtime, and build domains.
- **Inventory completeness**: `tests/test_diagnostic_inventory.py` confirms that 100% of stable codes emitted in `src/` and `crates/` are catalogued in the registry and Fluent shards.
- **Embedded Fluent shards**: Embedded `en-US` catalog shards (`lex.ftl`, `parse.ftl`, `sem.ftl`, `runtime.ftl`, `build.ftl`, `lsp.ftl`) provide structured title, message, and labels.
- **Discovery order**:
  1. `BN_DIAGNOSTICS_DIR` environment variable overlay if set.
  2. Executable-relative `share/bn/diagnostics/en-US` directory if present.
  3. Compiled-in embedded `en-US` catalog.
- **Lazy formatting**: Diagnostics capture code, arguments, and spans (`DiagnosticSpec`), delaying formatting until render or LSP publication.
- **Warning policy**: First-class warning levels (`allow`, `warn`, `error`/deny) configurable via CLI (`--allow`, `--warn`, `--deny`) and `config.toml`, with promotion of warnings to fatal build errors when configured.
- **LSP integration**: `to_lsp` maps structured catalog fields (title, message, causes, help, related information for secondary labels) to `LspDiagnostic`.
- **Language invariant**: The language-level `Error` object (`Code AS INTEGER`, `Message AS STRING`) remains completely unchanged.
