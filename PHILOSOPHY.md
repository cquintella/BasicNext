# Basic Next Philosophy

Basic Next is designed to reduce cognitive load and turn ideas into clear,
object-oriented, cross-platform software. It should make programming
pleasurable by preserving attention and helping programmers enter a state of
flow while reading and writing code. Its design is informed by Zen: clarity,
restraint, and deliberate choices over novelty.

## Mission

Make modern programming more readable, predictable, pleasurable, and
accessible through a small, explicitly typed, object-oriented language.

## Vision

Enable people to create software for capable environments without sacrificing
readability, explicitness, portability, or creative freedom.

## Design principles

1. **Low cognitive load** — common code should be easy to understand.
2. **Flow by clarity** — common code should preserve the programmer's
   attention: its intent is local, its rules are predictable, and its path from
   idea to feedback is short and comprehensible.
3. **Readability first** — source code is communication, not merely an
   instruction to a machine.
4. **Ideas into software** — useful abstractions should be direct to express.
5. **Object-oriented by default** — behavior belongs to cohesive objects;
   dependencies and boundaries should be explicit.
6. **Keep it simple (KISS)** — prefer the simplest construct that expresses an
   idea clearly. Complexity must earn its place through a concrete problem,
   not anticipation.
7. **Clean by design** — the language should make Clean Code and Clean
   Architecture natural to apply, without imposing a framework or prescribed
   architecture.
8. **Small core, broad reach** — libraries and host capabilities provide
   features; reserved words express only fundamental language concepts.
9. **Cross-platform through capabilities** — programs target `HOST`
   capabilities, not vendors or operating systems.
10. **Explicit contracts** — types, boundaries, and effects should not be
    surprising. Every variable and constant declaration states its type.
11. **Deliberate evolution** — the specification precedes implementation;
    proposals, examples, simplicity, and compatibility outweigh novelty.
