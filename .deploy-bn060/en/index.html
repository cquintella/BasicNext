Basic Next (or BN) is a programming language for people who want less language friction and more focus on software logic. 0.5.0 brings ARC — automatic memory for classes. 0.4 brought BNWeb and BNDispatch.

Current line · 0.5.0

The visible version is now 0.5.0 — ARC (automatic retain/release), no DELETE, with AS WEAK, optional RELEASE, and typed AWAIT. BNWeb and BNDispatch remain.

Basic Next is still experimentation — version 0, pre-alpha. It must not run business processes.

In the age of Artificial Intelligence, Basic Next is a language for humans. It was built as a low-friction interface between people and the machine. You can vibe-code applications without making them hard for humans to read. It follows object-oriented principles, and it was designed to be extensible and powerful.

How to start quickly

Install bn. Write. Run.

Download the binary from GitHub Releases (Linux, macOS, Windows), or build from the repository with Rust. Then: bn run.

1 · Releases

Ready-made binary

Grab your platform asset from GitHub Releases, put bn on your PATH, and go.

2 · From source

cargo install

With Rust installed, clone the repo and install the CLI:

cargo install --path .

Conversion

Fahrenheit → Celsius

Explicit types and clear arithmetic.

fahrenheit.bn
FUNCTION Start() AS VOID
  LET fahrenheit AS FLOAT = 98.6
  LET celsius AS FLOAT = (fahrenheit - 32.0) * 5.0 / 9.0
  PRINT "Celsius: ", celsius
END FUNCTION

Text

Word counter

Walk the string; count words with no hidden magic.

words.bn
FUNCTION CountWords(text AS STRING) AS INTEGER
  LET words AS INTEGER = 0
  LET inWord AS BOOLEAN = FALSE
  LET i AS INTEGER = 0
  WHILE i < LEN(text)
    LET ch AS STRING = text[i]
    IF ch = " " THEN
      inWord = FALSE
    ELSE IF NOT inWord THEN
      inWord = TRUE
      words += 1
    END IF
    i += 1
  END WHILE
  RETURN words
END FUNCTION

FUNCTION Start() AS VOID
  LET phrase AS STRING = "Basic Next lowers friction"
  PRINT "Words: ", CountWords(phrase)
END FUNCTION

Recursion

Factorial

The classic example from the repository.

factorial.bn
FUNCTION Factorial(value AS INTEGER) AS INTEGER
  IF value = 0 THEN
    RETURN 1
  ELSE
    RETURN value * Factorial(value - 1)
  END IF
END FUNCTION

FUNCTION Start() AS INTEGER
  LET value AS INTEGER = 10
  LET result AS INTEGER = Factorial(value)
  PRINT "Factorial of ", value, " is ", result
  RETURN 0
END FUNCTION

Loop

Sum 1 through N

Explicit accumulator, visible intent.

sum.bn
FUNCTION SumTo(n AS INTEGER) AS INTEGER
  LET total AS INTEGER = 0
  LET i AS INTEGER = 1
  WHILE i <= n
    total += i
    i += 1
  END WHILE
  RETURN total
END FUNCTION

FUNCTION Start() AS VOID
  PRINT "Sum 1..100 = ", SumTo(100)
END FUNCTION

Why use it

Concrete benefits — no empty marketing.

BN exists to cut friction between idea and program — and to teach with visible contracts.

1

Small core

Reserved words cover only the fundamentals. Everything else comes through imported modules.

2

Explicit typing

Every declaration states its type. No magic, no runtime surprises.

3

Host by capability

Programs target console, files, network — not Windows or Linux.

4

Built to teach

Types, memory, and control flow stay visible. Real learning without cryptic syntax.

Author’s note

Why I created Basic Next

Carlos Alvaro Quintela, from the book preface.

Words from the builder

Hello everyone. My name is Carlos Alvaro Quintela, and I want to introduce you to Basic Next—a programming language I created to solve a deeply personal pain point that I know affects many developers: the loss of intuition, fluidity, and genuine joy in turning ideas into software.

Programming used to be fun. For me, building a system or creating a game wasn’t an exercise in mental exhaustion, nor a battle against complex frameworks, endless configurations, and unnecessary verbosity.

When we program at our best, we enter what psychology calls the State of Flow—that moment of absolute focus where the tool vanishes, the mind connects directly with the system, and hours pass without us noticing. Idea → zero syntactic friction → program.

Throughout my career I’ve worked with dozens of languages and paradigms. With the rise of vibe coding we generate massive volumes of code—but staying trapped almost exclusively in Python, the language AI models tend to favor, doesn’t feel like the most rewarding experience for those who lived through the golden era of BASIC and Pascal. And while C remains one of my favorites, its cognitive load is extremely high: pointers and function pointers break Flow and drain energy away from creation.

Basic Next was born to eliminate that energy loss. It is engineered to be simple, powerful, intuitive, and to have an extremely low learning curve.

Core pillars: KISS (a small, predictable core); direct, frictionless writing; absolute transparency (mandatory types, explicit paths, no magic); modularity and extensibility; and a hardware isolation layer so you can port without rewriting the application.

It distills the best of several traditions—BASIC (clarity and excitement), Pascal (elegance and explicit declarations), C (minimalist core), C++ (practical OO), R (vectorized math)—and leaves behind Python’s implicit typing and historical friction, and Java’s bureaucracy of endless abstractions.

Beyond reclaiming Flow for experienced developers, the primary commitment is to be an exceptional educational tool: allocation, types, control flow, and memory stay understandable without cryptic syntax. Strict semantic analysis catches errors early and keeps learning as discovery rather than frustration.

Basic Next bridges rigorous software engineering, ease of learning, and pure creative freedom. It was built for those who want to create deterministic systems, teach the essence of computer science, and, above all, enter the Flow state and have fun programming again.

Thank you!

What’s new in 0.5.0

0.5.0 · automatic memory (ARC)

0.5.0 brings ARC for class instances, removes DELETE, adds AS WEAK, optional RELEASE, and typed AWAIT. 0.4 brought BNWeb and BNDispatch — still in the family. Still version 0 — experimentation, pre-alpha. Already on GitHub.

ARC

Automatic retain/release

Class instances use strong retain/release on assign, parameter, return, and end of scope. Zero strong → destructor, then free.

arc.bn
CLASS Counter
    PUBLIC count AS INTEGER = 0
    FUNCTION CONSTRUCTOR()
    END FUNCTION
    FUNCTION DESTRUCTOR()
        PRINT "Counter gone"
    END FUNCTION
    PUBLIC FUNCTION Inc() AS VOID
        count = count + 1
    END FUNCTION
END CLASS

FUNCTION Start() AS VOID
    LET c AS Counter = NEW Counter()
    c.Inc()
    PRINT c.count
    // c released at end of Start
END FUNCTION

Typed AWAIT

T OR Error result

When the worker is AS T OR Error, AWAIT ticket(ms) yields T OR Error. Tickets use Close — never DELETE.

await.bn
IMPORT BNDispatch AS Dispatch

ASYNC FUNCTION Worker(n AS INTEGER) AS INTEGER OR Error
    RETURN n * 2
END FUNCTION

FUNCTION Start() AS VOID OR Error
    LET queue AS Dispatch.Queue OR Error = Dispatch.Queue.Concurrent(4)
    IF queue IS Error THEN RETURN queue
    LET ticket AS Dispatch.Ticket OR Error = ASYNC queue Worker(21)
    IF ticket IS Error THEN RETURN ticket
    LET result AS INTEGER OR Error = AWAIT ticket(60000)
    IF result IS Error THEN RETURN result
    PRINT result
    RETURN ticket.Close()
END FUNCTION

No DELETE

Keyword purged

DELETE is gone from the language. Prefer end of scope or reassignment; ARC releases the last strong.

WEAK

AS WEAK ClassName

Weak references break cycles. When the object dies, the weak reads as NULL.

RELEASE

Optional advanced

Early end of a whole binding. RELEASE a[i] is invalid. Hello may omit it and leave scope.

BNWeb

Serve pages from BN

HTTP with the same explicit contract as the rest of the runtime. Still in the 0.4 family.

hello-web.bn
IMPORT BNWeb AS Web

FUNCTION Hello(req AS Web.Request, res AS Web.Response) AS VOID
  res.Write("<h1>Hello World</h1>")
END FUNCTION

FUNCTION Start() AS VOID
  LET server AS Web.Server = Web.Server.New()
  server.Route("GET", "/", Hello)
  server.Start("127.0.0.1:8080")
END FUNCTION

BNDispatch

Parallelism + typed AWAIT

Dispatch work in parallel. In 0.5.0, typed AWAIT closes the ticket contract.

count.bn
IMPORT BNDispatch AS Dispatch

FUNCTION Count1to10() AS VOID
  LET n AS INTEGER = 1
  WHILE n <= 10
    PRINT n
    n += 1
  END WHILE
END FUNCTION

FUNCTION Start() AS VOID
  LET queue AS Dispatch.Queue = Dispatch.Queue.Concurrent(10)
  queue.Async(Count1to10)
  // … more groups in parallel
  queue.Join(5000)
  queue.Close(1000)
END FUNCTION

Why the new architecture

Source → frontend → IR → interpret or compile.

In plain language: your program goes through an analyzer (frontend), becomes a typed intermediate representation (IR), and from there is either interpreted or compiled.

The path of the code

You write .bn. The frontend (lexer, parser, semantic analysis) validates and produces typed IR. Then:

Interpretbn run — the interpreter is the language reference.
Compilebn build — emits LLVM / an artifact for the supported subset.
Checkbn check — precise diagnostics with source locations.

Why split into crates

The Rust project is split into clear pieces (frontend, IR, interpreter, emitter) so each part has an obvious job. That makes the specification easier to review, test, and evolve without one opaque monolith.

The interpreter stays the reference: if something is not yet in the compiler, the “official” behavior is what bn run does.
