# 0.4.5 diagnostic bridge

## Scope

The CLI now routes `Diagnostic` values through the process-wide
`bn_diag::Catalog` selected by `BN_DIAGNOSTICS_DIR` (or the embedded catalog)
when their legacy code has a registered mapping. The registry now covers the
existing lexical, parser, semantic, IR, target-support, runtime and build
codes: each becomes a `DiagnosticSpec` with the original message as an
argument and a primary source label. Unknown codes retain the legacy renderer
through an explicit fallback, so this slice does not fabricate identities or
alter their semantics.

The catalog messages for migrated codes accept `{$message}`, preserving
contextual messages such as unterminated literals, grammar expectations and
target-specific failures. The BN `Error` value is unchanged.
