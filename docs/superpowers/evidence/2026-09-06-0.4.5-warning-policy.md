# 0.4.5 warning policy foundation

## Scope

`bn_diag` now owns the warning-level policy for `allow`, `warn` and `error`.
The parser accepts the normative `[warnings]` and `[warnings.levels]` subset of
`config.toml`, rejects unknown diagnostic codes, invalid levels, `allow` as a
global default and attempts to allow hard errors. CLI options
`--warnings errors`, `--allow CODE`, `--warn CODE` and `--deny CODE` are parsed
into the same typed policy. Precedence is CLI per-code, global promotion,
config per-code, config default, then registry default.

The policy is passed into CLI catalog rendering. Allowed catalog-backed
diagnostics are not rendered; promoted warnings use the error prefix. Semantic
analysis now has a warning-collecting API: `UNREACHABLE_CODE` is collected while
analysis continues, and post-analysis symbol resolution emits
`UNUSED_BINDING`/`UNUSED_IMPORT` without textual name matching. The original
fatal-only APIs remain compatible.
