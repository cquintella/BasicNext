## Highlights

- **Automatic reference counting (ARC)** is the class lifetime model on **both** backends (`bn run` and `bn build` / LLVM).
- Strong assignments retain; the last strong reference runs the destructor; **`AS WEAK`** bindings become `NULL` when the object is destroyed.
- **`RELEASE`** ends one binding early (optional / advanced). The **`DELETE` keyword is purged** from the 0.5 language DNA (Host resources keep `Close` / `*_close`).
- **Typed `AWAIT` → `T OR Error`** for `BNDispatch` / async workers (primary API); fixtures and native parity included in the claim.
- Conformance fixtures **F1–F13** green on interpret **and** native (see the ARC conformance notes under [`language/0.5/arc-conformance.md`](../../language/0.5/arc-conformance.md)).

## Toolchain

- Capability catalog / parity coverage expanded for the supported IR subset.
- Filesystem policy hardening on the compiled path (sandbox roots re-checked in `bn_rt`).

## Not in 0.5.0

- Unowned references; promoting Host handles to ARC classes in the same slice.
- Closing every historical compile-matrix gap unrelated to ARC.
- `bn eval`, Fluent diagnostics catalog as the DX1 claim, ordered `--module-path`, and `HOST.Exec` (those ship in **0.5.1**).

## Upgrade notes

1. Replace any teaching use of `DELETE` with end-of-scope release or `RELEASE` on a **binding**.
2. Prefer `AS WEAK T` (or `AS WEAK T OR NULL`) for non-owning links; do not assume force-dispose.
3. Async callers should treat `AWAIT` as producing `T OR Error`, not a bare ticket result as the primary API.
4. Re-run ARC fixtures or your object-heavy tests under both `bn run` and `bn build` if you maintain native artifacts.
