- **Status:** Fixed

## Implementation Summary

- **Activity 2a.1 (Fixed):** `bn_rt_clock_now` and `bn_rt_clock_timer` in `crates/bn_rt/src/lib.rs` are now gated with `policy::allows(policy::POLICY_CLOCK)`. When the policy denies clock access, both entry points emit diagnostic `"EXECUTION_POLICY_DENIED"` (`"HOST.Clock is denied by execution policy"`) and return `-1` with no clock side effects. Verified by test `clock_functions_respect_policy_clock`.
- **Activity 2a.2 (Fixed):** Grep and code audit of policy bit usage across `crates/bn_rt`, `crates/bn_llvm`, and `docs/architecture/value-memory-abi.md`:
  - `POLICY_CLOCK`: enforced in `bn_rt_clock_now` and `bn_rt_clock_timer`.
  - `POLICY_CONSOLE`: enforced across all Console entry points (`bn_rt_console_cls`, `bn_rt_console_beep`, `bn_rt_console_print_at`, `bn_rt_console_num_cols`, `bn_rt_console_num_rows`).
  - `POLICY_NET`: enforced across all Net entry points (`bn_rt_net_*`).
  - `POLICY_DISPATCH`: enforced across all Dispatch entry points (`bn_rt_dispatch_*`).
  - `POLICY_FILESYSTEM` & `POLICY_RANDOM`: audit verified that native compilation currently lowers Random via an internal PRNG state (`%rng = alloca i64`) and does not yet lower FileSystem to `bn_rt` native calls. Their execution policy is enforced interpret-only via `HostEnv` / `Capabilities`. `docs/architecture/value-memory-abi.md` was explicitly updated to document this exact boundary, ensuring no ABI doc implies native coverage that the code lacks.
