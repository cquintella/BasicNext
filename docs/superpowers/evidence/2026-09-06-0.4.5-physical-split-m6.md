# 0.4.5 physical split and GC-EXT evidence

## Summary

This document records the completion of Section 3 (M6) physical crate extraction and the GC-EXT contract verification log for BasicNext 0.4.5.

## Physical crate extraction (C-P0.3)

All path-backed frontend modules previously residing under `src/` were physically relocated to `crates/bn_frontend/src/`:

- `ast.rs`
- `host_spec.rs` and `host_spec/` (`members1.rs`, `members2.rs`, `members3.rs`, `members4.rs`)
- `keyword_registry.rs`
- `lexer.rs`
- `module_graph.rs`
- `parser.rs` and `parser/` (`expressions.rs`, `phase1.rs`, `phase2.rs`, `phase3.rs`, `phase4.rs`)
- `semantic.rs` and `semantic/` (`analyzer1.rs` through `analyzer8.rs`, `declarations.rs`, `helpers1.rs`..`helpers3.rs`, `host_defaults.rs`, `module_analysis.rs`, `type_names.rs`, `type_ops.rs`, `types.rs`)
- `token.rs`

All `#[path = "../../../src/..."]` shims in `crates/bn_frontend/src/lib.rs` and `crates/bn_frontend/build.rs` have been completely removed. Root `src/lib.rs` acts strictly as a facade re-exporting the frontend API from `bn_frontend`.

## Activity 3.5 — `bn` binary as wiring

`src/main.rs` contains solely CLI option parsing, process logging orchestration, and invocation wiring:
- Frontend analysis: delegates to `bn_frontend` (`load_with_session`, `analyze_modules_with_warnings`, `lower_module`).
- IR validation: delegates to `bn_ir` (`validate_module`).
- Target support: delegates to `bn_llvm::validate_for`.
- Native/Wasm code generation: delegates to `bn_llvm::lower_validated_module_for_target`.
- Interpreter execution: delegates to runtime execution primitives (`execute_validated_with_host`).
- Tooling protocols: delegates to `bn::lsp::run_stdio` and `bn::dap::run_stdio`.

No AST, lowering, validator, or compiler logic is implemented in `main.rs`.

## GC-EXT contract verification

Every contract gate was re-evaluated against the physically split workspace:

- **GC-IR (IR contract minimum & well-formed handoff)**: Confirmed. Lowering in `bn_frontend` emits validated IR checked by `bn_ir::validate`. Both runtime interpreter and LLVM backend strictly consume `ValidatedModule`.
- **GC-SUP (`validate` ≠ target support)**: Confirmed. Target unsupported ops fail `bn_llvm::validate_for` before emission.
- **GC-DEP (No semantic leak)**: Confirmed. `bn_ir` depends only on `bn_source`, `bn_types`, and `bn_diag`. No frontend types leak into `bn_ir` public model or backends.
- **GC-FE (Shared session)**: Confirmed. CLI and LSP share `FrontendSession` and produce identical diagnostic sets on shared fixtures (`*-lsp-check-equivalence.md`).
- **GC-POL (Execution policy)**: Confirmed. Execution policy carrier is propagated and re-checked at the call boundary in `bn_rt` (`*-execution-policy-carrier.md`).
- **GC-PAR (Feature-scoped parity)**: Confirmed. Claimed matrix rows are mapped to pertinent non-happy path test families (`*-gc-par-mapping.md`).
