# Bucket 0.4.5 — BNMath native parity slice

Date: 2026-09-06

## Implemented

- Reused the existing `bn_rt_math_*` implementations from the interpreted
  BNMath scalar floating-point path instead of duplicating the formulas in
  `src/runtime/executor.rs`.
- Covered absolute value, min/max, sign, rounding, elementary functions,
  powers, trigonometric functions, `HYPOT` and `FMA`.
- Moved floating-vector reductions (`MEAN`, `MEDIAN`, `QUARTILE1`,
  `QUARTILE3`, `MODE`, `STDEV`, `VARIANCE` and `RANGE`) into `bn_rt` and
  exposed the matching `bn_rt_math_*_f64` ABI. The interpreter now adapts its
  `Value` vectors to that shared implementation.
- Added a compiler parity fixture using `FLOAT[4]` with `MEAN`, `MEDIAN` and
  vector `MAX`; the LLVM path links the `*_f64` symbols from the same static
  `bn_rt` library used by the native runtime.
- Extended the language IR call contract for the documented one-vector
  `MIN/MAX` overload, including numeric regions, without weakening ordinary
  function arity/type checks. Named imported class aliases are also preserved
  at the IR handoff where a module-qualified `Named` spelling denotes the same
  imported class.
- Preserved the executor's BN-specific argument conversion and diagnostic
  channel; integer-width handling and vector reductions remain separate until
  their ABI contracts are complete.
- Moved the dependency-free CSV parser used by `BNData.ReadCSV` into
  `bn_rt::parse_csv`; the root DataFrame module is now only a compatibility
  facade for this logic.
- Moved the generic DataFrame schema, duplicate-label check and four join
  modes into `bn_rt` as well. This reusable core has no dependency on the
  interpreter `Value` model.
