# Bucket 0.4.5 — source identity propagation

Date: 2026-09-06

## Implemented

- Added stable `SourceId` and content-derived `Revision` values to
  `bn_source::SourceFile`.
- Carried both values through `Position` and exposed them from `Span`.
- Updated the lexer so every token span for a source file carries that file's
  identity and revision.
- Marked manually constructed/synthetic positions with explicit unknown
  constants instead of fabricating a source identity.
- Added unit and lexer integration assertions for stable identity and revision
  changes.
- Connected the existing LSP `didOpen`/`didChange` publication path to
  `FrontendSession`: URI identities are reused, revisions advance per update,
  and diagnostics are published only after the request still matches the
  current snapshot.
- Added `module_graph::load_with_session`, so filesystem-loaded modules record
  immutable snapshots in the same session boundary. The CLI frontend loader
  now uses this path for `check`, `run`, and `build`.
- Fixed session freshness after replacement: the new revision is immediately
  requestable while older requests remain rejected. Added explicit
  request-scoped cancellation and source removal/reopen semantics, including
  tests for invalidation and monotonic revisions.
- Added `module_graph::load_with_overlays`, which resolves normalized
  in-memory buffers before disk and reuses an unchanged session revision.
  The LSP diagnostic path now runs the complete shared graph pipeline through
  semantic analysis, lowering and language `validate`; a regression fixture
  proves an unsaved imported module changes the root diagnostic without
  modifying the persisted source.
- LSP updates now republish diagnostics for every open document after the
  current revision passes the freshness check, so an imported-buffer edit
  refreshes dependent roots as well. The same fixture verifies that restoring
  the imported buffer removes the dependent diagnostic.
- Diagnostic collection now analyzes each graph once and routes every error
  and warning by normalized source identity to its matching open URI. The
  regression fixture verifies that a type error originating in an unsaved
  imported module is published on the module URI, not the root URI.
- Exposed the shared LSP diagnostic projection for integration verification.
  A multi-file golden now runs `bn check` and the LSP projection over the same
  root/imported-module fixture and requires the same diagnostic code, source
  owner and source line (`TYPE_MISMATCH` in `Module.bn:2`).
- Added a real stdio LSP protocol regression: opening a root and imported
  module, then changing the imported buffer, republishes diagnostics for the
  imported URI and the dependent root through the session freshness boundary.
- The stdio protocol regression also closes and reopens the same URI; the close
  removes its session snapshot/source mapping, and the reopened invalid program
  receives fresh `TYPE_MISMATCH` diagnostics.
