# Basic Next 0.6.1 — native crypto and JSON parity

**Tag:** `v0.6.1`.
**Base:** 0.6.0.
**Delivery lanes:** [`0.6.1b`](0.6.1b.md) and [`0.6.1c`](0.6.1c.md).

## Highlights

- **BNCrypto on both backends.** Digests, byte handles, authenticated
  encryption, HMAC/KDF, Ed25519, ECDSA P-256, ML-KEM, and ML-DSA run through
  `bni` and native `bnc` artifacts.
- **BNJson DOM on both backends.** Typed object/array construction, scalar and
  nested accessors, explicit `Clone`, move ownership for nested documents,
  and the existing bounded Parse/Stringify contract share the `bn_rt` JSON
  table.
- **Companion codecs.** Domain classes remain independent of JSON; sibling
  modules such as `BirdJson` expose `Encode(T) AS Json OR Error` and
  `Decode(Json) AS T OR Error`, preserving failures under interpretation and
  AOT compilation.
- **Documentation layout.** Active language specifications live under the
  top-level `language/` tree; contributor, governance, sponsorship, and
  trademark documents live under `docs/`.

## Compatibility and exclusions

The installed executables remain `bni` and `bnc`; the removed combined `bn`
command is not restored. This release does not add reflection, a `SERIALIZE`
keyword, `ToJson` methods on domain classes, generic object reflection, binary
codecs, JSON path queries, streaming JSON, or asynchronous JSON I/O.
