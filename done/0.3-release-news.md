# Basic Next 0.3 — Release news

Basic Next 0.3 is the rebuilt reference release of the language and its Rust
toolchain. This release replaces the former 0.2 implementation path with a
source-spanned frontend, a typed intermediate representation, a deterministic
interpreter, and a typed LLVM lowering path, while keeping the language core
small and explicitly object-oriented.

## What was rebuilt

- The lexer, recursive-descent/precedence parser, AST, semantic analyzer, typed
  IR, interpreter, and LLVM facade now form an explicit forward-only pipeline.
- Multi-binding `LET`, single-line `IF`, fixed vector dimensions, source-span
  diagnostics, imports, interfaces, classes, pointers, temporal values, and
  checked allocation behavior are covered by the accepted 0.3 contract.
- `HOST` remains the only built-in interface object. `BNJson`, `BNLog`, `BNWeb`,
  `BNData`, and `BNDispatch` are explicit external modules under `modules/bn/`.

## Host capabilities and standard modules

- `HOST.Net` provides bounded IPv4/IPv6 addressing, CIDR, resolution, TCP, UDP,
  timeouts, EOF, close, and capability-gated optional providers.
- `BNLog` provides bounded structured records, text/JSON output, transports,
  flush, close, escaping, and redaction.
- `BNWeb` provides the bounded request/response model, routing, filters,
  provenance, lifecycle, sessions, cookies, scraping, ACLs, and local HTTP/1.1,
  HTTP/2, and HTTPS server adapters.
- `BNDispatch` provides bounded serial and concurrent queues, named-function
  tasks, tickets, joins, groups, barriers, semaphores, mutexes, cancellation,
  and deterministic timeout/resource errors.
- `HOST.NumProcs()` exposes the logical processor count available to bounded
  dispatch selection.

## Compiler, tooling, and documentation

- LLVM lowering now uses the accepted numeric mapping (`INTEGER`/`INT32` →
  `i32`, `BYTE` → `i8`, `UINT64` → `i64`, `FLOAT32` → `float`, and `FLOAT64` →
  `double`), explicit blocks and terminators, overflow traps, and explicit
  `BUILD_LOWERING_UNAVAILABLE` diagnostics for unsupported operations.
- The Rust implementation was decomposed into responsibility-focused parser,
  semantic, IR, LLVM, runtime, CLI, networking, HTTP, web, LSP, and DAP
  modules. No Rust source file exceeds the 520-line project limit.
- Native LSP 3.18 and DAP subsets, the VS Code extension, the Jupyter adapter,
  the language book, external-module appendices, examples, and conformance
  records were updated for 0.3.

## Verification

The release gate passes the complete Cargo test suite, strict Clippy,
formatting, diff checks, parser/semantic/runtime/IR/codegen focused tests,
module checks, and local IPv4/IPv6 TCP/UDP example validation. The executable
record is [`0.3-conformance.md`](0.3-conformance.md); the complete work
breakdown is [`WBS-0.3.md`](WBS-0.3.md).

## Deliberate boundaries

The 0.3 release does not claim concurrent `BNWeb` transport callbacks,
transport access-log integration, HTTPS client/trust-root support, HTTP/3,
geolocation datasets, or unavailable host providers. Those items remain
explicitly deferred to the 0.4 forward plan rather than being silently implied
by the rebuilt implementation.
