## Highlights

Language / module-system surface for clearer libraries and safer OO:

| ID | Item | Summary |
| --- | --- | --- |
| **I1** | Qualified export import | `IMPORT Module.Export AS Alias` binds one exported type (e.g. `IMPORT BNString.String AS Str`) |
| **O2** | Explicit `OVERRIDE` | Overriding instance methods must mark `OVERRIDE`; `OVERRIDE_REQUIRED` / `OVERRIDE_WITHOUT_BASE` |
| **O3** | `PROTECTED` | Visibility for the declaring class and `EXTENDS` subclasses only; `PROTECTED_ACCESS` outside |
| **O4** | Static factories | Multiple construction via `PUBLIC STATIC FUNCTION` factories (path A); no constructor overload in this claim |
| **S1** | `++` / `--` | Statement-only sugar for `+= 1` / `-= 1`; illegal in expression position |

## Cut from this release

| ID | Item | Note |
| --- | --- | --- |
| **O1** | Safe class downcast → `T OR Error` | Deferred (needs constructible `Error`); tracked outside this tag |

## Not in 0.5.2

- `IMPORT X FROM M AS A`; multi-name import lists.
- Constructor overloads (path B) without a new lock.
- Multiple inheritance; generics; properties sugar.
- `BNSqlite` / FFI slice (**0.5.3**).

## Upgrade notes

1. Add `OVERRIDE` on intentional overrides; fix call sites that accidentally shadowed base methods.
2. Prefer `PROTECTED` instead of widening fields to `PUBLIC` for hierarchy-only state.
3. Prefer `IMPORT M.E AS A` when a consumer needs one type, not the whole module alias.
4. Use `x++` / `x--` only as statements; keep `+=` / `-=` when an expression is required.
5. Re-check editor grammars (e.g. [basicnext-vscode](https://github.com/cquintella/basicnext-vscode)) for `PROTECTED` / `OVERRIDE`.
