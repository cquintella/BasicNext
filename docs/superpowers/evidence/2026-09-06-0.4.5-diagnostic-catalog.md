# 0.4.5 embedded diagnostic catalog

## Scope

`bn_diag` now embeds six real Fluent-format `en-US` shards (`lex`, `parse`,
`sem`, `runtime`, `build`, `lsp`) and validates them against the Rust
`DiagId` registry (63 stable codes, including runtime and build diagnostics).
The supported loader checks unknown IDs, duplicate IDs,
duplicate display codes, required `.title`/`.code` attributes and registry
coverage. It performs argument substitution only from `DiagnosticSpec` during
render, after sink filtering and deduplication. The validated embedded catalog
is available through a process-wide `OnceLock`. The CLI can replace present
entries from `BN_DIAGNOSTICS_DIR` once per process; missing entries continue to
use the embedded catalog and invalid overlays are reported as tool errors.

The parser intentionally implements the catalog subset used by this release
(message values plus the documented attributes); it is not presented as a
general Fluent runtime. Legacy `Diagnostic` construction remains compatible;
lexical, parser and the currently registered pipeline diagnostics now bridge
through the catalog in both CLI and LSP paths while unmigrated codes retain the legacy renderer. See
[diagnostic bridge](2026-09-06-0.4.5-diagnostic-bridge.md).
