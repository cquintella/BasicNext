# Bucket 0.4.5 — Execution-policy foundation

Date: 2026-09-06

`bn_rt` now has a versioned permission mask with two monotonic operations:
artifact initialization intersects the existing ceiling, and launch-time
restriction intersects the effective mask. Neither operation can widen a
previous restriction. Console C ABI calls recheck the effective Console bit
before writing or querying the terminal. Network and dispatch operations also
recheck their capability bit; dispatch reports `BN_DISPATCH_POLICY_DENIED` and
resource-close operations remain available for cleanup. LLVM emits
`bn_rt_policy_init(version, ceiling)` in `Start`; the current module metadata
materializes Console, Filesystem and Net requirements into that ceiling.
The C ABI boundary is covered by a regression that installs a restricted
ceiling and verifies `bn_rt_console_beep` plus network-address queries return
the policy-denied status without reaching the host operation.

Verification:

```text
cargo test --package bn_rt console_c_abi_rechecks_execution_policy_at_call_boundary
1 passed
cargo test --package bn_rt policy::tests
2 passed
cargo clippy --workspace --all-targets -- -D warnings
passed
```

This is not GC-POL closure. Network and dispatch call-boundary checks, scoped
filesystem scope policy and native/wasm policy fixtures remain required.
