# Basic Next Language Specification 0.1 (Draft)

This specification defines the core required for small programs. Anything not
defined here is not part of Basic Next 0.1.

## Lexical structure

Source files use the `.bn` extension and are Unicode encoded as UTF-8. Spaces
and tabs separate tokens; a line ending separates statements. Leading
whitespace does not change syntax, scope, or execution. Indentation is optional
but strongly recommended to make block structure readable. Line continuation is
not part of 0.1.

Identifiers start with an ASCII letter or `_` and continue with ASCII letters,
digits, or `_`. They are case-sensitive: `counter`, `Counter`, and `COUNTER`
are different names.

Reserved words use the exact uppercase spelling shown in this specification.
Only that spelling is reserved: `PRINT` is the output statement, while `Print`
is a distinct identifier.

Line comments begin with `//` and end at the line ending. They are recognized
outside strings. Strings use double quotes, cannot span lines, and accept only
`\"` and `\\` escapes. Integer literals are decimal digit sequences (leading
zeros are allowed), binary literals use the `0b` prefix, and hexadecimal
literals use the `0x` prefix. Floating-point literals require digits on both
sides of a decimal point, such as `3.14`; `.5`, `1.`, exponent notation,
numeric separators, and suffixes are not 0.1 syntax. A literal is range-checked
after lexing, so overflow reports the literal and its source span.

Block comments begin with `/*` and end at the first subsequent `*/`. They may
span lines but cannot nest. Each physical line ending inside a block comment is
a statement-separating newline; an unterminated block comment is a lexical error
reported at its opening delimiter. Invalid UTF-8, a control character in a
string, and an unsupported escape are lexical errors. No comment delimiter is
recognized inside a string. The lexer uses maximal munch for overlapping symbols
and recognizes comments before `/` can be treated as an operator.

### Reserved words

The [keyword registry](keywords.md) records the meaning and decision status of
every keyword. The list below is the reserved set in this draft.

```text
AND       AS        BOOLEAN   BYTE      CLASS     CONST     CONSTRUCTOR
CONTINUE  DELETE    DESTRUCTOR EACH     ELSE      END       EOF       EXIT      EXPORT
EXTENDS   FALSE     FLOAT     FLOAT32   FLOAT64   FOR       FUNCTION  HOST
IMPLEMENTS IMPORT    IN        INPUT     INT8      INT16     INT32     INT64
INTEGER   INTERFACE
IS        LET       NEW
NA        NOT       NULL      OR        POINTER   PRIVATE   PRINT     PUBLIC
PARALLEL  REPEAT
RETURN    SELF      SHL       SHR       STATIC    STEP      STOP      STRING
STRUCT    SYSTEM    THEN      TIMESTAMP TRUE      UINT16    UINT32    UINT64    UNTIL     VOID

```

`NAN` and `INF` are case-sensitive special `FLOAT` literal tokens. They are not
keywords, but their exact spellings cannot be used as identifiers. `INF` is
positive infinity; `-INF` is unary negation applied to `INF` and denotes
negative infinity.

### Symbols

```text
+  -  *  /  **  %  =  <>  <  <=  >  >=  +=  -=  *=  /=  %=  **=
(  )  [  ]  ,  .
//  /*  */
" "
```

The lexer must recognize the longest valid symbol: for example, `<=` is not two
tokens (`<` and `=`), and `+=` is not `+` followed by `=`. Comment delimiters
take precedence over their component symbols: `/*` is not `/` followed by `*`.

### Structural grammar

The versioned EBNF is maintained in [0.1.ebnf](0.1.ebnf). It defines syntax
only; this document defines the meaning of valid programs. The grammar remains
a draft while version 0.1 is being completed.

Diagnostic presentation and stable identifiers are defined in
[diagnostics.md](diagnostics.md).

| Language area | Authoritative EBNF productions |
| --- | --- |
| Source files and modules | `source-file`, `program`, `import-declaration`, `declaration` |
| Types | `return-type`, `value-type`, `data-type`, `vector-type`, `pointer-type`, `function-type` |
| Blocks and statements | `statement-block`, `statement`, `if-statement`, `while-statement`, `repeat-statement`, `for-statement`, `return-statement`, `continue-statement`, `stop-statement` |
| Expressions | `expression` through `primary`, `call-expression`, `cast-suffix` |
| Lexical tokens | `reserved-word`, `identifier`, `literal`, and the lexical grammar section |

The grammar defines an implicit `NEWLINE` immediately before EOF when a source
file does not physically end with one. Therefore a final line ending is optional
in a `.bn` file. Imports precede declarations; blank and comment-only lines are
legal wherever a block admits a line. `EXTENDS` and `PARALLEL` remain reserved
lexical-only in 0.1: they cannot be identifiers and do not introduce executable
syntax in this version.

EBNF cannot prove that every completed path of a value-producing function
executes `RETURN expression`; that is a semantic rule defined below.

Basic Next 0.1 emits errors, not warnings. A diagnostic either rejects source
before execution or reports a runtime failure.

`bn check` exits with `0` for valid source, `1` for a BN error, and `2` for
invalid tool use or a tool failure. On normal completion, `bn run` propagates
the `0`–`255` code returned by `Start`; it uses `1` for a BN error and `2` for
invalid tool use or a tool failure.

## Types

Syntax: [type productions in `0.1.ebnf`](0.1.ebnf).

Primitive types are `BOOLEAN`, `BYTE`, `INT8`, `INT16`, `INT32`, `INT64`,
`UINT16`, `UINT32`, `UINT64`, `FLOAT32`, `FLOAT64`, `INTEGER`, `FLOAT`,
`TIMESTAMP`, `STRING`, and `VOID`. `FUNCTION(...) AS ...` is a callable value
type, not a primitive type; `VOID` remains valid only as a function return type.

Numeric types have a fixed representation across hosts:

| Type | Representation |
| --- | --- |
| `BYTE` | Unsigned 8-bit integer (`0` through `255`). |
| `INT8` | Signed 8-bit integer. |
| `INT16` | Signed 16-bit integer. |
| `INT32` | Signed 32-bit integer. |
| `INT64` | Signed 64-bit integer. |
| `UINT16` | Unsigned 16-bit integer. |
| `UINT32` | Unsigned 32-bit integer. |
| `UINT64` | Unsigned 64-bit integer. |
| `FLOAT32` | IEEE 754 binary32 floating-point value. |
| `FLOAT64` | IEEE 754 binary64 floating-point value. |
| `INTEGER` | Alias for `INT32`. |
| `FLOAT` | Alias for `FLOAT64`. |
| `TIMESTAMP` | Alias for `INT64`, representing a UTC Unix-epoch instant in nanoseconds. |

`INTEGER` and `FLOAT` are the default numeric spellings in ordinary program
code. The fixed-width forms are intended for binary data, memory access,
device interfaces, and cases where representation matters.

`FLOAT32` and `FLOAT` use the IEEE 754 value model: finite values, positive and
negative zero, positive and negative infinity, and not-a-number values. `NAN`
is a numeric value, not missing data: `NAN = NAN` is `FALSE`. `INF` is positive
infinity and `-INF` is negative infinity. `NA` is a missing observation and
`NULL` is the absence of an object, reference, or pointer. Both `NA` and `NULL`
must appear explicitly in an alternative type and must be tested with `IS`
before the other alternative is used.

`NAN` is unordered: `NAN < value`, `NAN > value`, `NAN <= value`, and
`NAN >= value` are all `FALSE`, for every numeric `value`. Consequently,
`NAN <> NAN` is `TRUE`. `value IS NAN` returns `TRUE` exactly when a `FLOAT32`
or `FLOAT` value is `NAN`; it is a static error for any other type. `value IS
INF` and `value IS -INF` test positive and negative infinity respectively and
are likewise valid only for `FLOAT32` or `FLOAT` values.

Declarations use `name AS TYPE`. Every `LET` and `CONST` declaration must state
its type explicitly; Basic Next has no inferred-binding form. `LET name AS TYPE
= expression` requires a compatible assignment. `CONST` uses the same typed
form, requires an initializer, and cannot be reassigned. `CONST` fixes its
binding only; it does not make a referenced class, vector, or pointed allocation
immutable. A mutable `LET` may
omit its initializer only when its declared type defines a default value. Such
a binding is initialized; BN has no uninitialized storage. In 0.1, `BOOLEAN`,
numeric types, and `STRING` default to `FALSE`, numeric zero, and `""`; a
`STRUCT` defaults recursively when all its fields do; and a fixed-size vector
defaults each element when its element type does. Alternative types, class or
interface references, pointers, and function values have no default and
require an initializer. A vector of named class or interface references must
use an explicit vector literal initializer; its elements are never silently
`NULL`.

BN uses lexical scopes. Each function or method body creates one local scope;
`IF`, `WHILE`, `REPEAT`, and `FOR` blocks do not create another. A local name
may hide a module-level name, but no name may be declared twice in the same
local scope, including parameters and loop bindings.

### Explicit conversion

An explicit conversion uses postfix `AS`:

```basic
LET count AS INTEGER = 3.9 AS INTEGER
LET ratio AS FLOAT = count AS FLOAT
LET byteValue AS BYTE = 255 AS BYTE
LET isEmpty AS BOOLEAN = "" AS BOOLEAN
LET hasText AS BOOLEAN = "A" AS BOOLEAN
LET isNull AS BOOLEAN = NULL AS BOOLEAN
LET isMissing AS BOOLEAN = NA AS BOOLEAN
LET isEndOfInput AS BOOLEAN = EOF AS BOOLEAN
```

Assignments have no implicit numeric conversion, including widening conversion.
Numeric expressions use only the explicit widening rules defined below; all
other conversions must be written explicitly. Numeric values may be converted
explicitly as defined below, or converted to `BOOLEAN`. A
`STRING` may be converted only to `BOOLEAN`. For a conversion to `BOOLEAN`, an
empty string and numeric zero become `FALSE`; a non-empty string and every
nonzero numeric value become `TRUE`. `NAN AS BOOLEAN` is `TRUE` because `NAN`
is not zero. `NULL AS BOOLEAN`, `NA AS BOOLEAN`, and `EOF AS BOOLEAN` are
`FALSE`. These conversions do not erase the original value: use `IS NA` or
`IS EOF` when the program must distinguish those states.

An integer literal is an exact, untyped integer while its expression is checked;
a floating literal is an exact, untyped `FLOAT` value. A literal adopts the
numeric type required by its declaration, assignment target, or other numeric
operand, and is a static error if its value cannot be represented there. Without
such a context, an integer literal is `INTEGER` and a floating literal is
`FLOAT`. This is literal typing, not an implicit conversion between declared
numeric values.

For numeric binary expressions, the signed widening sequence is `INT8 → INT16
→ INT32 → INT64` (including `INTEGER` as `INT32` and `TIMESTAMP` as `INT64`);
`BYTE` also widens to `INT16`. The unsigned widening sequence is `BYTE → UINT16 → UINT32 → UINT64`.
The result has the widest integral type present in its sequence. `FLOAT32` and
`FLOAT64` combine as `FLOAT64` (including its alias `FLOAT`). Integers and
floating-point values do not combine implicitly. `UINT16`, `UINT32`, and
`UINT64` do not combine implicitly with signed integral types; `BYTE` is the
sole unsigned exception because it widens safely to `INT16`.

`TIMESTAMP` and `INT64` are the same type for assignment, parameter passing,
conversion, and expressions. `TIMESTAMP` records the intended unit and epoch;
it does not introduce a separate runtime representation or prevent ordinary
`INT64` arithmetic.

Unary negation does not widen `BYTE`, `UINT16`, `UINT32`, or `UINT64`; write an
explicit conversion, such as `-(value AS INT16)`, before negating such a value.

An explicit conversion is permitted between any integral types, including
narrowing conversions and signed/unsigned changes. The runtime checks that the
source value fits the target range; otherwise it raises
`INVALID_NUMERIC_CONVERSION`. `INTEGER` follows `INT32` because it is its
alias. Converting a floating-point value to an integer truncates toward zero
and raises `INVALID_NUMERIC_CONVERSION` when the result is outside the target
range. Converting `NAN`, positive infinity, or negative infinity to an integer
raises `INVALID_NUMERIC_CONVERSION`. Converting to `FLOAT32` rounds to its IEEE
754 binary32 representation. `NAN` and both infinities convert to the
corresponding `FLOAT32` values; a finite `FLOAT` value that overflows `FLOAT32`
converts to the appropriately signed infinity.

Floating operations use IEEE 754 binary arithmetic in their result type, with
the `roundTiesToEven` rounding direction. They produce `NAN`, signed zero, and
signed infinities according to IEEE 754; floating overflow and floating
division by zero do not raise BN runtime errors. BN 0.1 does not expose IEEE
status flags, traps, NaN payloads, or a program-selectable rounding direction.

Every integral operation, including unary negation, arithmetic, exponentiation,
shifts, compound assignment, and counted-`FOR` binding updates, checks that its
result fits the destination type. A result outside that range raises the runtime
error `NUMERIC_OVERFLOW`; integer arithmetic never wraps or saturates.

`/` returns `FLOAT` for every numeric operand type and performs IEEE 754
floating-point division after its operands are represented as `FLOAT`. It never
performs implicit integer division or truncates a fractional result. A zero
divisor produces the IEEE 754 result: for example, `1 / 0` is `INF`, `-1 / 0`
is `-INF`, and `0 / 0` is `NAN`.

`**` is the only exponentiation operator. With integral operands, it applies
integral widening and returns the widest integral operand type. Its exponent
must be non-negative: a negative literal exponent is a static error and a
negative computed exponent raises `INVALID_EXPONENT`. With floating operands,
it applies floating widening, returns the promoted floating type, and implements
real power; its exponent may be negative. For example, `2.0 ** -1.0` evaluates
to `0.5`. Its floating special-value behavior is the same as
[`Math.POW`](../library/math.md). Integral and floating operands do not mix
implicitly.

`%` accepts integral operands only and raises `DIVISION_BY_ZERO` when its
divisor is zero. Its result uses Euclidean modulo: it is non-negative and
strictly smaller than the absolute value of the divisor. For example,
`-7 % 3` is `2`.

### Alternative types and end of input

`OR` lists explicitly allowed alternatives in a type declaration. There is no
separate `UNION` declaration form. Each alternative may appear only once; a
repeated alternative is a static error. Alternative order has no semantic
meaning.

```basic
LET line AS STRING OR EOF = INPUT()

IF line IS EOF THEN
    PRINT "input ended"
ELSE
    PRINT line
END IF
```

`EOF` is the singleton end-of-input value. `INPUT()` returns `STRING OR EOF`:
it returns `EOF` when standard input has ended rather than an empty string.
`NULL`, `NA`, and `EOF` are singleton values and compare equal to themselves;
`NAN` is the non-reflexive exception. `INF` and `-INF` compare equal to values
of the same signed infinity.
`value IS alternative` tests an allowed alternative and narrows `value` in the
corresponding branch. `IS Type` is valid only when `Type` is a declared
alternative of `value`; it is not a general runtime type test. In the `ELSE`
branch above, `line` is a `STRING`. Equality with `NULL`, `NA`, or `EOF` is
also permitted when that value is a declared alternative and narrows the same
way as the corresponding `IS` test. Inequality with one of those values also
narrows, with the branch facts inverted. Narrowing facts propagate through
`AND`, `OR`, and `NOT` according to their short-circuit evaluation paths. An
assignment is checked against the declared alternative type and then replaces
the narrowing fact with the type of its new value.

### Error values and parsing

`Error` is a standard-library object, not a language keyword. Fallible
operations return their normal value or an `Error` object:

```basic
LET value AS FLOAT OR Error = Float.TryParse(token)

IF value IS Error THEN
    PRINT value.Message
ELSE
    PRINT value
END IF
```

`Error` has public `Code AS INTEGER` and `Message AS STRING` fields. `TryParse`
names operations whose failure is an expected result; `Parse` requires success
and raises `PARSE_ERROR` at runtime on invalid input.

### Fixed-size vectors

A fixed-size vector is written as an element type followed by one or more
dimensions:

```basic
LET values AS INTEGER[10]
LET temperatures AS FLOAT[365]
LET primes AS INTEGER[5] = [2, 3, 5, 7, 11]
LET grid AS INTEGER[2][3] = [[1, 2, 3], [4, 5, 6]]

grid[1][2] = 9
```

Each dimension is a non-negative integer literal. `INTEGER[2][3]` is a vector
of two vectors, each with three `INTEGER` elements. Indices follow the same
order: `grid[row][column]`. Every index runs from `0` to one less than its
corresponding dimension; an out-of-range index raises `INDEX_OUT_OF_BOUNDS` at
runtime.
A fixed-size vector whose declared dimensions overflow its checked element or
byte-size calculation is a static error. A mathematically valid fixed vector
may still raise `ALLOCATION_TOO_LARGE` at runtime; BN defines no portable memory
limit.

A vector declaration without an initializer creates each scalar element with
its default value: `0`, `0.0`, `FALSE`, or `""`. A vector literal must match
the declared shape at every dimension. `VOID` cannot be a vector element type.

Vectors are mutable. Variable-size vectors and vector arithmetic are outside
0.1. Vector assignment and parameter passing copy elements; vectors do not
alias each other. When an element is a class or interface reference, the
reference is copied and continues to name the same object.

## Structs

A `STRUCT` declares a small value type with named public fields. Its fields may
have default values, but a struct has no methods, visibility modifiers,
constructors, destructors, interfaces, inheritance, or `STATIC` members.

```basic
STRUCT Point
    X AS FLOAT = 0.0
    Y AS FLOAT = 0.0
END STRUCT

LET origin AS Point
LET moved AS Point = origin
moved.X = 10.0
```

Struct declaration, assignment, and parameter passing use copies of the field
values. Thus changing `moved.X` does not change `origin.X`. `NEW` and `DELETE`
do not apply to structs. A class or interface reference field is copied as a
reference to the same object, not cloned.

## Classes and allocated memory

Class fields and members are `PRIVATE` by default. `PUBLIC` makes a member
available to code outside its class. Interface members must be implemented as
`PUBLIC`. Instance fields are initialized before `FUNCTION CONSTRUCTOR(...)`:
explicit field initializers run in source order, and a field without one uses
its type's default value when available. A field without a default requires an
initializer.

`PRIVATE` visibility is scoped to the declaring class: its methods may access
private members on any instance of that same class.

```basic
CLASS Customer
    PRIVATE id AS INTEGER

    PUBLIC FUNCTION CONSTRUCTOR(id AS INTEGER)
        SELF.id = id
    END FUNCTION
END CLASS
```

`NEW` is the only allocation form. It creates class instances or contiguous
typed memory. `DELETE` releases the allocation. There is no separate `MALLOC`
form. `NEW` instantiates only `CLASS`; `STRUCT` and `INTERFACE` cannot appear
as its named type.

```basic
LET value AS POINTER TO INTEGER = NEW INTEGER
value[0] = 42
DELETE value

LET samples AS POINTER TO FLOAT[4] = NEW FLOAT[4]
samples[0] = 1.5
DELETE samples
```

`POINTER TO TYPE` points to one value of `TYPE`; `POINTER TO TYPE[length]`
points to a fixed-size contiguous region. `POINTER TO TYPE[]` describes a
region whose size is supplied at runtime:

```basic
LET count AS INTEGER = 1024
LET samples AS POINTER TO FLOAT[] = NEW FLOAT[count]
```

An allocation assigned to `POINTER TO TYPE[length]` must have that exact
length. A mismatching literal count is a static error; a computed mismatch
raises `POINTER_LENGTH_MISMATCH` at runtime.
`POINTER TO TYPE[length]` is assignable to `POINTER TO TYPE[]`; the reverse
direction requires the same fixed-length check.

A dynamic allocation with count `0` is a valid empty region; every index into
it raises `INDEX_OUT_OF_BOUNDS`. A negative literal count is a static error; a
negative computed count raises `ALLOCATION_SIZE_INVALID` at runtime.
Before allocating, the runtime checks the element count and resulting byte size.
Arithmetic overflow raises `ALLOCATION_SIZE_OVERFLOW`; a valid size that exceeds
the host limit raises `ALLOCATION_TOO_LARGE`.

In 0.1, a pointer element is numeric; named types, `BOOLEAN`, and `STRING` are
deliberately excluded. Allocated numeric memory is initialized with the default
value of its element type. Pointer indexing is relative to the allocation and
is bounds-checked; an invalid index raises `INDEX_OUT_OF_BOUNDS`.
`DELETE` accepts any alias of the base pointer returned by `NEW`; it cannot
delete a vector or a region supplied by `HOST.memory`. Pointer arithmetic and
derived offset pointers are outside 0.1.
Memory management is manual in 0.1. A deleted allocation is invalid for every
alias; a later access raises `USE_AFTER_DELETE`, and a second `DELETE` raises
`DOUBLE_DELETE`.
An allocation is considered deleted while its destructor runs, so a reentrant
`DELETE` also raises `DOUBLE_DELETE`.
Pointer assignment and parameter passing copy the pointer handle and preserve
the same allocation alias; they never transfer ownership implicitly.
Indexing or dereferencing a `NULL` pointer raises `NULL_POINTER_ACCESS` at
runtime, as does `DELETE NULL`. Test optional pointers with `IS NULL` before
using them.

Class instances are also created with `NEW` and released with `DELETE`:

```basic
LET customer AS Customer = NEW Customer(10)
DELETE customer
```

Class assignment and parameter passing copy a reference to the same instance;
they do not copy the object. `STRUCT` is the corresponding value type and is
copied as described above.

Within a class, `SELF` names the current instance. Instance fields and methods
must be accessed through `SELF.member`; an unqualified identifier never falls
back to an instance member. `FUNCTION CONSTRUCTOR(...)` initializes a new
instance. If it is present, `FUNCTION DESTRUCTOR()` runs exactly once when
`DELETE` releases the instance. Constructors and destructors have no `AS`
return type and cannot return a value; both close with `END FUNCTION`.
They may use bare `RETURN` for an early exit.
Each class may declare at most one constructor; overloads are outside 0.1.
Each class may declare at most one parameterless destructor. Only the runtime
may invoke it as part of `DELETE`.
A class without a declared constructor has an implicit parameterless
constructor with `PRIVATE` visibility. When a class declares one, every
`NEW ClassName(...)` call must match its parameter list; external creation
requires a `PUBLIC` constructor.
If constructor execution fails, `NEW` produces no value and the runtime
discards the allocation without running its destructor; a partially constructed
object is never observable.

At program termination, the runtime recovers allocations not released with
`DELETE`, but does not run their destructors. `DELETE` is the only deterministic
destruction point.

`STATIC` declares a class-level field or function. A static field exists once
per class and must have an initializer. A static function is called through the
class name; static code cannot use `SELF` or access an instance field.
The class name is a type and a static-member qualifier, not a first-class value.

```basic
CLASS Session
    PRIVATE STATIC nextId AS INTEGER = 0

    PUBLIC STATIC FUNCTION NextId() AS INTEGER
        Session.nextId += 1
        RETURN Session.nextId
    END FUNCTION
END CLASS
```

Static fields are initialized once, in source order, before their class is used
for the first time. They are accessed as `ClassName.member`, whether used
inside or outside the class. Re-entering an initialization already in progress
raises `STATIC_INITIALIZATION_CYCLE`; partially initialized fields are never
observable. Access through an instance is a static error.

## Program and declarations

Syntax: [source unit and module declaration productions in `0.1.ebnf`](0.1.ebnf).

A compilation unit contains zero or more leading `IMPORT` declarations followed
by `CLASS`, `STRUCT`, `INTERFACE`, and `FUNCTION` declarations. An import after
the first declaration is invalid. Blank and comment-only lines are permitted
between and inside declarations.

The executable module is the unit loaded by the runtime and must declare
exactly one `FUNCTION Start()` with no parameters. Its return type is either
`VOID` or `INTEGER`; the runtime calls this function to start the program.
An imported module may not declare `Start`.
`Start() AS VOID` completes with process exit code `0`. `Start() AS INTEGER`
must return a value from `0` through `255`, which becomes the process exit
code. Statements cannot appear loose at module level.

Each source file is a module. `EXPORT` makes a module-level `CLASS`, `STRUCT`,
`INTERFACE`, or `FUNCTION` available to importing modules. A declaration
without `EXPORT` is visible only within its module.
All declarations in a module are registered before function, method, and
initializer bodies are analyzed, so they may refer to declarations that appear
later in the same source file.

The executable module may declare `IMPORT HOST.main AS main`. `HOST` represents
the host environment and `main` is the `SYSTEM` object it provides. Only the
executable module may import `HOST.main`. The only 0.1 host capabilities are
`HOST.main` and
`HOST.memory`; the latter supplies typed regions subject to the same bounds
checks as `NEW` allocations. GPU, filesystem, network, and DOM capabilities
are outside 0.1. An imported host capability is required: if it is unavailable,
execution fails before `Start` with `HOST_CAPABILITY_UNAVAILABLE`. A
`HOST.memory` region belongs to the host, cannot be deleted by BN, and remains
valid for the complete program execution.

`HOST.main` has type `SYSTEM` and is an opaque capability token in 0.1: it has
no callable member contract beyond its availability. `Start`, `STOP`, and
`INPUT()` provide the portable program/console behavior; host-specific system
operations require a later capability proposal.

Imports always use an explicit local alias:

```basic
IMPORT HOST.memory AS Memory
IMPORT Basic.Collections AS Collections
```

This is the only import form for modules and host capabilities. A host API is
never introduced through separate plugin or extension syntax. Module imports
form an acyclic graph; an import cycle is a static error. A logical module name
such as `Basic.Collections` resolves to `Basic/Collections.bn` beneath the
project root, independently of the host path separator. In 0.1, that root is
the directory of the executable module supplied to `bn run` or `bn check`.
An import alias may not collide with a declaration in its importing module.

Every ordinary callable declaration is a `FUNCTION` and states its return type
after `AS`. `RETURN expression` appears only in a function with a non-`VOID`
return type. A `FUNCTION ... AS VOID`, `FUNCTION CONSTRUCTOR`, or `FUNCTION
DESTRUCTOR` completes at `END FUNCTION`, or may use a bare `RETURN` to leave
early. A function with any other return type must return a compatible value
with `RETURN expression`. Bodies end with `END FUNCTION`, `END CLASS`, or
`END INTERFACE`.
Functions and methods are not overloaded in 0.1: each scope may declare a
callable name only once.

`FUNCTION(parameter-types) AS return-type` is also a function value type:

```basic
FUNCTION Double(value AS INTEGER) AS INTEGER
    RETURN value * 2
END FUNCTION

FUNCTION Start() AS VOID
    LET transform AS FUNCTION(INTEGER) AS INTEGER = Double
    LET result AS INTEGER = transform(21)
    PRINT result
END FUNCTION
```

Only module-level functions and `STATIC` functions can be stored as function
values in 0.1. Their parameter and return types must match exactly. Instance
methods are called through their object but are not function values, and 0.1
has no lambdas, closures, overloads, or function-value equality.

### Minimum useful program subset

Every language version must identify the smallest subset sufficient for a
complete, useful program. For 0.1, that subset is: one executable module with
`FUNCTION Start() AS VOID` or `FUNCTION Start() AS INTEGER`, explicitly typed
`LET` and `CONST` bindings, primitive values, expressions, assignment, `IF`,
`WHILE`, `REPEAT`, `FOR`, `FUNCTION`, `PRINT`, and `INPUT()`.

Classes, interfaces, imports, vectors, pointers, and host capabilities extend
that core; none is required to write and run a useful 0.1 program. The
executable may use `IMPORT HOST.main AS main` when it needs the host-provided
system object.

## Interfaces

Syntax: [interface and class-member productions in `0.1.ebnf`](0.1.ebnf).

An interface is a named public contract. It contains only `FUNCTION` signatures:
it has no fields, constructor, destructor, or implementation body.

```basic
INTERFACE Printable
    FUNCTION Print() AS VOID
END INTERFACE

INTERFACE Named
    FUNCTION Name() AS STRING
END INTERFACE
```

A class implements one or more interfaces explicitly with `IMPLEMENTS`. It
must provide every required member with the same name, parameter count,
parameter types, and return type; parameter names need not match.
Only a public instance method satisfies an interface member; a `STATIC` method
never does.

```basic
CLASS Report IMPLEMENTS Printable, Named
    PUBLIC FUNCTION Print() AS VOID
        PRINT "Report"
    END FUNCTION

    PUBLIC FUNCTION Name() AS STRING
        RETURN "Report"
    END FUNCTION
END CLASS
```

An interface name is a type and can be used wherever a declared type is
accepted. Interface members are public by definition. Interface inheritance,
default methods, and reflection are outside 0.1. A class value is assignable to
an interface type it implements; this is an implicit interface upcast that
preserves the same object reference. Interface values cannot be downcast or
tested against a concrete class in 0.1.

## Expressions

Syntax and precedence: [expression productions in `0.1.ebnf`](0.1.ebnf).

Literals, identifiers, calls, and parentheses compose expressions. Operators,
in descending precedence: exponentiation `**` (right-associative); unary
`NOT`, `-`; multiplicative `*`, `/`, `DIV`, `%`; additive `+`, `-`; comparison `<`, `<=`,
`>`, `>=`; equality `=`, `<>`; `AND`; `XOR`; `OR`. `SHL` and `SHR` bind after
addition and before comparison.

Operands and call arguments are evaluated strictly from left to right.

`/` is floating-point division: `5 / 2` evaluates to `2.5`. `DIV` is integer
division paired with Euclidean modulo: for a nonzero divisor `b`,
`a = (a DIV b) * b + (a % b)`, and `a % b` is in the range `0` through the
absolute value of `b` minus one. Thus `-5 DIV 3` is `-2` and `-5 % 3` is `1`.
`DIV` and `%` accept integral operands only. Division or modulo by zero is a
runtime error.

Exponentiation binds more tightly than unary negation and associates to the
right: `2 ** 3 ** 2` is `2 ** (3 ** 2)`, `-2 ** 2` is `-(2 ** 2)`, and
`(-2) ** 2` is `4`. With integral operands, `**` requires a non-negative
integral exponent. With floating operands, it is real exponentiation and
permits a negative floating exponent, so `2.0 ** -1.0` is `0.5`.

`+` concatenates strings when both operands are `STRING`; otherwise it is
numeric addition. Arithmetic does not coerce `BOOLEAN` values or `STRING`
values to numbers. `+=`, `-=`, `*=`, `/=`, `%=`, and `**=` assign the result
of the corresponding operation to their left-hand binding.

Equality is strict outside numeric types: the operands of `=` and `<>` must
have the same static type unless a specific compatibility rule applies. Numeric
operands use the numeric widening rules. There is no implicit conversion between
`STRING`, `BOOLEAN`, or numeric families. Therefore `"" = FALSE` and
`0 = FALSE` are static errors. Write an
explicit conversion when that is the intent:

```basic
LET empty AS BOOLEAN = "" AS BOOLEAN
LET hasText AS BOOLEAN = "A" AS BOOLEAN
LET isNull AS BOOLEAN = NULL AS BOOLEAN
LET isMissing AS BOOLEAN = NA AS BOOLEAN
LET isEndOfInput AS BOOLEAN = EOF AS BOOLEAN

IF empty = FALSE THEN
    PRINT "empty"
END IF

IF hasText = TRUE THEN
    PRINT "has text"
END IF

IF isNull = FALSE THEN
    PRINT "no object"
END IF

IF isMissing = FALSE OR isEndOfInput = FALSE THEN
    PRINT "an explicit absence converts to false"
END IF
```

Class equality compares object identity, not fields: two references compare
equal exactly when they name the same instance.
When one operand is a class and the other is an interface implemented by that
class, the class operand is implicitly viewed through that interface and
identity is compared.
Vector equality compares shape and then each element in index order. An element
whose type is a class uses class identity equality.
`STRUCT` equality compares fields in declaration order; a class-reference field
uses class identity equality.
Pointer equality compares allocation identity, not pointed content.
Ordered numeric comparisons apply the numeric widening rules; integers and
floating values still require an explicit conversion before comparison.
`STRING` supports equality only; ordered string comparisons are outside 0.1.

`NOT`, `AND`, `OR`, and `XOR` are selected by the static operand type, so their
spelling is never ambiguous: they are logical only for `BOOLEAN`, and bitwise
only for integral operands, using the integral widening rules. Mixed
logical/integral operands are a static error. Logical `AND` and `OR` evaluate
left to right and short-circuit; bitwise operations and logical `XOR` evaluate
both operands. Every bitwise result has the promoted operand type. `SHL` and
`SHR` operate only on integral values. `SHR` fills new high
bits with zero. Their left operand determines the result type; their count may
have any integral type and must be non-negative and smaller than the left
operand width. An invalid literal count is a static error; an invalid computed
count raises `INVALID_SHIFT_COUNT` at runtime.

```basic
LET flags AS BYTE = 0b00001010
LET mask AS BYTE = 0b00000100
LET enabled AS BOOLEAN = (flags AND mask) <> 0

flags = flags XOR 0x01
flags = flags SHL 1
```

`PRINT` and `INPUT()` are built-in macros over the default console capability:

```basic
PRINT value             // Console.WriteLine(value)
LET line AS STRING OR EOF = INPUT() // Console.ReadLine()
```

`PRINT` writes to standard output. With multiple expressions, it concatenates
their text representations without a separator and then writes one line ending.
With no expression, it writes a blank line.
`INPUT()` reads one line from standard input as a `STRING`, or returns `EOF` at
end of input; it does not include the input line ending. Programs do not need to import
`HOST.console` to use these macros; the runtime provides the default `Console`
object. Once it returns `EOF`, later `INPUT()` calls also return `EOF`.
`PRINT` renders `BOOLEAN` as `TRUE` or `FALSE`, renders `NAN`, `INF`, `-INF`,
`NULL`, `NA`, and `EOF` with those uppercase spellings, renders strings without
quotes, and uses portable decimal text for finite numbers. A finite floating
value uses the shortest decimal text that reproduces the same `FLOAT32` or
`FLOAT` value.

The standard-library [`Math`](../library/math.md) namespace provides the 0.1
mathematics surface. It is available without an import:

```basic
LET root AS FLOAT = Math.SQRT(9.0)
LET rounded AS FLOAT = Math.ROUND(3.14159, 2)
LET lower AS FLOAT = Math.FLOOR(3.9)
```

`Math` provides `ABS`, `MIN`, `MAX`, `SIGN`, `FLOOR`, `CEIL`, `TRUNC`, `ROUND`,
`SQRT`, `HYPOT`, `FMA`, `EXP`, `LOG`, `LOG10`, `LOG2`, `POW`, `SIN`, `COS`,
`TAN`, `ASIN`, `ACOS`, `ATAN`, and `ATAN2`. Its signatures, domains, and IEEE
754 special-value behavior are normative in the [Math contract](../library/math.md).
Complex numbers and vectorized arithmetic remain outside 0.1.

## Statements

Syntax: [statement and control-flow productions in `0.1.ebnf`](0.1.ebnf).

Basic statements are `LET`, `CONST`, assignment, `PRINT`, call, `IF`, `WHILE`,
`REPEAT`, `FOR`, `FOR EACH`, `EXIT`, `CONTINUE`, `RETURN`, and `STOP`. `RETURN
expression` is permitted only in a `FUNCTION` whose return type is not `VOID`;
bare `RETURN` is permitted in `FUNCTION ... AS VOID`, `FUNCTION CONSTRUCTOR`,
and `FUNCTION DESTRUCTOR`.

```basic
IF condition THEN
    PRINT "yes"
ELSE
    PRINT "no"
END IF

WHILE condition
    counter += 1
END WHILE

REPEAT
    counter -= 1
UNTIL counter = 0
END REPEAT

FOR i AS INTEGER = 0 TO 9 STEP 2
    PRINT i
END FOR

FOR EACH value AS INTEGER IN values
    IF value = target THEN
        EXIT FOR
    END IF
END FOR
```

`IF`, `WHILE`, and `UNTIL` require `BOOLEAN`. `WHILE` tests its condition
before the body; `REPEAT` executes its body at least once and ends when `UNTIL`
is true. `UNTIL` is the post-condition of `REPEAT`, not its closing delimiter.
`FOR EACH` iterates in index order over a fixed-size vector in 0.1. Its binding
is read-only and its declared type must equal the vector element type. Future
collections may support the same form without changing its syntax. It reads the
current element at each index, so a mutation to an unvisited element is visible.

`EXIT FOR`, `EXIT WHILE`, and `EXIT REPEAT` provide early, exceptional exit
from the nearest matching loop. `EXIT FOR` applies to both counted `FOR` and
`FOR EACH`. `CONTINUE FOR`, `CONTINUE WHILE`, and `CONTINUE REPEAT` skip the
remainder of the nearest matching iteration; `CONTINUE FOR` also applies to
`FOR EACH`. There is no bare `EXIT`, bare `CONTINUE`, `EXIT FUNCTION`, or
`BREAK` keyword.

A counted `FOR` evaluates its start, end, and optional `STEP` expressions once
before its first iteration. Each must produce the same integral type as the
loop binding; `STEP` must not be zero. When omitted, it is `1`. A positive step
continues while the binding is less than or equal to the end value; a negative
step continues while it is greater than or equal to the end value. The binding
changes by the step after the body, including after `CONTINUE FOR`. A loop with
a direction that cannot reach its bound executes zero times. A literal zero
step is a static error; a computed zero step is a runtime error.

`STOP expression` terminates the entire BN program immediately. Its expression
requires an `INTEGER` value from `0` through `255`; that value becomes the
process exit code. For normal completion, prefer `RETURN value` from
`FUNCTION Start() AS INTEGER`. This is the portable program-to-host signal. BN
does not expose platform-specific process signals such as POSIX `SIGTERM` or
`SIGKILL` in 0.1. A literal outside `0` through `255` is a static error; a
computed value outside that range raises `INVALID_EXIT_CODE` at runtime. The
same rule applies to the return value of `Start() AS INTEGER`.

Every compound form closes explicitly with `END` followed by its opening
keyword: `END IF`, `END WHILE`, `END REPEAT`, `END FOR`, `END FUNCTION`, `END
CLASS`, `END STRUCT`, or `END INTERFACE`.
The closing word must match the opener; for example, `END WHILE` cannot close a
`FOR`. `FOR` iterates inclusively; its optional `STEP` defaults to `1` in 0.1.

### Return analysis and diagnostics

Every non-`VOID` `FUNCTION` must return an expression compatible with its
declared return type on every completed execution path. Reaching `END FUNCTION`
without a value is a compile-time semantic error, never a runtime `NULL`, `NA`,
or default value. The analyzer must report the error at the function name and
state the missing route, for example:

```text
FUNCTION ParseCount returns INTEGER, but a path reaches END FUNCTION without
RETURN INTEGER. Add RETURN on that path, or declare the function AS VOID.
```

The analyzer does not assume that a loop runs forever; a `RETURN` hidden only
inside a loop does not satisfy the rule. In a `FUNCTION ... AS VOID`,
`FUNCTION CONSTRUCTOR`, or `FUNCTION DESTRUCTOR`, `RETURN expression` is a
static error and bare `RETURN` is permitted only for an early exit. In a
non-`VOID` function, bare `RETURN` is a static error.

For return analysis, an `IF` satisfies the rule only when it has an `ELSE` and
every branch satisfies it. Loops never satisfy the rule by themselves, even
`REPEAT`; `STOP` does. `EXIT` and `CONTINUE` end only the remaining path of
their named loop iteration.

Code that is provably unreachable after `RETURN`, `STOP`, `EXIT`, or `CONTINUE`
is a static error.

## Still undecided

`MATCH`, `ENUM`, inheritance, variable-size collections, and concurrency
require proposals before becoming part of a later version of the specification.
`EXTENDS` and `PARALLEL` are reserved now so they cannot be used as identifiers.
