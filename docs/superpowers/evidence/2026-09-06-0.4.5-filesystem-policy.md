# Bucket 0.4.5 — Filesystem policy scope

Date: 2026-09-06

`HostEnv` now supports separate canonicalized read and write directory roots.
The compatibility constructors preserve existing unrestricted local CLI
behaviour, while `without_filesystem()` installs deny-all policy. `Exists`,
`Open`, `DeleteFile`, and BNLog file transport setup check the requested path
against the appropriate root before touching the filesystem. New files are
checked against their canonicalized parent directory.

Verification:

```text
cargo test --lib runtime::tests::filesystem_policy_separates_read_and_write_roots
1 passed
cargo check --all-targets
passed
cargo clippy --all-targets -- -D warnings
passed
```

The compiled filesystem path is not currently advertised as supported by the
LLVM matrix, so native artifact path scopes remain a later GC-POL requirement.
