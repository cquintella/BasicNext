## 1. Activities Summary

* **Activity 4b.1: Lock default for untrusted HostEnv: fail-closed / rooted**
  * Added `HostEnv::sandbox(arguments: Vec<String>) -> HostEnv` in `src/runtime_impl.rs`:
    * Initializes `FilesystemPolicy::denied()`, which rejects all reads, writes, and capability checks by default.
  * Documented in `docs/architecture/nfr-security.md` (§8 Filesystem default sandbox and rooted TOCTOU):
    * Untrusted execution profiles default to fail-closed / denied filesystem access (`HostEnv::sandbox`).
    * `HostEnv::system` is documented as an explicit grant of full host trust.

* **Activity 4b.2: Rooted mode: reject static symlink escape**
  * The original implementation canonicalized a pathname before a separate
    filesystem operation. That rejected a static escape but did not close the
    check/use race and was therefore insufficient for the original Fixed
    claim.
* **Activity 4b.3: Close symlink replacement races**
  * `bn_rt::secure_fs::RootedDir` pins the configured root as an open directory
    descriptor and verifies its device/inode identity during setup.
  * Each intermediate component is opened with `openat`, `O_DIRECTORY`, and
    `O_NOFOLLOW`; the final component is opened with `O_NOFOLLOW` for read,
    create/truncate, or append. Removal uses `unlinkat` relative to the pinned
    parent after verifying a regular-file descriptor.
  * The interpreter, compiled `HOST.FileSystem` ABI, and BNLog file transports
    use the descriptor-relative primitive. Policy denial remains distinct from
    ordinary transport or I/O failure.
  * Rooted access fails closed on non-Unix platforms where this primitive is
    unavailable. `HostEnv::system` remains explicitly unrestricted.
