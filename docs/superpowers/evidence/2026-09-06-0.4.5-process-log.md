# 0.4.5 companion process log

## Scope

`bn build` now owns a small ordered process recorder. With `-o artifact` it
writes `artifact.log`; `--log-file` selects an explicit destination and
`--no-log` disables writing. `--log-level error|warn|info|debug` filters event
lines before they are persisted. Successful builds and failures that reach the
frontend/lower/support/backend stages flush a partial or complete record. The
record uses escaped structured text fields and redacts known secret-bearing
key/value details.

The current build path records pipeline start/end, frontend, lower,
`validate_for`, LLVM emission and link transitions, plus safe option/module
snapshots and external clang/wasm-ld argv at debug level. Frontend warning
facts are mirrored at warn level with code and source position, without
copying source text. Explicit `--config` and the `[logging]` section select
the level, destination and enabled state; CLI logging flags override those
values, and the working-directory config takes precedence over an executable-
directory fallback. Log-write failures are reported as `PROCESS_LOG_WRITE`
tool errors. The recorder is separate from user-facing diagnostics and does
not change BN program `Error` values.

The final `diagnostic/summary` event is emitted once per build and includes
`errors`, `warnings`, and the resulting exit code; both successful and partial
failed builds assert these fields end to end.
Warning diagnostics are recorded at `warn` level, and a build with
`--log-level warn` asserts that warning events and the final summary remain
visible while informational events stay filtered.

## Remaining work

Remaining acceptance is broader than this implementation slice: complete
diagnostic summary/count mirrors for all pipeline families. Config discovery
and logging precedence now have deterministic goldens for explicit config,
working-directory config, executable-directory fallback, `--log-file` and
`--no-log`; CLI logging flags have explicit last-wins behavior for enabled
state. The broader pipeline coverage is required before Activity 6.3/G4 can
close.
