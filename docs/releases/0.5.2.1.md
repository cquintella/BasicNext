# Basic Next 0.5.2.1 — security patch (compiled `HOST.Net.Neighbor`) + one execution policy

**Buckets:** `done/bucket-0.5.2a.md` (Fragilidades 3 + 5; D-P-01..05) and
`done/bucket-0.5.2.1b.md` (Fragilidade 6 value-model correction).
**Base:** 0.5.2 (`23550aa`). No language surface change.

## Highlights

- **Interpreter value-model correction.** Record fields are interned and
  lowered to validated `FieldId`/`FieldSlot` references; interpreted records
  use checked `Box<[Value]>` positional storage instead of hashing field names
  on every access. LLVM consumes the same exact qualified layout contract.
- **Shared immutable values and one JSON model.** Immutable runtime text uses
  `Arc<str>`, and BNJson stores `serde_json::Value` while retaining duplicate
  key rejection, depth and byte bounds, trailing-input rejection, and Unicode
  behavior. This changes internal representation only, not the language or CLI.

- **Security — native `HOST.Net.Neighbor` resolves `arp`/`ndp` from trusted
  paths only.** The 0.4.6 hardening (`resolve_trusted_program`: `/usr/sbin`,
  `/usr/bin`, `/sbin`) had been applied to the interpreter copy of the
  neighbor lookup only; binaries produced by `bn build` still located `arp`
  through `PATH`. Both backends now run the same code.
- **One `HOST.Net` core.** `icmp`, `reverse` and `neighbor` (plus `Address`,
  `Endpoint`, `resolve`, `resolve_timeout`) have a single definition in
  `bn_rt::net`; `bn_host_net` re-exports it. The interpreter also gains the
  stricter ICMP checksum fold (`u16::try_from`) that only the interpreter copy
  had, and the compiled runtime gains the finished-worker reaping in
  `resolve_timeout` that only the interpreter copy had.
- **New native fixture:** `tests/cli.rs::native_host_net_neighbor_loopback_is_a_typed_result`
  mirrors `tests/runtime.rs::host_net_ping_loopback_and_neighbor_typed_result`.

- **Execution policy is one type on both backends** (Fragilidade 5).
  `bn_rt::Policy` is held by the interpreter's `HostEnv` and by the compiled
  runtime's single static; `BN_FS_POLICY`, `BN_EXEC_POLICY`,
  `BN_EXEC_CAPTURE_LIMIT` and `BN_EXEC_TIMEOUT_MS` are parsed by one function.
  `bn run` now honours the two `HOST.Exec` ceilings (previously native only).
- **Malformed policy input is fail-closed on both backends.** A value outside
  the documented domain stops the process before `Start` with
  `CONFIG_INVALID` and exit status 2 (`bn run`, `bn eval --format json`,
  native and wasm artifacts). Previously a compiled artifact ignored the
  failed `bn_rt_policy_init` and ran with whatever had been applied before
  the bad key. Spec: `language/0.5/0.5.md` § `HOST.Exec` "Policy inputs".
- **Construction gate:** `tests/check-shared-cores.sh` (CI) fails if a HOST
  core is duplicated, a second policy static appears, or the policy
  environment is read outside the parser.

## Breaking changes

Programs that set a malformed `BN_FS_POLICY` / `BN_EXEC_*` value and relied
on a compiled artifact ignoring it now stop with exit status 2. `bn run`
under `BN_EXEC_CAPTURE_LIMIT` / `BN_EXEC_TIMEOUT_MS` now returns
`Exec.CAPTURE_LIMIT` / `Exec.TIMEOUT` where it previously ignored the
variables. Crate consumers: `bn_host_net::net::{Address, Endpoint, …}`
are now re-exports of `bn_rt::net`; `bn_host_net` no longer depends on
`socket2` / `dns-lookup` directly (it does through `bn_rt`).

## Upgrade notes

Rebuild every artifact produced with `bn build` 0.5.2 or earlier that imports
`HOST.Net`; the fix is in the linked runtime, not in emitted code.
