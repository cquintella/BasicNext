# Basic Next 0.6.1c — BNJson DOM, AOT, and companion codecs

**Bucket:** `done/bucket-0.6.1c.md`.
**Base:** 0.6.1b. Spec: [`language/0.6/bnjson.md`](../../language/0.6/bnjson.md).
**Proposal:** [`todo/proposals/bn-serialization-companion-modules.md`](../../todo/proposals/bn-serialization-companion-modules.md).

## Highlights

- **Typed DOM on both backends.** `Object` / `Array`, `Kind` / `Has` / `Length`,
  typed `Set*` / `Get*` / `Append*` / `*At`, `Clone`, and nested `SetJson` /
  `GetJson` run under `bni` and `bnc`. Accessors are typed — there is no
  generic `Get` / `Set`.
- **One document table in `bn_rt`.** The interpreter marshals through
  `bn_lib_json`; AOT lowers through `bn_llvm` onto the same `bn_rt_json_*`
  ABI, so a handle means the same thing on both paths.
- **Move ownership for nested Json.** `SetJson` / `AppendJson` / `SetJsonAt`
  consume the child; `Clone` is the explicit duplicate. Bounds (depth 64,
  8 MiB, duplicates, trailing, non-finite) are unchanged and fail at the
  write that would breach them.
- **Companion codecs (option E).** Domain types stay free of JSON. Example:
  `examples/serialization/Bird.bn` + `BirdJson.bn`. Naming locked to sibling
  `BirdJson` (S-3).

## Not in this release

Reflection; keyword `SERIALIZE`; `ToJson` on domain classes; binary codecs;
`BNData` CSV; generic `Json.Encode(T)`; path queries / streaming / async I/O;
`EncodeText` / `DecodeText` as part of the convention (S-4 deferred —
companions may add locally); **Adjacent CLI/help/man** checklist from the
bucket (out of claim).
