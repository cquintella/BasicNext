# Basic Next 0.4 Deterministic Security Test Harness

Status: **DONE**.

Current evidence: `src/test_support.rs` provides bounded `FakeResolver`,
`ManualClock`, `TestDeadline`, `ScriptedPeer`, `HandshakeResult`,
`BoundedKeyTable`, and `ConnectionAccounting` seams, with local tests for deterministic answers,
bounded resolution, missing-host failure, clock advancement, deadline
expiration, scripted peer chunks, handshake outcomes, admission limits, drain
rejection, release, and join accounting. The fake resolver is now exercised by
an SSRF policy test, and TLS handshake, HTTP/1 header, HTTP/2 idle, and body
deadlines are applied by `src/http.rs` from the registry.
Delayed peer chunks now model partial headers, late body data, and idle
expiration without sleeping. Local HTTP lifecycle tests cover cancellation,
slow/failing workers, listener/worker deadlines, repeated stop, and multiple
connections without external services.

This harness is test infrastructure only. It must not weaken production
defaults, bypass the typed configuration layer, or become a second runtime
provider.

## Required seams

| Seam | Required behavior | Forbidden test dependency |
|---|---|---|
| Resolver | Fixed hostname-to-address answers, including mapped IPv6, CGNAT, special ranges, public IPv4, and DNS/redirect changes | Public DNS or Internet |
| Clock/deadline | Manual monotonic time and deterministic deadline advancement | Wall-clock sleep |
| Entropy | Injectable success stream and explicit failure result | Real entropy failure |
| Peer/socket | Local scripted peer for headers, body, idle, disconnect, and overload | Public service or timing race |
| TLS handshake | Local test-only certificate/key and controlled handshake outcome | External CA/certificate |
| Connection accounting | Observable admission, rejection, release, drain, and join counts | Thread-count heuristics |

## Implementation requirements

- Seams are dependency-injected behind small typed traits or test-only
  constructors; production code keeps the real provider as its default.
- Tests use the constants from [`config/0.4-bnweb-limits.toml`](../config/0.4-bnweb-limits.toml)
  through the same typed options path as production.
- Every fake has bounded state and deterministic cleanup. No fake may spawn an
  untracked thread or own an unbounded collection.
- Test certificates and keys are local fixtures, clearly marked non-production,
  and never copied into release configuration.
- Failure injection is explicit and repeatable: resolver error, entropy error,
  timeout, queue full, handshake failure, and join deadline expiry.

## Acceptance tests

The harness is accepted when local tests can deterministically exercise SSRF
classification and redirects, session-randomness failure, rate-limit table
limits, N+1 admission, handshake/header/body/idle deadlines, stop/drain
deadline, TLS success/failure, and connection release. Each test must pass in
serial and parallel execution without network access or sleeps.
