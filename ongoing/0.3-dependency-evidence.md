## Security and target notes

- Rust source keeps `unsafe_code = "deny"`; native code is confined to the
  audited `ring` build dependency (`cc`) and is not exposed through BN APIs.
- Rustls uses the selected provider explicitly; application code must not rely
  on implicit provider installation.
- Licenses are MIT/Apache-2.0/ISC-compatible according to the accepted
  planning table; transitive advisories and target builds remain release-gate
  checks.
- ICMP providers remain platform-specific and are not added as a dependency:
  Linux datagram sockets and Windows IP Helper are the D-016 providers;
  unsupported hosts report `operation-unavailable`.

## Environment evidence

The current host reports Rust 1.97.0 on `aarch64-apple-darwin`; no additional
Rust targets are installed. `cargo tree --duplicates` reports no duplicate
packages. `cargo-deny` 0.20.2 was installed for the gate check and, using the
checked-in `deny.toml`, reported `advisories ok, bans ok, licenses ok, sources
ok`. `cargo tree --duplicates` is empty for the host target; `cargo tree
--duplicates --target all` confirms only target-conditional duplicate
`windows-sys` versions
(0.52 through ring and 0.61 through Tokio); cargo-deny reports this as a
warning because the platform dependency paths do not overlap at runtime.

The `surge-ping` 0.9.0 candidate was evaluated and rejected for 0.3: it adds
Tokio/asynchronous runtime behavior and contains platform raw-socket fallbacks,
which conflict with the synchronous provider contract and D-016's explicit
unprivileged-provider policy.

`cargo metadata --format-version 1` enumerated 45 locked packages and found no
package without a declared license. The declared set is MIT, Apache-2.0, ISC,
BSD-3-Clause, Unlicense, Unicode-3.0, and the documented LLVM exception; all
are recorded in the generated metadata for manual SPDX review.
