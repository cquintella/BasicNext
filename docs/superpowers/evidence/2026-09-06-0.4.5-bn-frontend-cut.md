# 0.4.5 frontend crate cut

## Scope

`bn_frontend` is now a workspace crate with the frontend dependency direction:

```text
bn_frontend -> bn_diag -> bn_source
             -> bn_source
             -> bn_types
             -> bn_ir
```

The crate owns the compiled frontend module boundary for AST, lexer, parser,
module graph, semantic analysis, HOST specification, token definitions and
`FrontendSession` and the complete lowering entrypoints. The root `bn` package
re-exports these modules and keeps only an IR compatibility facade; it no
longer declares a second frontend/lowering implementation.

The activity remains open for shared CLI/LSP/DAP entrypoint and GC-DEP checks;
this slice does not claim G3 complete.

## Contract checks

- `bn_frontend` depends on `bn_ir` and has no dependency on `bn`, runtime or
  backend crates.
- `bn_frontend` unit tests: 12 passed.
- `bn_frontend` lowering integration test: 1 passed.
- `cargo check --workspace --all-targets`: passed.
- `cargo clippy --workspace --all-targets -- -D warnings`: passed.
- `cargo test --test lexer --test parser --test semantic --test module_graph --test validated_ir`: 104 passed.
- `cargo tree -e normal -p bn_frontend`: matches the dependency direction above.

## Remaining gate work

GC-FE still requires CLI and LSP to share the same lower+validate stages on
multi-source/revision fixtures. GC-DEP still requires the final public API and
Cargo graph review after the remaining runtime and backend extractions.
