# Basic Next 0.4 Authority Audit

This audit records the current authority gap before any 0.4 language or
concurrent BNWeb implementation begins.

## Evidence

| Source | Current content | Consequence |
|---|---|---|
| `docs/language/0.4/0.4.md` | Header says 0.4, but the status, authority order, amendments, capability section, and final exclusions repeatedly describe 0.3/0.2. | It cannot currently be the authoritative 0.4 prose contract. |
| `docs/language/0.4/0.4.ebnf` | Header says grammar 0.4, but productions preserve the 0.3 grammar and do not define `ASYNC` or `AWAIT`. | It cannot parse the async surface proposed for 0.4. |
| `docs/superpowers/specs/2026-09-01-async-await-0.4-design.md` | Defines `ASYNC FUNCTION`, `ASYNC queue function(...)`, and `AWAIT ticket(timeoutMs)`, with bounded ownership and runtime semantics. | It is a design input, not yet the normative language contract. |
| `done/0.4-forward-plan.md` | Defines `BNThreads`, semaphore, crypto, concurrent BNWeb, Haiku, and decision gates. | It establishes scope candidates but explicitly does not authorize implementation. |
| `ongoing/WBS-0.4.md` | Requires the authority boundary to be frozen before async/concurrent work. | Implementation is correctly gated. |

## Required reconciliation

Before Activity 0.2 can close, the project must choose one authority model:

### Option A — Adopt the async design as the 0.4 language amendment

Update `0.4.md` to describe 0.4, retain the 0.3 baseline by reference, and
add the exact async semantics from the design. Update `0.4.ebnf` with the
reserved words and productions for `ASYNC` and `AWAIT`; add keyword registry
and positive/negative grammar fixtures in the same change.

This enables Activities 0.4, 5.1, and 5.2 after their independent provider,
ownership, and lifecycle decisions.

### Option B — Keep 0.4 security/BNWeb hardening only and defer async

Correct the 0.4 documents to define only the accepted hardening and BNWeb
configuration surface. Keep `ASYNC`, `AWAIT`, and concurrent BNWeb outside the
0.4 grammar and move the async design to a later version.

This permits bounded BNWeb hardening but does not permit language-level async
or concurrent BN handlers to be claimed in 0.4.

### Option C — Adopt a revised 0.4 design

Replace the current async proposal with another explicitly reviewed syntax or
execution model. The replacement must define grammar, precedence, parameter
ownership, queue/ticket behavior, cancellation, running-task timeout,
response ownership, output ordering, provider dependencies, and all fixtures
before implementation.

## Non-negotiable consistency rules

- `0.4.md`, `0.4.ebnf`, keyword registry, fixtures, and async design must not
  disagree about whether `ASYNC`/`AWAIT` are 0.4 syntax.
- No 0.4 document may claim an implementation or release status that the
  source, tests, or conformance evidence does not prove.
- The 0.3 grammar, conformance claim, synchronous BNWeb handler contract, and
  Program-mode Jupyter behavior remain unchanged unless a separate accepted
  amendment says otherwise.
- `HOST` remains the only built-in interface object; `BNDispatch`, `BNThreads`,
  `BNWeb`, and future facilities remain explicit external modules.
- Security defaults and lifecycle requirements must be normative before code
  relies on them; a forward plan alone is insufficient authority.

## Decision

**Option A accepted — 2026-09-01.** Carlos authorized adoption of the
`ASYNC`/`AWAIT` design as the 0.4 language amendment. The normative surface is
now defined by `docs/language/0.4/0.4.md`, `0.4.ebnf`, and `keywords.md`, with
the async design retained as rationale and implementation detail. The
remaining provider, parameter-ownership, cancellation, response-ownership,
and quota decisions stay explicit gates for Activities 0.3 and 0.4; this
decision does not authorize their implementation by itself.

## Status

The authority audit is complete and Activity 0.2 is closed. The documents
agree that `ASYNC` and `AWAIT` are 0.4 syntax and that they are absent from the
0.3 contract. Implementation remains gated by the independent decisions
listed above.
