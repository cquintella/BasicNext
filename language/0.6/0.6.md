## Amendments to 0.2 (0.3 baseline, retained)

1. **Multi-binding `LET`.** A `LET` declaration may declare one or more
   identifiers of the same `variable-type`:

   ```basic
   LET v, v1, v2 AS INTEGER = 0, 1, 3
   LET c, v AS STRING = "carro", "moto"
   ```

   The initializer is optional. When present, it contains exactly one
   expression per identifier. All identifiers in the declaration are out of
   scope in every initializer expression. Expressions are then evaluated and
   assigned to their corresponding identifiers from left to right. Each value
   must be assignable to the declared type. Duplicate identifiers are a
   declaration error.
   `CONST`, fields, parameters, and `FOR` bindings retain their 0.2 syntax,
   with the constant inference amendment below.

   A module constant may omit its type annotation when its initializer is a
   scalar literal:

   ```basic
   EXPORT CONST Count = 10
   EXPORT CONST Rate = 10.2
   EXPORT CONST Enabled = TRUE
   EXPORT CONST Label = "SS"
   ```

   Inferred integer and floating-point constants use the default `INTEGER`
   (`INT32`) and `FLOAT` (`FLOAT64`) types. `BOOLEAN` and `STRING` literals
   infer their corresponding types. The explicit form remains available when
   a specific width or signedness is required, for example
   `EXPORT CONST Mask AS UINT32 = 10`. Inference is restricted to scalar
   literals; `NULL`, `NA`, `EOF`, and special floating literals require an
   explicit type annotation.

   Module constants follow `module-constant-declaration` in
   [`0.6.ebnf`](0.6.ebnf): a module-level `CONST` appears after every
   `IMPORT` and is initialized by one literal. With `EXPORT` it is visible
   to importers; without it (0.6.5, B4) it is private to its module
   (`CONST Limit = 3`). A minus
   sign applied to a single integer or floating-point literal is a negative
   literal (`EXPORT CONST Min = -1`, `EXPORT CONST Low AS FLOAT = -2.5`).
   Anything else is an expression and is not a module-constant initializer:
   `-1 + 2`, `- -1`, and vectors such as `[1, 2, 3]` are rejected.

   `TYPEOF(expression)` is a built-in function that returns the canonical
   static type name as `STRING`. Alias spellings are normalized to their
   fundamental representation: `INTEGER` is reported as `INT32`, and
   `FLOAT` as `FLOAT64`. For example, `TYPEOF(10)` returns `"INT32"` and
   `TYPEOF(10.2)` returns `"FLOAT64"`.

2. **Networking and web module.** `HOST.Net` is a native-host capability for
   IPv4/IPv6 addressing, bounded system resolution, TCP, and bounded UDP.
   ICMP Echo, direct-neighbor lookup, and reverse DNS remain provider-deferred
   operations until a platform provider contract supplies permission and
   timeout semantics. `BNWeb` is an external standard module for HTTP clients and
   servers. Both use ordinary imports; neither adds a keyword or statement:

   ```basic
   IMPORT HOST.Net AS Net
   IMPORT BNWeb AS Web
   ```

   The operating system owns networking, DNS/system resolution, and transport
   stacks. BN does not implement IP, TCP, UDP, TLS, QUIC, HTTP framing, cookie
   grammar, or HTML parsing.    The native interpreter is the only initial host;
   compiler and Jupyter hosts reject these facilities deterministically
   until they provide conforming providers.

The LLVM backend accepts `FUNCTION Start() AS VOID` and
`FUNCTION Start() AS INTEGER`. For an integer entry point, the returned value
is emitted as the process exit code of LLVM `main`. Other LLVM-subset gaps,
including general BN function calls and dynamic arrays/pointers, remain explicit
lowering diagnostics. These diagnostics identify the function or operation and
give the supported execution alternative; a program may therefore pass `check`
and `run` while remaining unavailable to `build`.

The native provider applies the configured socket-handle quota to TCP streams,
TCP listeners, and UDP sockets; uses the configured resolver-address and
datagram bounds; applies the connect timeout to subsequent TCP reads and
writes; and binds TCP listeners with the requested backlog. UDP multicast and
broadcast destinations are denied by default.

3. **Structured logging module.** `BNLog` is an external standard module for
   structured logging inspired by Winston's separation of levels, formats,
   and destinations; a logger is made with its format and destination, and
   writes `Log.Event` and `Log.Apache` records ([`bnlog.md`](bnlog.md), "API
   (0.6.5)"):

   ```basic
   IMPORT BNLog AS Log
   ```

   `BNWeb` performs network I/O through `HOST.Net` and emits its access and
   internal error records through an explicitly configured `BNLog` logger.
   `BNLog` does not depend on `BNWeb` or `HOST.Net`.

4. **Single-line `IF`.** A conditional containing exactly one simple statement
   per branch may remain on one physical line:

   ```basic
   IF x = y THEN PRINT z
   IF ready THEN StartServer() ELSE PRINT "not ready"
   ```

   The physical line after `THEN` selects the form. If a simple statement
   follows `THEN` on that same line, the complete construct, including its
   optional `ELSE` statement, must end on that line and has no `END IF`. If
   `THEN` is followed by `NEWLINE`, the construct is a block and must end with
   `END IF`. A block admits zero or more `ELSE IF` branches followed by at most
   one final `ELSE`; no `ELSE IF` may follow that final `ELSE`.

   Single-line branches may contain declarations, assignments, calls, `PRINT`,
   `RELEASE`, `RETURN`, `EXIT`, `CONTINUE`, or `STOP`, but not another `IF`, a
   loop, or a compound declaration. The condition must be `BOOLEAN`, with the
   same narrowing and control-flow semantics as the corresponding block form.

5. **Declaration-time vector dimensions.** Local `LET` bindings may use
   declaration-time vector dimensions that are evaluated once at binding time:

   ```basic
   LET n AS INTEGER = 4
   LET values AS INTEGER[n] = [1, 2, 3, 4]
   ```

   The vector remains fixed-size after initialization, and the dimension
   expression must resolve to a non-negative integer. Function signatures,
   class fields, struct fields, parameters, and return types remain
   literal-only in their vector dimensions.

## Amendments to 0.1 (0.2 baseline, retained)

The following 0.1 rules are replaced or withdrawn.

1. **Inheritance.** 0.1 reserved `EXTENDS` as a lexical-only word and stated
   that inheritance was outside the language. 0.2 gives `EXTENDS` executable
   syntax and the semantics in [Class inheritance](#class-inheritance).
2. **`SUPER`.** 0.2 introduces the reserved word `SUPER`. It is not an
   identifier.
3. **Console object.** 0.1 used the statements `CLS(HOST.Console)` and
   `BEEP(HOST.Console)`. 0.2 withdraws those statements and the reserved
   words `CLS`, `BEEP`, and `PRINTAT`. Clear, bell, positioned write, and
   window size are methods on `HOST.Console`. `PRINT` and `INPUT()` stay as
   stream macros.
4. **`STRING` indexing.** 0.1 forbade `index-suffix` on `STRING`. 0.2 allows
   a read-only index as defined in [String indexing](#string-indexing).
5. **`Float.TryParse`.** The 0.1 conversion example `Float.TryParse` is not
   part of the 0.2 surface. Numeric text conversion is `BNMath.VAL`. Temporal
   `Parse` operations are unchanged.
6. **Host capabilities.** 0.1 listed files as outside the language. 0.2 adds
   `HOST.FileSystem` and `HOST.Random`. Networking (`HOST.Net`, introduced in
   0.3 — never named `HOST.Network`), `HOST.Memory`, FFI, and TZDB-backed
   conversion remain outside 0.2.
7. **Class construction.** 0.1 initializes instance fields before the
   constructor body. In a class that `EXTENDS` another, that rule is amended
   as specified under [Construction and destruction](#construction-and-destruction).
8. **`LEN` of a pointer region.** 0.1 makes `LEN` a static error for every
   pointer. 0.2 allows `LEN` on a region pointer, as specified under
   [Pointer region length](#pointer-region-length).
9. **Command line.** 0.2 withdraws `HOST.Main` / `SYSTEM` / `ArgumentCount` /
   `Argument`. The executable module uses `HOST.Args` with no `IMPORT`, as
   specified under [Command-line arguments](#command-line-arguments).
10. **`IMPLEMENTS`.** 0.1 listed interfaces as a bare identifier, so a class
    could not implement `alias.Interface`. 0.2 uses `named-type` in
    `interface-list`, the same form as `EXTENDS`.
11. **Dispatch during construction and destruction.** A method call on the
    object whose constructor or destructor is running uses that class's
    implementation, not a subclass override. See
    [Construction and destruction](#construction-and-destruction).
12. **`IS` narrowing after exclusive return.** 0.1 narrows `value` in the
    corresponding `IF` / `ELSE` branch. 0.2 also applies the complement
    facts to the remainder of the enclosing block when an `IF` has no
    `ELSE` and every `THEN` / `ELSE IF` branch returns or `STOP`s. See
    [`IS` narrowing after returning branches](#is-narrowing-after-returning-branches).

The 0.1 base was never part of this repository. Scopes, values, vectors,
strings, structs, pointers, `IS` narrowing, control flow, modules,
conversions and diagnostics are specified in [Core language
(0.6.5)](#core-language-065) and the sections it links; nothing is
inherited from 0.1 by reference.

## Core language (0.6.5)

Written 2026-10-12 from the verified behaviour of both backends and the
BDFL's answers to the specification questionnaire (bucket 0.6.5, S.2–S.12);
where both backends disagreed, the rule below is normative and the
diverging backend is a defect.

### Values and copies

`STRING`, `STRUCT`, fixed vectors and every scalar type are **values**:
every store — a `LET` initializer, an assignment, an argument, a `RETURN`
value, a field, a vector element, a `STATIC` — stores a copy, so changing
one binding never changes another. Class objects, interfaces and pointer
regions are **references** under ARC ([Memory model
(ARC)](#memory-model-arc)); a value that holds a reference holds a strong
reference, retained by each copy.

A store into a **place** changes that place inside its owner: in
`b[0].x = 7`, `item.data[1] = 3` or `Holder.cells[2] = 1`, the element or
field of `b`, `item` or `Holder.cells` changes, and nothing else does. An
`assignment-target` names a place by any sequence of member and index
suffixes ([`0.6.ebnf`](0.6.ebnf)).

`=` and `<>` compare two values of the same type: two `STRUCT`s field by
field, two vectors element by element (the dimensions must be equal, or the
comparison is a `TYPE_MISMATCH`), two `STRING`s scalar by scalar, two `DATE`s
by calendar date, two `TIME`s by millisecond offset, two `TIMEZONE`s by canonical
identifier text, and two `TIMESTAMP`s by epoch millisecond. Two objects compare by
identity. `<`, `>`, `<=`, `>=` order numbers, `STRING`s, `DATE`s and `TIME`s;
two `STRING`s order by their Unicode scalar values, the first differing scalar deciding
and a proper prefix ordering first (`"Z" < "a"`, `"ab" < "abc"`); `DATE` and `TIME`
order chronologically. Other operands are a `TYPE_MISMATCH`.

`PRINT` of a `STRUCT` or an object writes its type name (`Site`, `Box`). `PRINT`
of a `DATE` writes ISO 8601 `YYYY-MM-DD`; `PRINT` of a `TIME` writes ISO 8601
`HH:MM:SS.mmm`; `PRINT` of a `TIMEZONE` writes its canonical IANA identifier string (e.g. `UTC`).

### Scopes and bindings

- A name is visible from its declaration to the end of the block that
  declares it; using it before the declaration is `NAME_NOT_FOUND`. The
  bodies of `IF`, `ELSE IF`, `ELSE`, `WHILE`, `REPEAT`, `FOR` and `FOR EACH`
  are blocks: a binding declared inside is not visible after the block.
- One name per function: declaring a name already declared in the function,
  in the same block or an enclosing one, is `DUPLICATE_NAME` (no
  shadowing). Parameters count as declared at the top of the body.
- The variable of a counted `FOR` and of a `FOR EACH` belongs to the loop
  and is not visible after `END FOR`.
- A `LET` without an initializer gives each binding its type's default
  (numbers `0` / `0.0`, `BOOLEAN` `FALSE`, `STRING` `""`, `DATE` `1970-01-01`,
  `TIME` `00:00:00.000`, `TIMEZONE` `"UTC"`, `TIMESTAMP` `0`, a vector of
  defaults, a `STRUCT` of its field defaults); types without a default need
  `=` ([STATIC field type defaults](#static-field-type-defaults-04)). A
  `LET` inside a loop declares a new binding on every iteration, with its
  initializer or default evaluated again.
- `CONST name = expression` declares a binding that cannot be assigned; in a
  function its expression may be any expression of the binding's type,
  evaluated when the declaration runs. A module-level `CONST` takes one
  literal (see [Amendments to 0.2](#amendments-to-02-03-baseline-retained)).
- **Parameter immutability and place mutation.** Function and method parameters
  are constant bindings: reassigning the parameter itself (`p = val`) is a compile-time
  error (`TYPE_MISMATCH`). When `p` is a value type (`STRUCT` or fixed vector),
  mutating its components (`p.field = val`, `p[i] = val`) is likewise rejected
  (`TYPE_MISMATCH`). When `p` is a reference or pointer region (`CLASS` instance
  or `POINTER TO T[]`), assigning to a field or element (`p.field = val`, `p[i] = val`)
  is permitted: it mutates the referenced heap allocation without reassigning
  the constant binding `p`.

### Vectors

- A field, `STATIC`, parameter or return type declares a fixed vector with
  literal dimensions (`INTEGER[3]`, `FLOAT[2][4]`). A local `LET` may use
  expressions (`LET v AS INTEGER[n]`); each is evaluated once, when the
  declaration runs. A dimension may be `0`; a negative dimension stops the
  program with `INVALID_VECTOR_DIMENSION`.
- Elements without an initializer take their type's default. A vector of a
  type without a default (`Box[2]`, an interface, `Error`) needs `=`.
- Indices are `0`-based, one per dimension: `g[i][j]` is an element, and
  `g[i]` (fewer indices than dimensions) is a row, a vector of the remaining
  dimensions. An index outside its dimension stops the program with
  `INDEX_OUT_OF_BOUNDS`.
- `LEN(v)` is the number of **elements** of `v`: the product of its
  dimensions (`LEN` of an `INTEGER[2][3]` is `6`).
- `FOR EACH x IN v` visits every element in row-major order, whatever the
  number of dimensions (an `INTEGER[2][3]` gives six `INTEGER`s).
- Assignment copies the elements; the destination's dimensions must equal
  the source's (`TYPE_MISMATCH` otherwise).
- **Open parameter (A8).** A parameter may leave its first dimension open:
  `FUNCTION Sum(v AS INTEGER[]) AS INTEGER`, or `INTEGER[][3]`. The argument
  is any vector with that element type and those remaining dimensions; the
  function reads its length with `LEN` and its rows with `v[i]`. Only
  parameters (and the parameter list of a `FUNCTION` type) may be open. The
  argument is not copied: a parameter is a constant binding, so the function
  cannot observe a difference.

### `STRING`

[String indexing](#string-indexing) defines `LEN`, `s[i]` and immutability;
a `STRING` is a sequence of Unicode scalar values (code points). U+0000 is
a scalar like any other: a `STRING` may contain it on every target, and no
operation shortens a `STRING` at it. `FOR EACH c IN text` visits each scalar
as a one-scalar `STRING`, in order. Comparison and ordering are in [Values
and copies](#values-and-copies).

### `STRUCT`

A `STRUCT` declares named fields, each with a type and an optional
initializer; it has no methods, no constructor and no inheritance, and `NEW`
of a `STRUCT` is a static error. A `STRUCT` binding without an initializer
holds every field's initializer value (or the type default). A `STRUCT` is
a value ([Values and copies](#values-and-copies)); a field of a class type
is a strong reference. A `STRUCT` that contains itself, directly or through
other `STRUCT` fields or vector elements, has no finite size and is a
`TYPE_MISMATCH`; reach a recursive shape through a class instead. Bracket
literals and destructuring: [Destructuring `LET` and `STRUCT`
literals](#destructuring-let-and-struct-literals-065).

### Pointers

Pointers, regions and `POINTER TO VOID` are specified in [String
indexing](#string-indexing) (opaque pointers), [Pointer region
length](#pointer-region-length) and [Pointer regions under
ARC](#pointer-regions-under-arc). A region is a reference, not a value: a
copy of the pointer shares the region.

### `IS` narrowing

`value IS T` is valid when `T` is a member of `value`'s alternative type (or
a pointer test, see above). A narrowed binding has the member type:

- in the `THEN` branch of `IF value IS T`, in the `ELSE` branch of
  `IF NOT (value IS T)`, and after an `IF` whose taken branches all return or
  `STOP` ([`IS` narrowing after returning
  branches](#is-narrowing-after-returning-branches));
- on the right of `AND` and in the `THEN` branch, for `value IS T AND …`;
  on the right of `OR` and in the `ELSE` branch, for `NOT (value IS T) OR
  …`;
- in the body of `WHILE value IS T`.

An assignment to the binding ends the narrowing from that point. Using a
member of an alternative that is not narrowed — `b.n` with `b AS Box OR
NULL`, `x + 1` with `x AS INTEGER OR NULL` — is a `TYPE_MISMATCH`.

### Control flow

- `IF … THEN … ELSE IF … ELSE … END IF`; the single-line form `IF c THEN
  statement [ELSE statement]` takes any simple statement, including `EXIT`,
  `CONTINUE`, `RETURN` and `STOP`. A condition is a `BOOLEAN`.
- `WHILE c … END WHILE` tests before each iteration; `REPEAT … UNTIL c
  END REPEAT` runs the body, then stops when `c` is `TRUE`, so it runs at
  least once.
- Counted `FOR i [AS T] = first TO last [STEP s]`: without `AS`, `i` is
  `INTEGER`, and a literal bound that does not fit `INTEGER` is a
  `TYPE_MISMATCH` (write `AS INT64`). `first`, `last` and `s` are evaluated
  once, in that order, before the first iteration; `s` defaults to `1`. A
  literal `STEP 0` is a `TYPE_MISMATCH`, and a step that is `0` at run time
  stops the program with `INVALID_FOR_STEP`. Before each iteration the loop
  compares the current `i` with `last` (`i <= last` for a positive step,
  `i >= last` for a negative one) and ends when the test fails; after the
  body it adds `s` to `i`. The body may assign `i`, which changes the
  iterations that follow. Reaching the end of `i`'s type does not overflow:
  when adding `s` would leave the type, the loop ends (`FOR i AS INT8 = 125
  TO 127` runs three times). The bounds are integers; a floating-point bound
  is a `TYPE_MISMATCH`.
- `FOR EACH x [AS T] IN source`: `source` is a vector or a `STRING`,
  evaluated once. Without `AS`, `x` has the element type (`STRING` for a
  `STRING`); with `AS`, the element must be assignable to `T`. `x` is a
  constant binding holding a copy of the element.
- `EXIT FOR|WHILE|REPEAT` leaves the innermost enclosing loop of that kind;
  `CONTINUE FOR|WHILE|REPEAT` starts its next iteration (a counted `FOR`
  adds its step first). Outside such a loop it is `INVALID_LOOP_CONTROL`.
- `STOP code` ends the program with exit status `code`, after releasing the
  locals of every running function (innermost first); `code` is an integer
  in `0..255`. A literal outside that range is `INVALID_EXIT_CODE` at
  compile time; a value outside it at run time stops the program with
  `INVALID_EXIT_CODE` (status `1`).
- `/` divides as floating point; `DIV` and `%` are Euclidean integer
  division and remainder: the remainder `r` is never negative
  (`0 <= r < |b|`) and `a = (a DIV b) * b + a % b` (`-7 DIV 2` is `-4` and
  `-7 % 2` is `1`; `7 DIV -2` is `-3` and `7 % -2` is `1`). An integer
  divisor `0` for `DIV` or `%` stops the program with `DIVISION_BY_ZERO`.

### Modules

- A module is a file ([Module names and files](#module-names-and-files-065));
  `IMPORT path AS Alias` makes its exported declarations visible as
  `Alias.Name`. Only declarations marked `EXPORT` are visible to importers;
  the rest are private to the module (`NAME_NOT_FOUND` from outside).
- **Re-export (E3).** `EXPORT IMPORT path AS Alias` imports `path` and
  exports it under `Alias`: a module that imports this one reaches it as
  `This.Alias.Name`, and further re-exports carry it on. Only a module
  import may be re-exported, not a `HOST` capability.
- Imports form no cycle, re-exports included: a module that reaches itself
  through imports is `IMPORT_CYCLE`.

### Operators

Precedence and associativity are those of the expression grammar in
[`0.6.ebnf`](0.6.ebnf), from loosest to tightest: `OR`, `XOR`, `AND`, `IS`,
`=` `<>`, `<` `<=` `>` `>=`, `SHL` `SHR`, `+` `-`, `*` `/` `DIV` `%`, unary
`NOT` and `-`, `**` (right-associative), then suffixes (call, member,
index, `AS`).

- **Evaluation order.** Expression evaluation is strictly left-to-right:
  binary operands (`a() + b()`) are evaluated left first, then right (with
  short-circuit for `AND` and `OR` on `BOOLEAN`); argument lists (`f(a(), b())`)
  are evaluated in declaration order from first to last; in compound assignments
  and indexed targets (`target[i()] = val()`), the target place is evaluated
  first, followed by dimension indices left-to-right, and finally the value
  expression. Side effects from `++` and `--` (S1') occur immediately during
  the left-to-right evaluation of the enclosing sub-expression (§ [0.6.0 language additions](#060-language-additions)).
- **Numeric operands.** Both operands of an arithmetic or comparison
  operator have numeric types, combined as follows (decided 2026-10-12, R4):
  `BYTE` is the 8-bit unsigned integer type. Two integer types of the same
  signedness give the wider (including `BYTE` with `UINT16`, `UINT32`, `UINT64`,
  which yields the wider unsigned type); `BYTE` with a signed type gives the
  wider of `INT16` and that type; any other combination of a signed and an
  unsigned type is a `TYPE_MISMATCH`; `FLOAT32` with `FLOAT64` gives `FLOAT64`;
  an integer with a floating-point operand is a `TYPE_MISMATCH` (write `AS`).
  A literal takes the other operand's type when it fits. This promotion applies
  only inside an expression: storing, passing or returning still converts nothing
  ([Conversions with `AS`](#conversions-with-as-065)).
- **`+`, `-`, `*`, unary `-`** on integers stop the program with
  `NUMERIC_OVERFLOW` when the result leaves the result type; on
  floating-point values they follow IEEE 754. `+` also concatenates two
  `STRING`s.
- **`/`** divides as `FLOAT64`, whatever the numeric operands.
- **`DIV` and `%`** are the quotient and the remainder of Euclidean integer
  division (see [Control flow](#control-flow)).
- **`**`** is the mathematical power (R3). Integer `**` integer is an
  integer for a non-negative exponent (checked, `NUMERIC_OVERFLOW`); a
  negative constant exponent makes the expression `FLOAT64` (`2 ** -1` is
  `0.5`), and a negative exponent known only at run time stops the program
  with `INVALID_EXPONENT` (use floating-point operands). With
  floating-point operands the result is the IEEE 754 power (`2.0 ** 0.5`,
  `2.0 ** -1`, and `NAN` for a negative base with a fractional exponent).
  An integer with a floating-point operand is a `TYPE_MISMATCH`, as above.
- **`AND`, `OR`, `XOR`, `NOT`** are logical on `BOOLEAN` and bitwise on
  integers (`5 XOR 3` is `6`, `NOT 0` is `-1`). On `BOOLEAN`, `AND` and `OR`
  evaluate their right operand only when the left does not decide the
  result; `XOR` evaluates both.
- **`SHL`, `SHR`** shift an integer by a count from `0` to its width minus
  one; another count is `INVALID_SHIFT_COUNT` (at compile time when it is a
  constant). `SHL` that loses a set bit or changes the sign is
  `NUMERIC_OVERFLOW`; `SHR` is a logical shift, filling with zeros in every
  integer type (`-8` as `INT8` `SHR 1` is `124`).
- **Compound assignment** `a op= b` is `a = a op b`, evaluating the place
  once; the result must fit `a`'s type. `s += t` appends to a `STRING`.
- **`IS NAN`, `IS INF`, `IS -INF`** test a floating-point value. `NAN` is
  equal to nothing, itself included (`x = x` is `FALSE` for `NAN`); test it
  with `IS NAN`.

### `NULL`, `NA`, `EOF`

`NULL` is the absence of an object or value, `NA` a missing datum (used by
`BNMath` and `BNData`), `EOF` the end of an input. Each is a value only as a
member of an alternative type (`INTEGER OR NULL`, `FLOAT OR NA`, `STRING OR
EOF`). `x = NULL` and `x IS NULL` agree (and likewise for `NA` and `EOF`).
`PRINT` writes them as `NULL`, `NA` and `EOF`; `AS BOOLEAN` gives `FALSE`.

### Function values

A `FUNCTION(T1, …) AS R` type holds a function with exactly those parameter
and return types. The name of a `FUNCTION` declared in a module (not a
method) is a value of that type: it may be stored, passed, returned and
called (`f(4)`). There are no closures: a function value captures nothing.
Two function values are equal when they name the same function. A function
type has no default, so a binding needs `=`.

### `INPUT` and `SIZEOF`

- `INPUT target` and `INPUT prompt, target` read one line into `target`,
  which must be a `STRING` (or a `STRING OR EOF`) place; `prompt` is a
  `STRING` written first, without a line ending. The line and the end of
  input follow `INPUT()` ([console.md](console.md)). A number is read as
  text and converted with `BNMath.VAL`.
- `SIZEOF(x)` is the portable size of `x` in bytes, as `INTEGER`, the same
  on every target: `1` for `BOOLEAN`, `BYTE` and `INT8`; `2`, `4`, `8` for
  the 16-, 32- and 64-bit numbers (`TIMESTAMP` is `8`); `4` for `DATE` and
  `TIME`; the UTF-8 byte count for a `STRING` (`SIZEOF("ção")` is `5`); the
  sum of its fields for a `STRUCT` (no padding) and of its elements for a
  vector. It is not the memory layout. `SIZEOF` of a pointer, an object,
  an interface, a `TIMEZONE`, a function value or an alternative is a
  `TYPE_MISMATCH`.

### Diagnostics and exit codes

Diagnostics are **errors** or **warnings**. An error stops `bni check`,
`bni run` and `bnc` before execution or emission; a warning
(`UNUSED_BINDING`, `UNUSED_IMPORT`, `UNREACHABLE_CODE`) is reported by
`bni check`, `bni run`, `bnc` and the editor and changes nothing else. A
diagnostic writes a type as the program spells it (`INT32 OR NULL`, not an
internal form).

| Exit status | Meaning |
| --- | --- |
| `0` | Success: the check passed, the program ended normally, or `bnc` produced its artifact. |
| `1` | A BN error: a static diagnostic, or a run-time error that stopped the program. |
| `2` | Invalid use of the tool (an unknown option, a missing file) or a tool failure (no toolchain). |
| `n` | `STOP n`. |

## STATIC field type defaults (0.4)

A `STATIC` field of a defaultable type may omit the initializer. Omitted
initialization uses the same type default as `LET` and instance fields:
numeric types `0` / `0.0`, `BOOLEAN` `FALSE`, `STRING` `""`, and the temporal
defaults already defined for those types. There is still no uninitialized
storage and no implicit `NULL`.

Types without a default still require `=`: `POINTER`, `FUNCTION` values,
class-typed fields, `Error` (see [error.md](error.md), "No default value"),
alternative types such as `INTEGER OR NULL`, and a vector whose element type
has no default (`Box[2]`, an interface vector, `Error[2]`; BDFL, 2026-10-07).
There is no implicit `NULL` element.
`STATIC POINTER TO INTEGER` without an initializer remains a
`TYPE_MISMATCH`. `PUBLIC STATIC shared AS INTEGER` is `0`;
`PUBLIC STATIC anotherShared AS STRING` is `""`.

The `=` expression form remains valid and is required when the initial value
is not the type default. Static initialization order and
`STATIC_INITIALIZATION_CYCLE` are unchanged for fields that do have an
expression.

## Bounded `ASYNC`/`AWAIT`

`ASYNC` and `AWAIT` were the only new 0.4 language keywords; 0.5.0 keeps the
surface spelling and amends the **result type** contract (typed `AWAIT`).
Their lexical forms are defined in [`0.6.ebnf`](0.6.ebnf) and
[`keywords.md`](keywords.md). The feature is deliberately explicit and bounded:

```basic
IMPORT BNDispatch AS Dispatch

ASYNC FUNCTION Worker(n AS INTEGER) AS INTEGER OR Error
    RETURN n * 2
END FUNCTION

FUNCTION Start() AS VOID OR Error
    LET queue AS Dispatch.Queue OR Error = Dispatch.Queue.Concurrent(4)
    IF queue IS Error THEN
        RETURN queue
    END IF
    LET ticket AS Dispatch.Ticket OR Error = ASYNC queue Worker(21)
    IF ticket IS Error THEN
        RETURN ticket
    END IF
    LET result AS INTEGER OR Error = AWAIT ticket(60000)
    IF result IS Error THEN
        RETURN result
    END IF
    PRINT result
    RETURN ticket.Close()
END FUNCTION
```

The queues, tickets, synchronization classes, bounds, and `Error` codes of
`BNDispatch` are specified in [bndispatch.md](bndispatch.md).

An `ASYNC FUNCTION` is a named task function whose result type is
`T OR Error`. Submission requires an explicitly typed `Dispatch.Queue` and
returns an opaque `Dispatch.Ticket OR Error`. The queue expression, target,
and arguments are evaluated once, left to right, before submission. The
target must be a named function; arbitrary closures, implicit global queues,
generic futures, shared mutable interpreter state, and OS thread handles are
outside this surface.

### Typed `AWAIT` (0.5.0)

| Rule | Decision |
| --- | --- |
| Primary surface | `AWAIT ticket(timeoutMs)` yields `T OR Error` when the ticket comes from a named function declared `AS T OR Error` |
| Not primary | `Ticket.Result()` — optional later compatibility only |
| Replay | The stored success value is replayed on repeated `AWAIT` until the ticket is `Close`d (not consume-once) |
| Result type `T` | `VOID`, `INTEGER`, `FLOAT`, `STRING`, `BOOLEAN` (primitive scalar MVP set) |

`AWAIT ticket(timeoutMs)` accepts an integer timeout from 1 through 60,000
milliseconds, may be repeated after completion, and never exposes a native
synchronization handle. Queue close cancels pending work; running work is not
force-killed. A timeout, queue failure, or task failure produces the typed
`Error` result.

### Async submit with arguments

Workers may take parameters. Two equivalent surfaces (arity and types must
match the named function's parameters — no partial-application object):

1. **Keyword form (grammar):** `ASYNC queue Fn(arg1, arg2, …)`
2. **Method form (ordinary call on the queue):** `queue.Async(Fn, arg1, arg2, …)`

Both produce a `Dispatch.Ticket OR Error`. Typed `AWAIT` then yields the
worker's `T OR Error`.

An argument of a task has one of these types: `BOOLEAN`, an integer type, a
floating-point type, `STRING`, `DATE`, `TIME`, `TIMESTAMP`, or one of the
`BNDispatch` classes `Queue`, `Ticket`, `Group`, `Barrier`, `Semaphore`,
`Mutex`. A parameter of any other type (an object, a vector, a `STRUCT`, an
alternative, a library handle) in an `ASYNC FUNCTION` is a static
`TYPE_MISMATCH`. (BDFL decision, 2026-10-15.)

**Asymmetry between task parameters and return values:** While task input
parameters admit the broader set of coordination objects and temporal types to
enable inter-task coordination, the return type `T` of a task (unwrapped via
`AWAIT` as `T OR Error`) remains strictly restricted to the primitive scalar MVP
set (`VOID`, `INTEGER`, `FLOAT`, `STRING`, `BOOLEAN`). Returning temporal types,
dispatch handles, vectors, or objects from an `ASYNC FUNCTION` is not supported
by the native ticket channel ABI and is rejected during native validation.

### Isolation and conformance

The worker executes with an isolated module/runtime copy. No caller frame,
mutable variable, BN object, or output writer is shared. Output is forwarded
through the ticket's synchronized channel and its order is unspecified.

The one exception is the coordination values of `BNDispatch`: a `Queue`,
`Ticket`, `Group`, `Barrier`, `Semaphore`, or `Mutex` passed to a task names
the same queue, ticket, or primitive in the worker, so tasks can coordinate
through it. Every other argument is copied. Their lifetime, and what the end
of a task does to them, are in [bndispatch.md](bndispatch.md), "Sharing
between tasks". (BDFL decision, 2026-10-15.)

A task ends as a program ends: when its function returns or fails, the end
of the task is the end of its copy's program. Its `STATIC` fields are not
released and no `DESTRUCTOR` runs, as at the normal end of a program; the
copy is then discarded, so every object it still holds ceases to exist and
its storage is reclaimed. The next task starts on a fresh copy. (BDFL
decision, 2026-10-15.)

`ASYNC` submission and `AWAIT` are primary expressions in the precedence
model. The semantic analyzer must enforce the queue/ticket types, named-target
signature, `T OR Error` result, integer timeout range, explicit import of
`BNDispatch`, and preservation of source spans. The typed IR represents them
as explicit `DispatchSubmit` and `DispatchAwait` operations. Opt-in
concurrent BNWeb handlers remain subject to the separate concurrency and
shutdown contract.

Required conformance includes positive and negative grammar fixtures,
semantic diagnostics, IR construction, submission/await, typed result
unboxing, timeout, cancellation, task failure, queue closure, output
forwarding, worker isolation, and a bounded BNWeb opt-in integration test.

## Lexical structure

The 0.1 lexical contract applies. The reserved-word set is the production
`reserved-word` in [`0.6.ebnf`](0.6.ebnf). `WEAK` and `RELEASE` are the 0.5.0
words; `DELETE` is **removed** and is an ordinary identifier position in 0.5
(a program that writes `DELETE x` is a call to an identifier `DELETE`, a
static error without a matching function). `ASYNC` and `AWAIT` (0.4) and
`EXTENDS` / `SUPER` (0.2) remain reserved.

`CLS`, `BEEP`, and `PRINTAT` are not reserved in 0.2. `PARALLEL` remains
reserved lexical-only: it cannot be an identifier and has no grammar
production in 0.2.

`OPEN`, `CLOSE`, `READ`, and `WRITE` are **not** keywords. File access is
`HOST.FileSystem` as defined in the host contract.

### Reserved identifiers and letter case (BDFL decision, 2026-10-20)

Grammar keywords remain exact uppercase (`FOR`, `WHILE`, `CLASS`, `LET`, etc.).

An identifier (`identifier = identifier-start { identifier-continue }`) must not match any reserved word in an ASCII case-insensitive comparison. Identifiers such as `for`, `For`, `fOR`, `while`, `Struct`, or `let` are prohibited. Attempting to declare or bind an identifier whose name collides with a reserved word regardless of case is a static error diagnosed as `RESERVED_IDENTIFIER`.

## String indexing

Syntax: `index-suffix` on a postfix expression whose type is `STRING`.

A `STRING` is a sequence of Unicode scalar values. `LEN(s)` is that count.
`s[i]` is valid when `s` has type `STRING` and `i` has an integral type. The
result is a `STRING` of length `1` containing the scalar at index `i`. Indices
are `0`-based and run from `0` through `LEN(s) - 1`. An index outside that
range raises `INDEX_OUT_OF_BOUNDS`. An empty string has no valid index.

```basic
LET word AS STRING = "café"
LET first AS STRING = word[0]    // "c"
LET last AS STRING = word[LEN(word) - 1]
```

`s[i]` is not an assignment target. Assigning to a string index is a static
error: `STRING` values are immutable. There is no `CHAR` type, no string
slice syntax, and no method namespace on `STRING`.

`ASC(text)`, `CHAR(code)`, `TOLOWER(text)`, and `TOUPPER(text)` are global
language functions. `ASC` returns the Unicode scalar value of the first
character as `INTEGER OR Error`; an empty string returns `Error`. `CHAR` returns
a one-scalar `STRING OR Error`; invalid Unicode scalar values (negative,
surrogate, or above `U+10FFFF`) return `Error`. `TOLOWER` and `TOUPPER` return
the string with Unicode default case mapping applied as `STRING` (see
[`bnstring.md`](bnstring.md)). None of these functions requires an import.
`Date.Parse`, `Time.Parse`, `TimeZone.Parse`, `Timestamp.Parse`, and
`Timestamp.Format` are likewise built-in functions available without an import
(contract in [`temporal.md`](temporal.md)).

Vector and pointer indices remain `0`-based. `PrintAt` coordinates are
`1`-based terminal cells. The two conventions are intentional and are not
aliases of each other.

`POINTER TO VOID` is the opaque pointer form, with C object-pointer conversion
semantics. A typed pointer or typed region converts implicitly to
`POINTER TO VOID`. A region keeps its element type and length through
`POINTER TO VOID`. An opaque pointer converts implicitly back to a typed pointer
or region when the underlying allocation matches the destination element type
and its length is compatible. Converting back to an incompatible element type
stops the program with `POINTER_TYPE_MISMATCH`. Converting back to a fixed
region length that does not match stops the program with
`POINTER_LENGTH_MISMATCH`. Bytes are never reinterpreted. `POINTER TO VOID`
cannot be indexed directly and `NEW VOID` is not syntax; convert it to a typed
pointer before indexing. `IS POINTER TO VOID` is true for every non-`NULL`
pointer value. For any other `T`, `IS POINTER TO T` reads the allocation, not
the static type (BDFL decision, 2026-10-16): it is true when the value is not
`NULL` and the allocation's element type is `T` — and, for `POINTER TO T[n]`,
its length is `n` — and false otherwise. It is true exactly when converting
the value to that type succeeds, so the test guards the conversion. A
`POINTER TO E OR NULL` value answers that test when the tested type is
compatible with the alternative: `IS POINTER TO VOID` is true for every
non-`NULL` value; `IS POINTER TO E` and `IS POINTER TO E[n]` are true when
the stored length is the tested length (`E[]` does not name a length). A
test that is not compatible with the alternative remains a static error, as
for any other `IS`. Storing that allocation as `POINTER TO VOID` does not
keep class names apart: every class shares one element code.

A region allocated by `NEW T[n]` is owned by **ARC**, exactly like a class
instance: every pointer binding to it is a strong reference, and the region
is freed when the last strong binding ends (scope exit, reassignment, or
`RELEASE`). See [Pointer regions under ARC](#pointer-regions-under-arc).

## Pointer region length

0.1: `LEN` is a static error for pointers, structs, classes, interfaces,
function values, `BOOLEAN`, `DATE`, `TIME`, `TIMEZONE`, and alternative
types.

0.2 amends only region pointers:

| Operand | `LEN` |
| --- | --- |
| `POINTER TO T[n]` | The declared element count `n`, as `INTEGER`. |
| `POINTER TO T[]` | The element count supplied at `NEW`, as `INTEGER`. |
| `POINTER TO T` (single value, no `[...]`) | Static error, as in 0.1. |
| `NULL` pointer of a region type | Runtime `NULL_POINTER_ACCESS`. |

`WriteBytes`, `BNMath` descriptive statistics on a region, and
`CopyIntegerColumn` / `CopyFloatColumn` use this `LEN` as the element
count. `SIZEOF` on pointers remains a static error.

An empty region (`NEW T[0]`) has `LEN` `0`. Every index into it still
raises `INDEX_OUT_OF_BOUNDS`.

`LEN(HOST.Args)` is the argument count, including the executable path. See
[Command-line arguments](#command-line-arguments).

## Class inheritance

Syntax: [class-declaration in `0.6.ebnf`](0.6.ebnf).

A class may declare a single base class:

```basic
CLASS Animal
    PRIVATE name AS STRING

    PUBLIC FUNCTION CONSTRUCTOR(name AS STRING)
        SELF.name = name
    END FUNCTION

    PUBLIC FUNCTION Name() AS STRING
        RETURN SELF.name
    END FUNCTION

    PUBLIC FUNCTION Speak() AS STRING
        RETURN ""
    END FUNCTION
END CLASS

CLASS Dog EXTENDS Animal
    PUBLIC FUNCTION CONSTRUCTOR(name AS STRING)
        SUPER(name)
    END FUNCTION

    PUBLIC FUNCTION Speak() AS STRING
        RETURN SUPER.Speak() + "woof"
    END FUNCTION
END CLASS
```

### Static rules

- The name after `EXTENDS` must resolve to a `CLASS` in scope. `STRUCT`,
  `INTERFACE`, primitive types, and undeclared names are static errors.
- A class extends at most one base. There is no multiple class inheritance.
- The inheritance graph is acyclic. A cycle is a static error.
- Interface inheritance (`INTERFACE Child EXTENDS Parent`), default methods,
  and abstract classes remain outside 0.6 (`PROTECTED` was added in 0.5.2;
  see [`PROTECTED` visibility (O3)](#protected-visibility-o3)).
- `PRIVATE` remains scoped to the declaring class. Methods of a subclass
  cannot read or write private members of the base, including through `SELF`
  or `SUPER`. Base methods may still access private members of any instance
  of that same base class.
- A subclass sees `PUBLIC` and `PROTECTED` instance fields and methods of its
  base through `SELF` and, for methods, through `SUPER` (0.5.2 O3).
- A field name declared in a class must not repeat a field name of any
  ancestor. Redeclaring a field is a static error.
- Functions and methods are not overloaded. Redeclaring an inherited
  `PUBLIC` or `PROTECTED` instance method with the same name, parameter count,
  parameter types, and return type is an **override** and requires explicit
  `OVERRIDE` (0.5.2 O2, [Explicit `OVERRIDE` (O2)](#explicit-override-o2)).
  Omitting `OVERRIDE` is `OVERRIDE_REQUIRED`. The same name with a different
  signature is a static error.
- All `PUBLIC` and `PROTECTED` instance methods are virtual. There is no
  `VIRTUAL` keyword. Overriding an inherited method requires the `OVERRIDE`
  keyword; placing `OVERRIDE` without a matching ancestor method is
  `OVERRIDE_WITHOUT_BASE`.
- `PRIVATE` instance methods are not overridable and are not visible in the
  subclass.
- `STATIC` members are not virtual. A `PUBLIC STATIC` field or function of
  the base is visible through the subclass name and through the base name;
  both names denote the same member. A subclass must not redeclare that
  name.
- A subclass inherits every interface that its base implements and may list
  additional interfaces after `IMPLEMENTS`. Each name after `IMPLEMENTS` is
  a `named-type`: `Printable` in the same module, or `Pets.Named` after
  `IMPORT Pets AS Pets`. It must resolve to an `INTERFACE`. A repeated
  entry is a static error. The class must supply a `PUBLIC` instance method
  for every interface member not already satisfied by an inherited public
  method.
- A class must not `EXTENDS` a host or standard-library class. In 0.2 that
  set is `FS.File`, `Data.DataFrame`, and `Error`. Composition (a field of
  type `FS.File`) is the allowed form.

### Assignment and dispatch

A value whose static type is a class is assignable to a variable, field, or
parameter of that class or of any ancestor class. The conversion is an
implicit upcast and preserves the object reference.

```basic
LET pet AS Animal = NEW Dog("Puck")
PRINT pet.Speak()    // dynamic dispatch: Dog.Speak
```

Dispatch of a `PUBLIC` instance method uses the **dynamic** class of the
object. An override in the most-derived class is called even when the static
type is the base or an interface.

A class value remains assignable to an interface it implements, including
interfaces implemented by an ancestor. Interface dispatch uses the same
dynamic class.

#### Vector literals take a declared destination (0.6.5)

A vector literal written where a vector type is declared — a `LET`
initializer, a field initializer, an argument, a `RETURN` value or an
assignment — checks each element against the declared element type, by the
rules of assignment above (upcast included). The literal then has the
declared element type. Its shape must still match the declared dimensions.

```basic
LET listeners AS Listener[2] = [NEW Printer("a"), NEW LoudPrinter("b")]
```

Each element is a `Listener` (`Printer IMPLEMENTS Listener`, `LoudPrinter
EXTENDS Printer`), so the literal is a `Listener[2]`. An element that is not
assignable to the declared element type is a `TYPE_MISMATCH` naming that
element. A numeric literal element must fit the declared element type, as in
a scalar store (`LET v AS INT64[2] = [1, 3000000000]`); an integer literal is
not a floating-point element (C2 converts only a scalar binding
initializer). A literal with no declared destination (`PRINT LEN([a, b])`) is
typed from its elements: its element type is the first element's (a
numeric literal takes its default type, `INTEGER` or `FLOAT`), and every
other element is checked against it by the same assignment rules, so
`[1, 2.5]`, `[2.5, 1]` and `[1, x]` with `x AS INT64` are each a
`TYPE_MISMATCH` naming the element (decision D-2, Carlos, 2026-10-12).

class named in `NEW`.

### `SUPER`

`SUPER` is a reserved primary. It is not a value: it cannot be assigned,
passed, indexed, or returned. Using `SUPER` outside a class that `EXTENDS`
another is a static error.

Two forms are valid:

1. **Constructor chaining.** `SUPER(arguments)` is a call. It is legal only
   as the first statement of a subclass constructor. Blank and comment-only
   lines may precede it because they are `NEWLINE`, not statements. It calls
   the unique constructor of the direct base class. Argument count and types
   must match that constructor.
2. **Parent method call.** `SUPER.Name(arguments)` calls the implementation
   of `Name` belonging to the nearest ancestor that declares it, skipping
   overrides in the current class. The method must be a `PUBLIC` instance
   method of an ancestor. `SUPER.Name` without a call, `SUPER.field`, and
   `SUPER` as an assignment target are static errors.

If the direct base has a parameterless constructor, a subclass constructor
that omits `SUPER()` receives an implicit `SUPER()` as its first action. If
the direct base constructor requires parameters, an explicit `SUPER(...)`
is mandatory; omitting it is a static error. A class that does not `EXTENDS`
another must not use `SUPER`.

A constructor still cannot be overloaded: each class has at most one
`FUNCTION CONSTRUCTOR`.

### Construction and destruction

Allocation of `NEW Derived(...)` proceeds as follows:

1. Allocate the most-derived object.
2. Evaluate `SUPER(...)` (explicit or implicit). That runs the base-class
   field initializers in source order, then the base constructor body, and
   so on until the class that does not `EXTENDS` another.
3. Run field initializers of the derived class in source order.
4. Run the remainder of the derived constructor body after `SUPER`.

A field without a default still requires an initializer, now executed at
step 3 for the class that declares it. 0.1 classes that do not use
`EXTENDS` keep the 0.1 order: field initializers, then the constructor body.

A successful `NEW` yields a **strong** reference whose count starts at one
for the binding that receives it. Lifetime ends when the strong count reaches
**zero** — typically when the last strong binding is released at end of
scope or on reassignment, or by an explicit `RELEASE` — never by a manual
dispose keyword (see [Memory model (ARC)](#memory-model-arc)). At that point
destructors run from the most-derived class toward the base. Each
`FUNCTION DESTRUCTOR` runs at most once. There is no `SUPER` in a destructor;
the chain is implicit. A class without a destructor still participates: it is
a no-op step in the chain. After destructors complete, the object's strong
fields are released in reverse declaration order — the derived class's fields
before the base class's, the reverse of initialization — and then the
allocation is freed.

While a constructor or destructor of class `C` is executing on an object,
a `PUBLIC` instance method call **on that object** uses the implementation
in `C` (or the nearest ancestor of `C` that declares it), not an override
in a subclass of `C`. Field initializers of a subclass have not yet run
during the base constructor, and a subclass destructor has already run
during the base destructor. After `NEW` returns, and until destruction
begins, dispatch uses the most-derived class as usual.
`SUPER.Name(...)` is unchanged: it always calls the ancestor implementation.

### Static field initialization and cycle detection

`STATIC` field initializers execute lazily upon the first reference to the
declaring class (at constructor invocation, static method call, or static field
access). Initializers within a class are evaluated in textual declaration
order. While a class's static initialization is running, any re-entrant access
to that class's static members (directly or indirectly via circular dependencies)
is detected by the runtime and stops execution with `STATIC_INITIALIZATION_CYCLE`.
Once initialization completes successfully, the class transitions to ready, and
subsequent accesses read the initialized static storage without re-evaluating
initializers.

## Memory model (ARC)

### Scope

These rules apply to **class instances** (reference types) and to **pointer
regions** (`NEW T[n]`, `POINTER TO T[]`). A value of an `INTERFACE` type holds
an object and is a strong reference to it, as a class-typed value is.
Structs, scalars, and fixed vectors keep **value / copy** semantics and are
not ARC themselves; a struct field or a vector element of a class type is a
strong reference like any other, so copying the struct or the vector retains
the objects it holds, and the end of the copy releases them: a struct's
fields in reverse declaration order (as an object's), a vector's elements in
index order.

### Strong references (default, automatic)

Locals, fields, parameters, and returns of class types are **strong** unless
annotated weak. The toolchain inserts retain and release at the natural
lifetime points:

- **Assign** — retain the new value; release the previous value of the target
  (when it held a class instance). Assigning `NULL` to a field, a `STATIC`,
  or a local drops the reference it held.
- **Parameter** — a parameter is a **constant** binding: the callee cannot
  assign to it (`TYPE_MISMATCH`). The caller keeps the argument alive for
  the whole call, so the callee never releases the caller's object. A
  callee that needs a changing value declares a local (`LET n AS T = x`).
- **Temporary** — a value no binding holds (a `NEW` argument such as
  `Use(NEW Box())`, a returned object whose call is a statement) is released
  at the end of the statement that produced it.
- **Return** — retain for the caller's received value; release locals that go
  out of scope as the frame unwinds.
- **End of scope** — release every strong local that leaves the block, in
  **reverse declaration order** (the last declared is released first).
- **`STOP`** — before the program ends, every running function releases its
  locals as if it returned: first the function that executes `STOP`, then
  its caller, and so on out to `Start`. Within each function, first the
  values of the statement in progress that no binding holds (temporaries),
  then the open scopes, innermost first, each in reverse declaration order.
  `STATIC` fields are not released, as at the normal end of a
  program. In a function that a library runs (a `BNDispatch` task, a `BNWeb`
  handler), the release reaches that function. (BDFL decision, 2026-10-06;
  until 0.6.4 only the locals of the function that stops were released.)

The model is Swift's ARC (BDFL decision, 2026-10-06). Where Swift leaves an
implementation free (it may release an object after its last use, and it
does not order releases), Basic Next fixes one choice that the Swift model
permits — release at the end of the scope, in reverse declaration order — so
the interpreter and the compiler never differ.

The programmer does **not** manually retain. A hello-world class needs no
dispose keyword:

```basic
CLASS Counter
    PUBLIC count AS INTEGER = 0

    PUBLIC FUNCTION CONSTRUCTOR()
    END FUNCTION

    FUNCTION DESTRUCTOR()
        PRINT "Counter gone"
    END FUNCTION

    PUBLIC FUNCTION Inc() AS VOID
        SELF.count = SELF.count + 1
    END FUNCTION
END CLASS

FUNCTION Start() AS VOID
    LET c AS Counter = NEW Counter()
    c.Inc()
    PRINT c.count
    // c released at end of Start; destructor runs when strong count → 0
END FUNCTION
```

Sharing aliases keeps the object alive until all strong bindings are gone;
reassignment drops the previous strong binding:

```basic
FUNCTION Share() AS VOID
    LET a AS Counter = NEW Counter()
    LET b AS Counter = a
    // both strong; object lives until both leave scope
END FUNCTION

FUNCTION Rebind() AS VOID
    LET x AS Counter = NEW Counter()
    x = NEW Counter()
    // first instance released if no other strong aliases remain
END FUNCTION
```

### Zero strong → destructor

When an object's strong count reaches zero, the implementation runs the
destructor chain (most-derived toward base), then releases the object's
strong fields in **reverse declaration order** (the last declared field is
released first, as for the locals of a scope; BDFL decision, 2026-10-06), and
frees the allocation, as specified under
[Construction and destruction](#construction-and-destruction).

### Weak references (cycles)

Weak references are **non-owning**. They break retain cycles and do not keep
the referent alive.

```basic
LET x AS WEAK Counter OR NULL = someStrong
PRIVATE other AS WEAK Node
PRIVATE other AS WEAK Node OR NULL = NULL
```

- Grammar: `WEAK` + `named-type` (`weak-named-type` in [`0.6.ebnf`](0.6.ebnf)).
- Prefer `OR NULL` so a dead weak is assignable and testable with `IS NULL`.
- When the referent's strong count reaches zero and the object is collected,
  every weak binding to it reads as **`NULL`**.
- Assigning a strong class value into a weak binding does not retain; the weak
  observes the object while it lives. An object that only a weak binding
  refers to (`w = NEW Node("n")` with `w` weak) has no strong reference: it is
  released at the end of that statement, and `w` reads `NULL`.

```basic
CLASS Node
    PUBLIC next AS WEAK Node OR NULL = NULL
    PUBLIC label AS STRING = ""

    PUBLIC FUNCTION CONSTRUCTOR(label AS STRING)
        SELF.label = label
    END FUNCTION
END CLASS

FUNCTION CycleBreak() AS VOID
    LET a AS Node = NEW Node("a")
    LET b AS Node = NEW Node("b")
    a.next = b
    b.next = a
    // next is weak — no strong cycle
END FUNCTION
```

### Pointer regions under ARC

**Carlos lock (2026-09-16).** A region created by `NEW T[n]` is a reference-
counted allocation. A `POINTER TO T[]` binding is a **strong** reference to
its region; copying the pointer (assignment, parameter, return) retains, and
the region is freed when its strong count reaches zero. There is no
destructor chain for regions; freeing is immediate.

- `RELEASE p` drops **one** strong from the binding `p` — never
  kill-all-aliases. Other pointer bindings to the same region keep it alive
  and keep reading the same elements.
- After `RELEASE p`, any use of `p` (`p[i]`, `LEN(p)`, passing `p`) is a
  **use-after-release** error; a second `RELEASE p` is a double-release
  error. Both are diagnosed on the *binding*, not on the region.
- A `NULL` pointer holds no region; `RELEASE` on a `NULL` binding ends the
  binding only.
- `POINTER TO VOID` participates identically: converting to or from a typed
  pointer neither retains nor releases beyond the ordinary binding rules.

```basic
FUNCTION Regions() AS VOID
    LET a AS POINTER TO INTEGER[] = NEW INTEGER[3]
    a[0] = 7
    LET b AS POINTER TO INTEGER[] = a    // second strong; region count 2
    RELEASE a                            // count 1; a is unusable from here
    PRINT b[0]                           // 7 — the region is alive through b
    // region freed when b leaves scope
END FUNCTION
```

Conformance: fixtures **F14** (pointer aliasing survives `RELEASE` of one
binding, both backends) and **F15** (use-after-release / double-release on
a pointer binding) in [`arc-conformance.md`](arc-conformance.md).

### No force-dispose; no `DELETE`

There is **no** operation that destroys a live object while other strong
aliases remain. The `DELETE` keyword is removed from the grammar, the
reserved-word list, and the teaching surface. Unowned references are
deferred and are not part of 0.5.

### Interpret = reference; compile = parity

The interpreter implements these ARC rules as the **executable reference**.
The LLVM backend implements the same observable behaviour (retain/release
insertion) and is held to the same conformance fixtures F1–F13
([`arc-conformance.md`](arc-conformance.md)); no silent native
drift is permitted. Both toolchains count references in one shared core of
the runtime (`bn_rt`); it is an implementation detail, not a language API.

## `RELEASE` (optional advanced)

`RELEASE` ends a binding **early**. It applies to **primaries, fixed vectors,
structs, class objects, alternatives, and pointer regions**. The operand must
name a **local binding or a parameter**, of any type, as Swift's `consume`
does (SE-0366, BDFL decision 2026-10-06). A field, a `STATIC`, or an element
of a fixed aggregate is not a binding (`INVALID_RELEASE_TARGET`): assign
`NULL` to drop the reference a field or a `STATIC` holds (`h.slot = NULL`).
`RELEASE` of a parameter ends the callee's binding only; the caller's object
stays alive (see "Parameter" above). `SELF` is the receiver parameter of a
method, so `RELEASE SELF` ends only that binding as well, also inside a
`DESTRUCTOR` (the object is destroyed once; a second `RELEASE SELF` is a
double release; BDFL decision, 2026-10-06).

After `RELEASE`, any use of that binding is a **use-after-release** error
(frontend or runtime diagnostic). Ordinary programs may omit `RELEASE` and
simply leave scope; scope exit performs the same end-of-binding work.

| Operand kind | Effect of `RELEASE binding` |
| --- | --- |
| **Class / object** | Drop **one** strong from this binding; run the destructor only if the strong count reaches 0. Other strong aliases keep the object alive (never kill-all-aliases). |
| **Fixed vector** | End the **aggregate** binding. Nested element lifetimes follow ordinary rules as the vector storage ends (including releasing strong elements). `RELEASE a[i]` is **not** "remove middle element" and is invalid. |
| **Struct** | End the **aggregate** binding; nested field rules apply (value fields discarded; class fields released as strong drops). |
| **Primary** (`INTEGER`, `FLOAT`, `BOOLEAN`, `STRING`, …) | End the local binding only — no reference count. The slot is unusable until redeclared (same use-after-release rule). |
| **Alternative** (`Box OR NULL`, `Box OR Error`, `INTEGER OR STRING`, …) | End the binding; when it holds an object, drop **one** strong from it, as for a class object. |
| **Pointer region** (`POINTER TO T[]`, `POINTER TO VOID`) | Drop **one** strong from this binding; free the region only if the strong count reaches 0. Other pointer aliases keep the region alive. See [Pointer regions under ARC](#pointer-regions-under-arc). |

- `RELEASE` is **not** a substitute for a HOST **`Close`**. `Close` releases the
  capability resource; `RELEASE` ends the BN binding.
- Prefer end of scope and reassignment in ordinary teaching.
- Fixed vector of tickets: `Close` each element, then optionally `RELEASE`
  the whole `tickets` binding — never `RELEASE tickets[i]` as element removal.

```basic
FUNCTION EarlyDrop() AS VOID
    LET c AS Counter = NEW Counter()
    c.Inc()
    RELEASE c
    // if no other strong aliases, destructor runs here
    // c.Inc()  // use-after-release — error
END FUNCTION

FUNCTION ReleasePrimary() AS VOID
    LET n AS INTEGER = 42
    RELEASE n
    // PRINT n  // use-after-release — error
END FUNCTION
```

## HOST: `Close` / `*_close` only

Opaque HOST and library resources (files, DataFrame handles, net objects,
dispatch tickets, and similar) use capability methods such as `Close` and
`*_close`. `DELETE` is never reintroduced as sugar over those closes.
Unifying HOST handles into ARC class types is a later proposal, not part of
0.5.

```basic
IMPORT HOST.FileSystem AS FS

FUNCTION ReadOnce(path AS STRING) AS VOID OR Error
    LET file AS FS.File OR Error = FS.Open(path, FS.READ)
    IF file IS Error THEN
        RETURN file
    END IF
    // … use file …
    RETURN file.Close()
END FUNCTION
```

For a **fixed vector of tickets**: loop `tickets[i].Close()` (runtime
resource), then optionally `RELEASE tickets` on the aggregate — never
`RELEASE tickets[i]`.

```basic
FOR i AS INTEGER = 0 TO 3
    tickets[i].Close()
END FOR
RELEASE tickets
```

## Interfaces in 0.2

The 0.1 interface contract stands: an interface contains only function
signatures; a class lists `IMPLEMENTS` explicitly; only a `PUBLIC` instance
method satisfies a member; interface upcast preserves the reference.

Each entry after `IMPLEMENTS` is a `named-type`, so a class in one module
may implement an exported interface from another:

```basic
IMPORT Pets AS Pets

CLASS Dog IMPLEMENTS Pets.Named
    PUBLIC FUNCTION Name() AS STRING
        RETURN "Puck"
    END FUNCTION
END CLASS
```

Imported names remain `alias.member`; `IMPLEMENTS Named` does not see
`Pets.Named` unless the interface is declared in the same module.

0.2 adds that an override in a subclass is visible through an interface-typed
or base-typed reference to that object. Interface inheritance, default
methods, and reflection remain outside 0.2.

## Console methods

0.2 withdraws the 0.1 statements `CLS(expression)` and `BEEP(expression)`.
There is no `PRINTAT` statement. The canonical form is a method on the
console capability. `PRINT` and `INPUT()` are stream macros. `PRINT` writes
each expression in an expression list separated by one space, followed by one
line ending; `+` remains the string-concatenation operator within an expression.
For example, `PRINT "CASA" + "SHO"` writes `CASASHO`, while
`PRINT "CASA", "SHO"` writes `CASA SHO`.

```basic
IMPORT HOST.Console AS CON

CON.Cls()
CON.Beep()
CON.PrintAt(1, 1, "ready")
LET width AS INTEGER = CON.NumCols()
LET height AS INTEGER = CON.NumRows()
```

The same methods are valid on the unqualified capability:

```basic
HOST.Console.Cls()
HOST.Console.Beep()
HOST.Console.PrintAt(column, row, text)
```

Method names are identifiers, so they follow ordinary PascalCase (`Cls`,
`Beep`, `PrintAt`), not the withdrawn uppercase statement spellings. A 0.2
program that writes `CLS(HOST.Console)` is a call to an identifier `CLS`,
not a language statement; without a matching function it is a static error.

- `Cls() AS VOID` clears the display and homes the cursor. Reference:
  portable ANSI erase-display-and-home. Available when output is piped.
- `Beep() AS VOID` emits ASCII BEL. Available when output is piped.
- `PrintAt(column AS INTEGER, row AS INTEGER, text AS STRING) AS VOID`
  writes `text` at a **1-based** cell. `(1, 1)` is the top-left cell.
  `column` is X; `row` is Y. No `PRINT`-style concatenation and no trailing
  newline. The cursor ends after the last character written. Reference:
  ANSI CUP. Out of the current window, or a string that would extend past
  `NumCols` on that row, raises `INDEX_OUT_OF_BOUNDS`. No wrap, no clip.
  Each Unicode scalar occupies one cell (`LEN(text)` cells). Combining
  marks and wide glyphs are outside 0.2 and still count as one cell each.
- `NumCols() AS INTEGER` and `NumRows() AS INTEGER` read the current window
  on each call. They are not cached at `Start`. A column is a terminal cell,
  not a `LEN` or `SIZEOF` unit.

When standard output is not a TTY, `PrintAt`, `NumCols`, and `NumRows`
raise `HOST_CAPABILITY_UNAVAILABLE` **at the call**, at runtime. A branch
that does not execute the call does not fail. `PRINT`, `INPUT()`, `Cls`,
and `Beep` remain available when output is piped. The Jupyter kernel
follows the same rule.

The full console contract is [`console.md`](console.md).

`BNPallet` is an external standard-library module containing the CSS/W3C named

`BNMath` is an external standard-library module under `modules/bn/BNMath.bn`;

### Vector parameters

A standard-library or host parameter described as “a fixed-size `INTEGER`
vector of any length” (and the same for `FLOAT`, `STRING`, `BOOLEAN`)
accepts `INTEGER[1]`, `INTEGER[2]`, … — every declared fixed vector of that
element type. In versions prior to 0.6.5, this was an internal library-only rule;
under 0.6.5 (amendment A8, § [Open parameter](#vectors)), user `FUNCTION` and method
declarations may also declare an open first dimension (`v AS INTEGER[]`, `v AS FLOAT[]`),
accepting any vector with matching element type and inner dimensions. `BNMath`
reductions, `Add*Column`, and `Select` use this rule.

`Error` is an object with `Code AS INTEGER`, `Operation AS STRING`,
`Message AS STRING`, and `Cause AS STRING` (0.6.2; the contract, including
the portable codes, is [error.md](error.md)). Fallible file and CSV
operations return `T OR Error`. They do not raise exceptions.

## `IS` narrowing after returning branches

0.1 narrows an alternative in the `THEN` / `ELSE IF` branch that tests it
and in the `ELSE` branch that excludes it. 0.2 also applies those complement
facts to the statements that follow an `IF` without `ELSE` when every taken
branch returns or `STOP`s:

```basic
LET file AS FS.File OR Error = FS.Open("vendas.csv", FS.READ)
IF file IS Error THEN
    RETURN
END IF
LET closed AS VOID OR Error = file.Close()
```

After the `RETURN`, `file` has type `FS.File`. The same rule applies to
`ELSE IF` chains with no `ELSE`. A taken branch that can complete normally
leaves the declared alternative type in force after the `IF`.

## Recursion depth (0.6.5)

Decided 2026-10-11 (Carlos; known issue K53): the language sets no fixed
limit on recursion depth; machines grow, and a fixed depth would become an
arbitrary ceiling. A function may call itself, directly or through others,
until the call stack of the running program is exhausted. Every call takes
stack on both backends (a compiler does not turn a call into a jump), so a
recursion that never ends stops the same way under `bni` and `bnc`.

When a call would exhaust the stack, the program stops with the runtime
error `STACK_OVERFLOW` (exit status 1, as every runtime error), naming the
call at its source position, on both backends. Output written before the
stop is not lost. It is not an `Error` value: a program cannot catch it.

## Command-line arguments

0.2 withdraws `HOST.Main`, `SYSTEM`, `ArgumentCount()`, and `Argument(index)`.
The executable module uses `HOST.Args`. No `IMPORT` is required. A non-executable
module that names `HOST.Args` is a static error.

```basic
FUNCTION Start() AS INTEGER
    PRINT HOST.Args[0]
    RETURN 0
END FUNCTION
```

`HOST.Args` is a host argument list, not a user vector and not a `CLASS`.
It is valid only in `LEN(HOST.Args)` and `HOST.Args[index]`. Using `HOST.Args`
as a value (assignment, parameter, `PRINT HOST.Args`) is a static error.
`HOST.Args[index]` is not an assignment target.

| Form | Meaning |
| --- | --- |
| `LEN(HOST.Args)` | Count of entries, as `INTEGER`, including entry `0`. |
| `HOST.Args[0]` | Absolute path of the executed file. Under `bni run`, that is the `.bn` source. Under a compiled program (`bnc`), that is the produced executable. The path is rooted (`/` on Unix; a drive root such as `C:\` on Windows). |
| `HOST.Args[i]` for `i >= 1` | Program arguments in order. Under `bni run`, the entries after `--`. |

An index smaller than `0` or greater than or equal to `LEN(HOST.Args)`
raises `INDEX_OUT_OF_BOUNDS`. Entries are immutable `STRING` values.

## Host capabilities

0.5 host capabilities are `Args`, `Clock`, `Console`, `Random`,
`FileSystem`, `Net`, `NumProcs`, and (0.5.1) **`Exec`**. `HOST.Main` is not
a capability.
The spelling **`HOST.Network` must not exist**; the networking capability is
**`HOST.Net`** only. `HOST.Net` is imported explicitly:

```basic
IMPORT HOST.Net AS Net
```

**Which capabilities need `IMPORT`** (BDFL, 2026-10-07). `HOST.Console`,
`HOST.Args` and `HOST.NumProcs` are used without an `IMPORT`. Every other
capability (`Clock`, `Random`, `FileSystem`, `Net`, `Exec`, `Env`) is used only
through an `IMPORT HOST.<capability>` of the module; naming `HOST.Clock`,
`HOST.Random`, … in a module that does not import it is a static
`NAME_NOT_FOUND` that names the missing `IMPORT`. The qualified form is valid
once the capability is imported (`IMPORT HOST.Clock AS Clock` makes both
`Clock.Now()` and `HOST.Clock.Now()` valid).

`HOST.NumProcs() AS INTEGER OR Error` requires no import and returns the
operating-system-reported number of logical processors available to the current
process. It is suitable for selecting a bounded worker-pool size; it does not
claim a physical-core count. It is a native-interpreter capability. The result
is `Error` when the host cannot report a usable count.

`Net` owns typed IPv4/IPv6 addresses, CIDRs, endpoints, forward/reverse
system lookup, bounded TCP/UDP I/O, bounded IPv4/IPv6 ICMP Echo, and direct
ARP/NDP lookup. Its complete
method signatures, ownership, limits, and error channels are frozen by WBS
Phase 0 before implementation starts. No BN value exposes an OS descriptor or
raw packet. ICMP support is limited to one Echo Request/Reply operation per
call; arbitrary ICMP types, caller-provided payloads, source spoofing,
traceroute, and packet capture are outside 0.3.
The normative functional contract is [`host-net.md`](host-net.md).

IPsec is a host deployment policy, not a BN protocol or `BNWeb` feature. A
native host may transparently protect `HOST.Net` TCP or UDP traffic through
operating-system IPsec policy and security associations. BN neither detects
nor configures that protection, and exposes no key, IKE, tunnel, security
association, or kernel-policy value. The 0.3 capability matrix records only
whether the selected host has executable evidence for transparent IPsec use.

`BNLog`, `BNJson`, `BNWeb`, and `BNCrypto` are explicitly imported external
modules, never `HOST` capabilities:

```basic
IMPORT BNLog AS Log
IMPORT BNJson AS Json
IMPORT BNWeb AS Web
IMPORT BNCrypto AS Crypto
```

`BNLog` provides bounded structured entries, severity filtering, formats,
console/file/null transports, child context, flush, and close. Its normative
0.3 contract is [`bnlog.md`](bnlog.md).

`BNJson` provides bounded synchronous JSON parsing and serialization through
an external Rust provider. Its normative 0.6.1c contract (DOM + AOT) is [`bnjson.md`](bnjson.md).

`BNCrypto` provides digests (SHA-256, SHA-512), an opaque `Bytes` buffer,
authenticated encryption (AES-256-GCM, ChaCha20-Poly1305), message
authentication (HMAC-SHA-256), password hashing (Argon2id), signatures
(Ed25519, ECDSA P-256) and the post-quantum primitives ML-KEM-768 (FIPS 203)
and ML-DSA-65 (FIPS 204). Every member executes the same `bn_rt` implementation
under both backends. Its normative contract is
[`bncrypto.md`](bncrypto.md).

`BNWeb` provides the shared HTTP request/response pipeline, deterministic routes,
bounded client/server I/O, HTTPS, trusted-proxy provenance, filtering, ACL,
sessions, static scraping, and Apache-compatible access logs. HTTP/1.1 and
HTTP/2 are required. Default responses include `X-Content-Type-Options:
nosniff`; `Strict-Transport-Security` is emitted only for TLS responses.
HTTP/3 remains deferred beyond the initial 0.4 slice. Templates, WebSocket,
ORM, OAuth, generic plugins or middleware, browser automation, and
persistent/distributed sessions are outside 0.4.

BNWeb cookie storage defaults to `Secure`, `HttpOnly`, and `SameSite=Lax`.
Applications may use the explicit cookie policy operation to select
`Strict`, `Lax`, or `None`; `SameSite=None` requires `Secure=true`. Cookie
and session identifiers are not included in default logs.

Outbound BNWeb traffic may opt into an immutable `EgressPolicy`. Its
`schemes`, `cidrs`, and `ports` arguments are comma-separated allowlists;
empty lists deny all destinations in that dimension. `maxRedirects` and
`totalDeadlineMs` are bounded by the 0.4 registry. `Client.RequestWithPolicy`
resolves the hostname, applies the global private/sensitive-address policy,
then requires every selected address and every redirect destination to match
the declared allowlists. The policy is evaluated by the same resolver path as
the default client; no hidden second DNS lookup or socket is permitted.

```basic
LET policy AS Web.EgressPolicy OR Error = Web.EgressPolicy.New(
    "http", "93.184.216.0/24", "80", 3, 30000)
LET response AS Web.Response OR Error = client.RequestWithPolicy(
    "GET", "http://example.invalid/", "", policy)
```

Synchronous BN handlers remain the 0.4 default. No concurrent
transport-to-BN handler execution is claimed until the opt-in explicit-queue
design's admission, ownership, response, and shutdown contracts are accepted.
The bounded `ASYNC`/`AWAIT` amendment is documented in the
async/await design.

The `BNWeb` implementation consumes the resolved `HOST.Net` provider for all
socket and resolver operations. It does not create an independent network
provider or expose the host provider's descriptors. Applications still import
each module or capability they use directly; imports do not create transitive
aliases in application scope.
The normative functional contract is [`bnweb.md`](bnweb.md).


### `HOST.Exec` (0.5.1)

`HOST.Exec` launches an operating-system executable **without a shell** and
waits for it synchronously. It is an explicitly imported capability; it adds
no keyword, statement, or expression form.

```basic
IMPORT HOST.Exec AS Exec

FUNCTION Start() AS VOID
    LET args AS STRING[1]
    args[0] = "-s"

    LET r AS Exec.Result OR Error = Exec.Run("uname", args)
    IF r IS Error THEN
        PRINT r.Message
        STOP 1
    END IF

    PRINT r.ReturnCode
    PRINT r.Stdout
    IF LEN(r.Stderr) > 0 THEN
        PRINT r.Stderr
    END IF
END FUNCTION
```

**Surface.** `Run(program AS STRING, args AS STRING[]) AS Exec.Result OR Error`.
`args` is a fixed `STRING` vector of any length (library vector rule), passed
as the child's argument vector **without** shell word-splitting; the child
receives `[program] + args`. `Exec.Result` is a nominal class (canonical
`HOST.Exec.Result`) with immutable fields `ReturnCode AS INT64`,
`Stdout AS STRING`, and `Stderr AS STRING`. It is an ordinary ARC value; it
has no `Close`.

**Semantics.**

1. `program` is resolved as the platform's usual executable search (an
   explicit path, or a name through `PATH`). The child starts in the BN
   process's current working directory and inherits its environment.
2. Child **stdin is closed** (EOF on read). `stdout` and `stderr` are captured
   concurrently and independently as UTF-8 `STRING`s.
3. A **non-zero child exit status is a successful `Run`**: the call returns
   `Result`, and the caller inspects `ReturnCode`. `Error` is reserved for the
   host failing to launch, wait for, or capture the child.
4. On POSIX, termination by signal yields `ReturnCode = -signal`. Windows
   preserves its native termination status in `INT64` without truncation.
5. Capture is bounded: 16 MiB per stream and a 60 s wall clock from
   immediately before spawn through child termination and pipe EOF. Exceeding a
   ceiling returns `Error` — never a truncated `Result` — after the child
   process tree is terminated and reaped. Execution policy may **reduce** these
   ceilings but never raise them.
6. `Run` does not interpret `.bn` source and does not replace the BN process
   (it is not POSIX `execve`).

**Errors.** `Error.Code` uses the portable constants exposed on the capability
(independent of toolchain diagnostic codes; an OS code may appear in
`Error.Message` but never replaces the portable code):

| Constant | Value | Meaning |
| --- | ---: | --- |
| `Exec.INVALID_ARGUMENT` | 1 | Empty program, embedded NUL, or invalid argument shape |
| `Exec.PROGRAM_NOT_FOUND` | 2 | Executable could not be resolved |
| `Exec.PERMISSION_DENIED` | 3 | OS permission prevented launch |
| `Exec.SPAWN_FAILED` | 4 | Other child-creation failure |
| `Exec.WAIT_FAILED` | 5 | Host could not observe termination |
| `Exec.CAPTURE_FAILED` | 6 | Pipe/read/capture failure |
| `Exec.INVALID_UTF8` | 7 | A captured stream is not valid UTF-8 |
| `Exec.CAPTURE_LIMIT` | 8 | stdout or stderr ceiling exceeded |
| `Exec.TIMEOUT` | 9 | Wall-clock ceiling exceeded |
| `Exec.TERMINATION_FAILED` | 10 | Required containment cleanup failed |
| `Exec.POLICY_DENIED` | 11 | Provider exists but execution policy denies the call |

**Availability and policy** (three distinct outcomes):

- A target without an implementation rejects otherwise valid IR at
  `validate_for(target)` with `TARGET_UNSUPPORTED_HOST`.
- A target that supports `Exec` but whose selected host cannot bind the
  provider fails before `Start` with `HOST_CAPABILITY_UNAVAILABLE`.
- When the provider exists but **execution policy** denies the call, `Run`
  returns `Error(Code = Exec.POLICY_DENIED)` and no child is created. Policy
  is checked before spawning; on the compiled path the runtime re-checks at
  the spawn boundary. Restricted profiles (for example a notebook kernel) deny
  `HOST.Exec` by default.

**Policy inputs (0.5.2a).** The execution environment may narrow `HOST.Exec`
through three variables, honoured identically by `bni run` and by a compiled
artifact (`bnc`): `BN_EXEC_POLICY=deny` denies every call (`Exec.POLICY_DENIED`);
`BN_EXEC_CAPTURE_LIMIT=<bytes>` and `BN_EXEC_TIMEOUT_MS=<milliseconds>` are
non-negative integers that **reduce** the 16 MiB / 60 s ceilings (a larger
value has no effect). An empty value is the same as an absent one. Any other
value is a configuration error: the process does **not** start (the
interpreter reports `CONFIG_INVALID` and exits with status 2; a compiled
artifact fails in the same way before `Start` runs). A malformed policy never
falls back to the defaults on either backend.

Both the interpreter and the native (LLVM) backend implement `HOST.Exec` with
the same observables (fixtures E01–E14). The error constants listed in the table
above are exposed as integer members on the imported capability (e.g. `Exec.POLICY_DENIED`).
The library contract is [`host-exec.md`](host-exec.md).

### `HOST.Env`

`HOST.Env` provides read-only access to the process environment through `IMPORT HOST.Env AS Env`.

```basic
IMPORT HOST.Env AS Env

FUNCTION Start() AS INTEGER
    LET path AS STRING OR Error = Env.Get("PATH")
    IF path IS Error THEN
        PRINT "PATH not available:", path.Code
        RETURN 1
    END IF
    PRINT Env.Has("PATH")
    RETURN 0
END FUNCTION
```

| Member | Result |
| --- | --- |
| `Env.Get(name AS STRING)` | `STRING OR Error`: value of variable; `Error` if not set or invalid |
| `Env.Has(name AS STRING)` | `BOOLEAN OR Error`: `TRUE` if variable is set, `FALSE` if absent |

`HOST.Env` is read-only. It does not provide `Set` or `Remove` (modifying environment variables in a running multi-threaded process is unsafe), and does not enumerate all variables. An empty variable (`""`) is considered set.

**Errors.** `Error.Code` uses portable constants exposed on the capability:

| Constant | Value | Meaning |
| --- | ---: | --- |
| `Env.NOT_SET` | 1 | The requested variable is not set (`Get` only) |
| `Env.INVALID_NAME` | 2 | `name` is empty or contains `=` or NUL |
| `Env.INVALID_UTF8` | 3 | Value contains invalid UTF-8 bytes |
| `Env.POLICY_DENIED` | 4 | Execution policy denies environment access |

**Availability and policy:**
- A target without an implementation rejects IR at `validate_for(target)` with `TARGET_UNSUPPORTED_HOST`.
- A target that supports `Env` without an active host provider fails at the call with `HOST_CAPABILITY_UNAVAILABLE`.
- `BN_ENV_POLICY=deny` denies all reads (`Error(Code = Env.POLICY_DENIED)`). Allowed by default. Restricted profiles (notebook kernel) deny by default.
- Any malformed `BN_ENV_POLICY` value results in `CONFIG_INVALID` (process exits with status 2 before `Start`).
- The library contract is [`host-env.md`](host-env.md).

### `HOST.Random` is non-cryptographic

`HOST.Random` (`Random`, `Seed`) is an explicitly **non-cryptographic**
pseudo-random generator intended for simulations, games, and non-adversarial
randomized algorithms. It must never be used for security tokens, keys,
nonces, or session identifiers; library facilities that need those (for
example `BNWeb` sessions) use the operating-system CSPRNG and never consume
`HOST.Random`.

### `HOST.FileSystem` execution policy

Filesystem access is subject to an execution policy that can only **narrow**
what a program may do; it never widens it. Untrusted execution environments
default to fail-closed (denied or rooted) access; a trusted host grants the
process's own filesystem view explicitly. `BN_FS_POLICY=deny` and
`BN_FS_POLICY=read-only` narrow interpreter or compiled-artifact access in the
same way; any other non-empty value is a configuration error and the process
does not start (`CONFIG_INVALID`, exit status 2, on both backends). Rooted access on Unix pins each root as a directory descriptor and
performs open, create, truncate, append, and delete relative to it without
following symbolic links; a platform without that primitive denies rooted
access. A denied operation returns `Error`, not a truncated success.

`HOST.Random` may be imported by any module, with the same availability rule
as `HOST.Clock`:

```basic
IMPORT HOST.Random AS R
LET unit AS FLOAT = R.Random()
R.Seed(1)
```

`HOST.FileSystem` is a capability, not a set of keywords:

```basic
IMPORT HOST.FileSystem AS FS
LET file AS FS.File OR Error = FS.Open("data.txt", FS.READ)
```

An imported capability that the selected host cannot provide fails before
`Start` with `HOST_CAPABILITY_UNAVAILABLE`. The Jupyter 0.2 kernel does not
provide `HOST.FileSystem`. Positioned console methods fail at the call if
the cell is not a TTY.
The normative host contract is [`host.md`](host.md).

## Minimum useful program subset

The 0.1 minimum useful subset remains sufficient. 0.2 does not require
inheritance, positioned console methods, files, or `BNData` to write a

## Jupyter host

A notebook is another host of the Basic Next runtime, not a second language. A cell is a
complete program with `FUNCTION Start()`. There are no top-level statements
and no state between cells. Diagnostics are the same as `bni run`.

The 0.2 kernel is a separate Python package (working name `bn-kernel`) that
writes the cell to a temporary `.bn` file and runs `bni run`. The Rust crate
does not link ZeroMQ and stays zero-dependency.

## Compilation

Compilers consume **typed BN IR only**. `bnc` artifacts and per-target
capability tables are specified in the compiler track. The reference
pipeline is:

```text
.bn source → lexer → parser/AST → semantics → typed BN IR → interpreter
typed BN IR → LLVM IR → { Windows | macOS | Linux }
```

Both backends consume the **same validated IR**; a construct outside the
native support matrix fails a *support* check (`TARGET_UNSUPPORTED_*`), which
is distinct from language-invalid IR. `unsafe` remains forbidden unless the
BDFL approves a narrow use. JVM is not a backend.

Both backends represent `STRING` as an immutable, length-counted sequence of
Unicode scalar values (code points). U+0000 is a valid scalar on every target
(BDFL decision, 2026-10-12; § [`STRING`](#string)): runtime creation via
`CHAR(0)`, `INPUT`, file reads, process output, `BNJson`, and `BNData`
preserves U+0000 without shortening the string and without stopping the
program. String literals in source text cannot contain raw U+0000 (disallowed
by the lexical grammar, [`0.6.ebnf`](0.6.ebnf)).

## Migration: 0.4.x → 0.5

| 0.4.x pattern | 0.5 replacement |
| --- | --- |
| `DELETE x` on a class instance | Prefer end of scope or reassignment so ARC releases the last strong. Use `RELEASE x` only for an intentional early drop of one strong binding. |
| `DELETE` on HOST / library handles | Use `Close` / `*_close` (unchanged). |
| Teaching "you must DELETE" | Teach strong/weak + scope instead. |
| `AWAIT ticket(ms)` typed `VOID OR Error` only | Declare the worker `AS T OR Error`; `AWAIT` yields `T OR Error`. |

Programs written for 0.4 that use `DELETE` are **not** source-compatible with
0.5: the keyword is gone. Migration is a deliberate break, not a soft
deprecation. Book bridge: [`memory-migration.md`](memory-migration.md).

### Module names and files (0.6.5)

Decided 2026-10-10 (Carlos; known issue K47). A module path names a file
letter for letter on every platform: `IMPORT geo.Shapes AS S` loads
`geo/Shapes.bn` and nothing else. Each segment but the last is a
directory, the last is the file name without `.bn`, and letter case must
match the directory and file names exactly, even on a file system that
ignores case. A file that differs only in case is not a match: the import
is `MODULE_NOT_FOUND`, naming the path looked for, on every platform.

Every `IMPORT` of a program, whatever file it is written in, is resolved
against the same ordered list of directories; the first directory that
holds the file wins:

1. the directory of the entry file;
2. its `modules/` subdirectory, when present;
3. the standard library (`modules/bn`, or the one `BN_HOME` names);
4. the `module-path` array of the `config.toml` in use, each relative path
   taken from the directory of that file;
5. each `--module-path <dir>` of the command line, in order.

`bni` and `bnc` use the same list, so a program cannot run one module and
compile another.

### Qualified export import (I1)

Grammar unchanged (`module-import-path = identifier { "." identifier }`);
the **meaning** of a multi-segment path changes:

| Form | Meaning |
| --- | --- |
| `IMPORT M AS A` | Whole module, as today. |
| `IMPORT M.E AS A` | `M` = all segments but the last, `E` = the last. If `E` is an `EXPORT` of module `M`, `A` denotes **that export only** (siblings stay invisible). |

Resolution order: load `M` as today; if `E` is an export of `M`, bind it.
Only when `E` is **not** an export does the path fall back to today's nested
module resolution (`M/E.bn`). A path whose last segment is neither an
export nor a nested module is a static error `IMPORT_EXPORT_NOT_FOUND`
(distinct from `MODULE_NOT_FOUND`). `AS` stays required; no `FROM`; no
`.bn` in paths; `HOST.*` paths keep the host production.

**0.5.2 limit (recorte, 2026-09-19):** the alias may bind an exported
**type** (`CLASS`, `STRUCT`, `INTERFACE`). Naming an exported function or
constant (`IMPORT M.Area AS Area`) is `IMPORT_EXPORT_NOT_FOUND` with a
message pointing to the whole-module form; lifting this limit is a later
bucket, not a silent extension.

```basic
IMPORT BNString.String AS Str
LET s AS Str = NEW Str("a,b,c")
```

### Increment and decrement statements (S1)

```
increment-statement = assignment-target ( "++" | "--" ) ;
```

`target++` is exact sugar for `target += 1` and `target--` for
`target -= 1`: same target grammar, same typing, same checked overflow
(`NUMERIC_OVERFLOW`), no IR change.

**Amended in 0.6.0 (S1', bucket 0.6.1):** prefix and postfix forms are
also **expressions** with the C convention: `++i` / `--i` yield the **new**
value, `i++` / `i--` yield the **old** value. With `i = 100`, `PRINT ++i`
prints `101` and `PRINT i++` prints `100`; `i` is `101` after either. As a
statement the value is discarded (0.5.2 behaviour unchanged). See
[0.6.0 language additions](#060-language-additions) for the full rule.

**Confirmed (BDFL, 2026-10-12; §2.6):** lexing of adjacent `--`: the token is produced only when the
two characters are adjacent, and the parser accepts it only after an
assignment target at statement start, so `a--b` is a syntax error (not
`a - -b`). Comments are `//` and `/* */`, so there is no comment collision.

### `PROTECTED` visibility (O3)

`visibility = "PUBLIC" | "PRIVATE" | "PROTECTED"`; `PROTECTED` becomes a
reserved word. It applies wherever `PUBLIC` / `PRIVATE` apply today.

| Access site | `PUBLIC` | `PROTECTED` | `PRIVATE` |
| --- | --- | --- | --- |
| Same class body | yes | yes | yes |
| Subclass (`EXTENDS` chain) body | yes | yes | no |
| Unrelated code (other class, module, `Start`) | yes | no | no |

**Confirmed (BDFL, 2026-10-12; §2.3):** (a) `PROTECTED` on `STATIC` members — allowed, same matrix;
(b) a `PROTECTED` member reached through a base-typed reference from
outside the hierarchy — **no**. Across modules, `PROTECTED` members of an
exported class are visible to classes in other modules that `EXTENDS` it,
and to nothing else. The diagnostic is `PROTECTED_ACCESS`.

### Explicit `OVERRIDE` (O2)

A method that overrides an inherited instance method **must** carry
`OVERRIDE`; `OVERRIDE` becomes a reserved word.

| Shape | Result |
| --- | --- |
| `OVERRIDE` and a matching base method exists | legal; dynamic dispatch as in [Assignment and dispatch](#assignment-and-dispatch) |
| `OVERRIDE` but no ancestor declares the method | static error `OVERRIDE_WITHOUT_BASE` |
| Ancestor declares the method but `OVERRIDE` is missing | static error `OVERRIDE_REQUIRED` |
| `OVERRIDE` with a different signature | static error (signature mismatch) |

`STATIC` methods are not virtual and take no `OVERRIDE`. `PRIVATE` base
methods are not overridable (a same-named method in a subclass is a new
method and needs no marker).

**Confirmed (BDFL, 2026-10-12; §2.2):** keyword order is `PUBLIC OVERRIDE FUNCTION Name(...)` —
`OVERRIDE` immediately before `FUNCTION`, after the visibility (and after
`STATIC`, where it is then rejected); any other position is a syntax error.
`IMPLEMENTS` methods do not take `OVERRIDE` (interfaces are implemented,
not overridden). `OVERRIDE` on a method whose class has no `EXTENDS`, or
whose only same-named ancestor method is `PRIVATE`, is
`OVERRIDE_WITHOUT_BASE`.

Existing 0.5.1 programs that override without the marker become invalid
under this rule; the bucket migrates the repository's fixtures.

### Class downcast → `T OR Error` (O1 — deferred, not in 0.5.2)

**Status (2026-09-19):** cut from the 0.5.2 claim under the bucket's cut
rule. Prerequisite found while sizing: the language cannot construct an
`Error` value (`NEW Error` is not available; only host/runtime paths
produce one) and the IR has no `Error` constant, so the failure half of
`T OR Error` has no lowering. O1 returns in its own bucket together with a
lock on *constructible `Error`* (IR constant + both backends). The text
below stays as the intended surface.

When `expr` has static class type `B` and `C` is `B` or a class that
`EXTENDS` `B`, `expr AS C` has type `C OR Error`: the same object reference
narrowed on success, an `Error` on failure. No exception mechanism exists or
is introduced. Narrowing does not create a second object identity; ARC
counts are unchanged on both paths.

```basic
LET d AS Dog OR Error = pet AS Dog
IF d IS Error THEN
    PRINT d.Message
ELSE
    d.Bark()
END IF
```

Upcasts remain implicit. Numeric / `BOOLEAN` `AS` conversion is unchanged;
diagnostics must name which `AS` is meant.

**Deferred past 0.6 (BDFL, 2026-10-12; §2.1), with the questions it leaves:** (a) candidate **A** (reuse `AS`, above) vs
candidate **B** (`TRYCAST expr AS C`); (b) the `Error` code / Fluent id;
(c) `expr AS C` where `C` is unrelated to the static type of `expr` —
proposed: always a static error.

### Multiple construction via `STATIC` factories (O4)

Normative pattern, no grammar change: a class keeps its single
`CONSTRUCTOR` and exposes alternate entry points as `PUBLIC STATIC
FUNCTION` returning `NEW`. A second `CONSTRUCTOR` signature remains a
static error (constructor overload is **not** part of 0.5.2).

**Status:** opened 2026-09-21 by Carlos (bucket 0.6.1, language), shipped in

### Increment and decrement expressions (S1')

```
increment-expression = ( "++" | "--" ) assignment-target      (* prefix *)
                     | assignment-target ( "++" | "--" ) ;    (* postfix *)
postfix-expression   = primary { postfix-suffix } | increment-expression ;
increment-statement  = increment-expression ;
```

- **Value (C convention, D-061-01).** Prefix `++t` / `--t` evaluates
  `t += 1` / `t -= 1` and yields the **new** value of `t`. Postfix `t++` /
  `t--` performs the same update and yields the **old** value (the value
  read before the update). With `t = 100`: `PRINT ++t` → `101`,
  `PRINT t--` → `100`; after either statement `t` has changed by one.
- **Operand.** `t` is an `assignment-target` — a binding, a member path
  (`SELF.count`, `c.count`) or an element (`a[i]`) — with the typing of
  `t += 1`. A literal (`100++`, `++100`), a call result or a cast is a
  **syntax error**; parentheses around a target are transparent (`(i)++`
  is `i++`). The forms are not chainable: `i++++`, `++i++`, `++++i` are
  syntax errors.
- **Type.** The expression has the type of `t`.
- **Effects and order.** The side effect happens when the expression is
  evaluated, in the ordinary left-to-right order of the enclosing
  expression, once per evaluation. `x = i++` assigns the old value of `i`
  to `x` and increments `i`; `PRINT i++, i` prints `100 101` for `i = 100`.
  The target's sub-expressions are evaluated exactly as in `t += 1`.
- **Overflow.** Checked exactly as `t += 1`: `NUMERIC_OVERFLOW` (runtime
  `Error`), never wrap-around, on both backends. A postfix form that
  overflows raises the error and does not yield the old value.
- **Precedence.** Both forms bind tighter than `**`, unary `-` and `NOT`.
  `-i++` is `-(i++)`; `i++ ** 2` is `(i++) ** 2`; `-++i` is `-(++i)`.
- **Statement form.** `i++` or `++i` alone on a line is a statement; its
  value is discarded and both spellings are the 0.5.2 `i += 1`. Lowering
  may keep the statement path unchanged.
- **Lexing.** Unchanged from 0.5.2: `++` / `--` only for adjacent
  characters, accepted only immediately before or after an assignment
  target, so `a--b` remains a syntax error and `a - -b` needs the space.

**Fixtures:** `tests/grammar/valid/increment-expression.bn` (accept and
run: both forms on a binding, a member and an element, use inside a larger
expression), `tests/grammar/invalid/increment-on-literal.bn`,

## 0.6.2 language additions

Bucket 0.6.2. Both amendments concern literal initializers; neither adds a
keyword.

### Negative constant literals and range checks (C1)

A module constant is initialized by a `constant-literal`
([`0.6.ebnf`](0.6.ebnf)): a literal, or a minus sign applied to one integer or
floating-point literal (`-1`, `-0xFF`, `-2.5`). The minus applies to the
literal's value, so `-0xFF` is `-255`. Inference is unchanged: without a
decimal point the literal is `INTEGER`, with one it is `FLOAT`. A local
`CONST` without `AS` follows the same rule: `CONST x = -1` is `INT32` and
`CONST y = -2.5` is `FLOAT64`.

Every module constant must fit its declared or inferred type, as a binding
initializer must: `EXPORT CONST X = 0x80000000` (inferred `INTEGER`, which is
`INT32`) and `EXPORT CONST U AS UINT32 = -1` are `TYPE_MISMATCH`.

### Integer literals for floating-point bindings (C2)

When `LET`, `CONST`, or `EXPORT CONST` declares exactly one floating-point
type (`FLOAT`, `FLOAT32`, `FLOAT64`) and its initializer is an integer literal
(decimal, hexadecimal, or binary, optionally negative), the initializer
denotes the floating-point value of that integer:

```basic
LET mask AS FLOAT = 0xFF          // 255.0
EXPORT CONST Low AS FLOAT = -0x10 // -16.0
```

The integer must be exactly representable in the declared floating-point
type; otherwise the binding is a `TYPE_MISMATCH`. Only literal initializers
are converted: `LET f AS FLOAT = n` with an `INTEGER` binding `n` remains a
`TYPE_MISMATCH` (use `n AS FLOAT`). Class fields, parameters, arguments,
return values, and assignments are unchanged.

negative, range-limited, and `FLOAT` module constants read through an import),
`tests/grammar/valid/integer-literal-float-binding.bn` and
`tests/grammar/valid/negative-local-constants.bn` (accept and run),

### Number and `BOOLEAN` to text: `AS STRING` (C3)

`value AS STRING` converts a value of any integer type, any floating-point
type, or `BOOLEAN` to the text `PRINT` writes for it
([`console.md`](console.md), "Stream macros"):

- integers: decimal digits, with `-` when negative (`-42`);
- floating point: the shortest decimal that reads back as the same value of
  its type, always containing a decimal point or an exponent (`2.0`,
  `0.30000000000000004`), and `NAN`, `INF`, `-INF`;
- `BOOLEAN`: `TRUE` or `FALSE`.

```basic
LET count AS INTEGER = 3
LET label AS STRING = "items: " + (count AS STRING)      // "items: 3"
LET ratio AS STRING = (1 / 4) AS STRING                   // "0.25"
```

The conversion cannot fail. Any other source type, including an
alternative such as `INTEGER OR Error`, and `NULL`, is a `TYPE_MISMATCH`;
narrow the value first. `STRING AS STRING` is the identity
([Conversions with `AS`](#conversions-with-as-065)). `AS STRING` does not
format: there is no width, precision, or locale.

**Fixtures:** `tests/grammar/valid/as-string.bn` (accept and run on both
backends), `tests/grammar/invalid/as-string-from-alternative.bn`.
`STRING AS STRING` is the identity and is not a reject fixture.

## Alternative types: identity and assignment

Bucket typed-llvm-emitter. Rules 1–2 and 4 record what semantic analysis
already enforces; rules 3 and 5 are BDFL decisions (2026-10-05, 2026-10-06).
No keyword changes.

An alternative type (`value-type` in [`0.6.ebnf`](0.6.ebnf)) is the set of its
members:

1. Order does not matter: `INT32 OR STRING` and `STRING OR INT32` are the same
   type. The only exception is the internal default (rule 5).
2. A member appears once, after aliases are resolved: `INT32 OR INT32` and
   `INTEGER OR INT32` are a `TYPE_MISMATCH`.
3. Widening: a value of an alternative type may be stored in a binding, field,
   argument, or return value whose alternative type contains every member of
   its own (`INT32 OR NULL` → `INT32 OR NULL OR Error`). The value keeps the
   alternative it holds, so `IS` answers as before.
4. Narrowing needs a test: storing an alternative where not every member is
   accepted (`INT32 OR NULL` → `INT32`, or `INT32 OR NULL OR Error` →
   `INT32 OR NULL`) is a `TYPE_MISMATCH` unless an `IS` test has narrowed the
   value first (see "`IS` narrowing after returning branches").
5. Default (BDFL decision, 2026-10-06): a binding or field of alternative type
   still requires `=` (see "STATIC field type defaults"). Where the IR itself
   needs a default value of an alternative type, it is the default of the
   first member (`INT32 OR NULL` is `0`), and a first member `NULL`, `NA`,
   or `EOF` is its own default (`NULL OR INT32` is `NULL`). This is the one
   place where member order matters.

```basic
LET found AS INT32 OR NULL = 7
LET result AS INT32 OR NULL OR Error = found   // widening (rule 3)
IF result IS INT32 THEN
    LET n AS INT32 = result                    // narrowed by IS (rule 4)
END IF
```

## Numeric literals in alternative types

Bucket typed-llvm-emitter. This fills a normative gap; it adds no keyword
and changes no default type.

An integer literal is `INTEGER` (`INT32`) and a floating-point literal is
`FLOAT` (`FLOAT64`) (see the inference rule above and `TYPEOF`). When a
literal is stored in a binding, field, argument, or return value whose type
is an alternative, the stored value takes exactly one of the declared
alternatives:

1. the literal's default type (`INT32` or `FLOAT64`), when it is an
   alternative;
2. otherwise the only alternative of the literal's class (integer or
   floating point);
3. otherwise the store is a `TYPE_MISMATCH`: write the width explicitly
   (`1 AS INT16`).

```basic
LET a AS FLOAT32 OR FLOAT64 = 1.5   // FLOAT64 (rule 1)
LET b AS INT32 OR INT64 = 9         // INT32   (rule 1)
LET c AS INT64 OR Error = 9         // INT64   (rule 2)
LET d AS FLOAT32 OR INT32 = 1.5     // FLOAT32 (rule 2)
LET e AS INT8 OR INT16 = 1          // TYPE_MISMATCH (rule 3)
```

The literal must fit the alternative it takes, as for a single declared type.
`IS` then holds for that alternative and only for it.

**Fixtures:** `tests/grammar/valid/literal-into-numeric-alternative.bn`
(accept and run), `tests/grammar/invalid/literal-ambiguous-numeric-alternative.bn`.

## Conversions with `AS` (0.6.5)

Bucket 0.6.5 (known issue K32). The 0.1 base text on conversions was not
recoverable (see Status); this section states the rules both backends
implement (verified on `bni` and `bnc`, 2026-10-09). It changes no
behaviour.

No conversion is implicit in a store. A value of one primitive type is
stored, passed or returned as another only through `value AS T`
(`cast-suffix` in [`0.6.ebnf`](0.6.ebnf)). `LET wide AS INT64 = narrow`
with `narrow` declared `INT16` is a `TYPE_MISMATCH`; `LET wide AS INT64 = narrow AS
INT64` is valid. Inside one expression, operands of different numeric
types combine by the rule in [Operators](#operators), which converts nothing
that is stored. Literals are not values of a fixed type: an integer or
floating-point literal fits its destination directly
([C1](#negative-constant-literals-and-range-checks-c1),
[C2](#integer-literals-for-floating-point-bindings-c2), [Numeric literals in
alternative types](#numeric-literals-in-alternative-types)).

The primitive numeric types are `BYTE` (0 to 255), `INT8`, `INT16`,
`INT32`, `INT64`, `UINT16`, `UINT32`, `UINT64`, `FLOAT32` and `FLOAT64`.
`INTEGER` is `INT32`, `FLOAT` is `FLOAT64` and `TIMESTAMP` is `INT64`; an
alias converts as the type it names.

| From | To | Result |
| --- | --- | --- |
| Integer | Integer | The same value when the target's range holds it; otherwise the program stops with `NUMERIC_OVERFLOW`. |
| Integer | `FLOAT32`, `FLOAT64` | The nearest value of the target (exact while the value fits the significand: 24 bits for `FLOAT32`, 53 for `FLOAT64`). |
| Floating point | Integer | The value truncated toward zero (`-2.5 AS INT8` is `-2`) when the target's range holds it; otherwise `NUMERIC_OVERFLOW`. `NAN`, `INF` and `-INF` stop with `INVALID_NUMERIC_CONVERSION`. |
| Floating point | Floating point | The nearest value of the target; `NAN`, `INF`, `-INF` are kept. A finite `FLOAT64` beyond the `FLOAT32` range stops with `NUMERIC_OVERFLOW` (BDFL, 2026-10-12). |
| Number | `BOOLEAN` | `FALSE` for zero (including `-0.0`), `TRUE` otherwise. |
| `STRING` | `BOOLEAN` | `FALSE` for the empty string, `TRUE` otherwise (`"0"` and `"FALSE"` are `TRUE`). |
| `NULL`, `NA`, `EOF` | `BOOLEAN` | `FALSE`. |
| Number, `BOOLEAN` | `STRING` | The text `PRINT` writes ([C3](#number-and-boolean-to-text-as-string-c3)). |
| Any type | The same type | The same value (`BOOLEAN AS BOOLEAN`, `STRING AS STRING`, `INT32 AS INT32`; BDFL, 2026-10-12). |

Every other pair is a `TYPE_MISMATCH`: `BOOLEAN` or `STRING` to a number
(text to a number is `BNMath.VAL`), an alternative before it is narrowed
with `IS` (`x AS BOOLEAN` with `x` declared `INT32 OR NULL`), and a temporal
value. A
`BOOLEAN` binding declared without an initializer is `FALSE`; a number is
`0` or `0.0`; a `STRING` is `""`.

Decided by the BDFL on 2026-10-12 (known issue K32 (a)–(d)): a conversion to
the same type is the identity for every type; `NAN AS BOOLEAN` is `TRUE` (it
is not zero); a finite `FLOAT64` beyond the `FLOAT32` range is
`NUMERIC_OVERFLOW`, as every other out-of-range conversion; the `PRINT` text
of a `TIMESTAMP` is its `INT64` value.

## Destructuring `LET` and `STRUCT` literals (0.6.5)

Decided by the BDFL on 2026-10-11 (syntax) and 2026-10-12 (rules).

### Destructuring `LET`

A destructuring `LET` declares several bindings from one vector or one
`STRUCT` value:

```basic
LET [x, y] = point2            // vector: x = point2[0], y = point2[1]
LET [name, port] = site        // STRUCT: the fields name and port
LET [first AS INT64, second AS INT64] = pair
```

Grammar: `"LET" "[" destructuring-binding { "," destructuring-binding } "]"
"=" expression`, where `destructuring-binding = identifier [ "AS"
local-variable-type ]` ([`0.6.ebnf`](0.6.ebnf)).

The source expression is evaluated once. Every binding is out of scope in
it, a repeated binding name is `DUPLICATE_NAME`, and a binding name that is
already declared in the function is `DUPLICATE_NAME` (no shadowing). A
binding without `AS` takes the type of the value it receives; a binding
with `AS` receives that value as an assignment to the declared type.

**Vector source.** Binding `i` (counting from `0`) receives `source[i]`; for
a vector of more than one dimension that is a row (`LET [top, bottom] =
grid` with `grid AS INTEGER[2][3]` gives two `INTEGER[3]`). The number of
bindings must equal the length of the first dimension:

- a fixed vector of another length is a `TYPE_MISMATCH` at compile time;
- a vector whose length is known only at run time — a local `T[n]`, an open
  parameter `T[]`, a pointer region made by `NEW T[n]` — stops the program
  with `INDEX_OUT_OF_BOUNDS` when the lengths differ.

**`STRUCT` source.** Each binding name must be a field of the `STRUCT`, and
the binding receives that field, whatever its position; naming a field that
does not exist is `NAME_NOT_FOUND`. Any subset of the fields, in any order,
may be named. There is no renaming: the binding has the field's name.

**Other sources** — an object, an alternative, a `STRING`, a scalar — are a
`TYPE_MISMATCH`. Objects are read field by field.

**Values.** Each binding holds a copy of the value it receives (value
semantics); an object reference inside that value is a new strong reference
(retained), released when the binding ends. Destructuring exists only in
`LET`: `[x, y] = point2` as a statement is a syntax error.

### `STRUCT` literals

A bracket literal fills a `STRUCT` by position wherever a `STRUCT` type is
declared — a `LET` initializer, a field initializer, an argument, a `RETURN`
value or an assignment — extending [Vector literals take a declared
destination](#vector-literals-take-a-declared-destination-065):

```basic
STRUCT Site
    port AS INTEGER = 80
    name AS STRING
END STRUCT

LET site AS Site = [10, "web"]   // port = 10, name = "web"
```

Element `i` fills the field declared `i`-th, checked as an assignment to that
field's type; an element for a `STRUCT` or vector field may itself be a
bracket literal. The literal must have exactly one element per field:
fewer or more is a `TYPE_MISMATCH` (a field's default does not fill a
missing element). Reordering the fields of a `STRUCT` changes the meaning of
its literals; destructuring, which goes by name, is unaffected. A bracket
literal never makes an object: objects are made by `NEW` and their
`CONSTRUCTOR`.

**Fixtures:** `tests/destructuring.rs` — valid destructuring of a fixed
vector, a run-time-length vector and a `STRUCT`; a `STRUCT` literal in
each destination; invalid count, unknown field, object source, duplicate
name, and short `STRUCT` literal. The run-time length check runs on both
backends for a pointer region (`NEW T[n]`). A local `T[n]` is checked by
the interpreter; native code does not yet index that vector form.
