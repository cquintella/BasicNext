# Bucket 0.4.5 — IR type-boundary validation

Date: 2026-09-06

## Implemented

- `bn_ir::validate` now records the declared type of every SSA result before
  checking executable paths.
- `Phi` incoming values are checked against the result type, including
  integer/float literals, alternatives and dynamic-pointer destinations.
- `Branch` conditions must be BOOLEAN values.
- `Stop` codes must be integer values.
- `Return` shape and value type must agree with the function return type.
- `Copy` operands must match the declared copy type (storage writes retain
  runtime/semantic ownership checks for dynamic pointer/vector and class types).
- Vector elements must match the vector element shape, and all index operands
  must be integer values.
- The rules intentionally do not infer class inheritance from opaque `Named`
  types; that relationship belongs to semantic analysis and is not present in
  the current IR contract.
