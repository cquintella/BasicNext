# Basic Next 0.5.1 — Release notes

**Tag:** [`v0.5.1`](https://github.com/cquintella/BasicNext/releases/tag/v0.5.1)  
**Released:** 2026-09-16 (tag republished on green `main` / publish 2026-09-19)  
**Baseline:** 0.5.0  
**Bucket:** [`done/bucket-0.5.1.md`](../../done/bucket-0.5.1.md) (and follow-on `0.5.1a`–`d` closes under `done/`)

## Highlights

Four toolchain / Host claims closed on top of ARC 0.5.0:

1. **`bn eval`** — first-class eval subcommand for REPLs and hosts (no global `-e`).
2. **Expressive diagnostics (DX1)** — Fluent catalog, structured facts shared by CLI / eval JSON / LSP.
3. **Ordered module search path (MP1)** — repeatable `--module-path`, config array, first hit wins.
4. **`HOST.Exec`** — run an OS executable with argv, capture stdout/stderr/return code; no shell default.

## Language / Host

| ID | Item | Summary |
| --- | --- | --- |
| **H1** | `HOST.Exec` | `IMPORT HOST.Exec`; `Run(program, args) AS Exec.Result OR Error` with `ReturnCode`, `Stdout`, `Stderr`; child stdin closed; restricted profiles deny by default; nonzero child exit remains `Result`; interpret ↔ native parity |

No new language keywords in 0.5.1. BN value `Error` (`T OR Error`) is unchanged by DX1.

## Toolchain

| ID | Item | Summary |
| --- | --- | --- |
| **T1** | `bn eval` | `bn eval SOURCE` or `bn eval --stdin`; oneshot (no `--session` in 0.5.1); auto-promote `FUNCTION Start` with one warning; `--format json` → single JSON v1 envelope |
| **DX1** | Diagnostics | Catalog under `share/bn/diagnostics/en-US/*.ftl` (+ embedded); title / causes / help; warning policy |
| **MP1** | Module path | `--module-path <dir>` repeatable; `module-path = […]` in config; defaults include entry directory + discovered `modules/bn`; same rules for check / run / build / eval |

## Packaging / ecosystem

- Prebuilt `bn` / `bnc` assets on the GitHub Release (Linux/macOS aarch64 & x86_64, Windows x86_64) plus `bn.1` and `SHA256SUMS`.
- Jupyter kernel and VS Code extension moved to **standalone** repositories (see README).

## Not in 0.5.1

- Persistent eval session (S1); language keyword `EVAL`; LLVM-as-eval backend.
- Shell-string process launch; stdin feed / PTY / background jobs for `HOST.Exec`.
- OO surface of 0.5.2 (`PROTECTED`, `OVERRIDE`, qualified import, `++`/`--`).

## Upgrade notes

1. Install or pin **v0.5.1** (`BN_VERSION=v0.5.1` or GitHub Latest once this tag is Latest).
2. Prefer `bn eval` for fragment hosts; keep files on `bn run` / `bn check`.
3. Pass extra library roots with `--module-path` instead of inventing nested copy layouts.
4. Import `HOST.Exec` only where policy allows; never pass a shell command string as `program`.
