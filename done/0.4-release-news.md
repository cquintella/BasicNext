# Basic Next 0.4.0 — Release notes

Released: 2026-09-02

Basic Next 0.4.0 is the production-hardening and developer-tooling release of
the Rust reference implementation. It preserves the explicit 0.3 language
contract, adds bounded `ASYNC`/`AWAIT`, and closes the main BNWeb security,
resource-lifecycle, debugger, and notebook integration gaps.

## Highlights

### Language and runtime

- `ASYNC` and `AWAIT` are part of the 0.4 grammar, semantic checks, typed IR,
  and interpreter runtime.
- Async work uses bounded dispatch queues, bounded waits, cancellation, output
  limits, and isolated task output.
- Source spans remain available through the lexer, parser, semantic pipeline,
  IR, diagnostics, and debugger.
- `bn check`, `bn run`, and the supported `bn build` path report the 0.4
  version consistently as `bn 0.4.0`.

### BNWeb security and HTTP hardening

- SSRF checks classify IPv4-mapped IPv6 addresses as IPv4 and reject private,
  loopback, link-local, CGNAT, documentation, benchmark, multicast,
  unspecified, and IPv6 ULA destinations.
- The same egress policy is applied after DNS resolution and across redirects;
  typed `EgressPolicy` allowlists can further restrict schemes, CIDRs, ports,
  redirects, and deadlines.
- Session identifiers contain at least 128 bits from a CSPRNG. Rotation
  invalidates the previous identifier, and cookies default to `Secure`,
  `HttpOnly`, and `SameSite=Lax`.
- Cleartext and TLS servers use validated, registry-backed limits for
  connections, backlog, workers, pending work, headers, bodies, and timeouts.
- Accept admission and handler execution are bounded; overload is separated
  from rate limiting (`503` versus `429`), and shutdown performs cancellation,
  drain, join, and deadline reporting.
- HTTP security headers, TLS handshake deadlines, header/body/connection
  deadlines, HTTP/2 idle protection, request correlation IDs, bounded server
  statistics, and broad BNLog redaction are included.
- Token-bucket refill uses sub-second time precisely and preserves fractional
  refill remainder under traffic faster than 1 Hz.

### Developer tools

- `bn dap` now provides an event-driven native DAP service with breakpoints,
  pause/resume, `next`, `stepIn`, `stepOut`, locals, stack snapshots, and
  source spans.
- The VS Code extension bridges to `bn dap` over bounded stdio instead of
  launching `bn run` through `runInTerminal`.
- Debugger stepping is defined as stepping at IR-instruction boundaries with
  source-line mapping. It is not a REPL and does not provide arbitrary
  expression evaluation.
- The Jupyter integration is explicitly Program-only: every cell is a complete
  `Start()` program executed in a fresh process with `--no-filesystem`; state
  does not survive between cells.

## Configuration and compatibility

Normative BNWeb thresholds are recorded in
[`config/0.4-bnweb-limits.toml`](../config/0.4-bnweb-limits.toml). Runtime code
loads one validated typed snapshot; application code should use the typed
server options rather than duplicating limit literals.

The active 0.4 language authority is the [0.4 specification](../docs/language/0.4/0.4.md),
[EBNF](../docs/language/0.4/0.4.ebnf), and [keyword registry](../docs/language/0.4/keywords.md),
with the inherited 0.3 and 0.2 contract incorporated by reference.

## Verification

The release gate passed locally:

```text
cargo fmt --check
cargo test --all-targets -- --test-threads=1
cargo clippy --all-targets -- -D warnings
git diff --check
node plugins/vscode/test/debug-adapter.js
node plugins/vscode/test/test.js
PYTHONPATH=plugins/jupyter plugins/jupyter/.venv/bin/python -m unittest tests.test_kernel tests.test_jupyter -v
```

The release binary was built with `cargo build --release`, reported `bn 0.4.0`,
validated `examples/hello.bn` with `check` and `run`, and produced a native
artifact with `bn build`. The generated executable produced the same output as
the interpreter in the local artifact check. Detailed evidence is recorded in
[`0.4-conformance.md`](../ongoing/0.4-conformance.md).

## Deliberate boundaries

The following are not claimed as part of 0.4.0:

- LLVM lowering for async operations;
- persistent or distributed Jupyter `Session` mode;
- atomic TLS certificate reload;
- HTTP/3, QUIC, WebSocket, and other deferred transport surfaces;
- production deployment controls such as certificate/key storage, firewall
  policy, OS descriptor limits, log retention, and process supervision.

These boundaries are documented in the 0.4 conformance record and language
specification. The source repository contains the release commit; binary
distribution remains managed through the project’s GitHub Releases process.
