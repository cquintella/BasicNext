# Basic Next Language Specification 0.1 (Draft)

This specification defines the core required for small programs. Anything not
defined here is not part of Basic Next 0.1.

## Lexical structure

Source code is Unicode encoded as UTF-8. Spaces and tabs separate tokens; a
line ending separates statements. Line continuation is not part of 0.1.

Identifiers start with an ASCII letter or `_` and continue with ASCII letters,
digits, or `_`. They are case-insensitive: `counter`, `Counter`, and `COUNTER`
refer to the same name. Reserved words are also case-insensitive and cannot be
used as identifiers.

Line comments begin with `REM` or `//` and end at the line ending. Both forms
are equivalent and are recognized outside strings. Strings use double quotes,
cannot span lines, and accept only `\"` and `\\` escapes. Integer literals are
decimal digit sequences; floating-point literals have a decimal point, such as
`3.14`.

### Reserved words

The [keyword registry](keywords.md) records the meaning and decision status of
every keyword. The list below is the reserved set in this draft.

```text
AND       AS        BOOLEAN   CLASS     CONST     ELSE
END       FALSE     FLOAT     FOR       FUNCTION  HOST
IMPORT    INTEGER   LET       MOD       NEXT      NOT
OR        PRINT     REPEAT    RETURN    STRING    SUB
SYSTEM    THEN      TO        TRUE      UNTIL     VOID
WHILE     REM
```

### Symbols

```text
+  -  *  /  =  <>  <  <=  >  >=  +=  -=
(  )  ,
```

The lexer must recognize the longest valid symbol: for example, `<=` is not two
tokens (`<` and `=`), and `+=` is not `+` followed by `=`.

### Structural grammar

The notation below uses EBNF: `{x}` means repetition, `[x]` means an optional
item, and quotes indicate literal words or symbols. The expression grammar is
specified in the types and expressions section.

```ebnf
program          = { blank-line | import-declaration | declaration } ;
blank-line       = newline ;
import-declaration = "IMPORT" import-path "AS" identifier newline ;
import-path      = "HOST" "." identifier | identifier "." identifier ;

declaration      = sub-declaration | function-declaration | class-declaration ;
sub-declaration  = "SUB" identifier "(" [ parameters ] ")" newline
                   { statement } "END" "SUB" newline ;
function-declaration = "FUNCTION" identifier "(" [ parameters ] ")" "AS" type newline
                   { statement } "END" "FUNCTION" newline ;
class-declaration = "CLASS" identifier newline
                   { sub-declaration | function-declaration }
                   "END" "CLASS" newline ;

parameters       = parameter { "," parameter } ;
parameter        = identifier "AS" type ;
type             = "BOOLEAN" | "INTEGER" | "FLOAT" | "STRING" | "VOID" ;
statement        = { non-newline-character } newline ;
identifier       = ( letter | "_" ) { letter | digit | "_" } ;
letter           = "A"…"Z" | "a"…"z" ;
digit            = "0"…"9" ;
non-newline-character = ? any character except a line terminator ? ;
newline          = "\\n" | "\\r\\n" ;
```

`statement` is intentionally open in this section; complete statement forms
appear in the expressions and control-flow sections.

## Types

Primitive types are `BOOLEAN`, `INTEGER`, `FLOAT`, `STRING`, and `VOID`.

Declarations use `name AS TYPE`. `LET name = expression` infers the expression
type; `LET name AS TYPE = expression` requires a compatible assignment. `CONST`
uses the same form and cannot be reassigned.

## Program and declarations

A compilation unit contains `IMPORT`, `CLASS`, `SUB`, and `FUNCTION`. The
executable module is the unit loaded by the runtime and must declare exactly
one `SUB Start()`; the runtime calls this procedure to start the program.
Statements cannot appear loose at module level.

The executable module may declare `IMPORT HOST.main AS main`. `HOST` represents
the host environment and `main` is the `SYSTEM` object it provides. Only the
executable module may import `HOST.main`. The `SYSTEM` interface will be
defined separately; it is not part of the base syntax or semantics of 0.1.

`SUB` does not return a value; `FUNCTION` declares a return type after `AS`.
Bodies end with `END SUB`, `END FUNCTION`, or `END CLASS`.

## Expressions

Literals, identifiers, calls, and parentheses compose expressions. Operators,
in descending precedence: unary `NOT`, `-`; multiplicative `*`, `/`, `MOD`;
additive `+`, `-`; comparison `<`, `<=`, `>`, `>=`; equality `=`, `<>`; logical
`AND`, `OR`.

`+` concatenates strings when both operands are `STRING`; otherwise it is
numeric addition. There is no implicit coercion between `STRING` and numbers.

## Statements

Basic statements are `LET`, `CONST`, assignment, `PRINT`, call, `RETURN`,
`IF`, `WHILE`, `REPEAT`, and `FOR`.

```basic
IF condition THEN
    PRINT "yes"
ELSE
    PRINT "no"
END IF

WHILE condition
    counter += 1
END WHILE

REPEAT
    counter -= 1
UNTIL counter = 0

FOR i AS INTEGER = 0 TO 9
    PRINT i
NEXT
```

`IF`, `WHILE`, and `UNTIL` require `BOOLEAN`. `WHILE` tests its condition
before the body; `REPEAT` executes its body at least once and ends when `UNTIL`
is true. `FOR` iterates inclusively and uses step `1` in 0.1. `RETURN` in a
`FUNCTION` requires an expression compatible with the return type; in a `SUB`,
it does not accept an expression.

## Still undecided

`MATCH`, `STRUCT`, `ENUM`, `INTERFACE`, modules, collections, union types,
error handling, and concurrency require proposals before becoming part of a
later version of the specification.
