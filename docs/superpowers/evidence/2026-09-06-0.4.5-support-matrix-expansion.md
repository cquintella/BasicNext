# Bucket 0.4.5 — support matrix expansion

Date: 2026-09-06

## Implemented

Added six fixture-exact rows to `tests/compiler-capabilities.json` for:

- all scalar widths and boolean emission;
- input/EOF preservation;
- shared BNMath scalar symbols;
- bounded HOST.Net resolution;
- seeded random branching;
- repeated SSA-value observation.

Added a seventh row for the verified LLVM/native parity fixture covering
`BNMath` `FLOAT[4]` reductions and vector `MAX` through the shared `bn_rt`
f64 ABI.

Each row now also records the exact `bn_ir::Instruction` variants emitted by
its fixture. The capability test invokes `bn check --emit ir` and compares that
inventory with the catalog, so a row cannot silently drift to a different IR
shape while retaining the same user-facing operation label.

The rows declare concrete operations, types, conditions, target, provider and
the exact test fixture. No support label was added for an unverified feature.

## Verification

```text
python3 -m unittest tests.test_capabilities -v
passed: 3 tests; all 19 capability rows passed, including lowered-IR inventory
python3 -m json.tool tests/compiler-capabilities.json
passed

python3 scripts/support_matrix_report.py
2262 combinations; 74 covered; 2188 gaps

The report derives the `Instruction` and `Type` inventories from their Rust
models and expands them across `interpret`, `llvm-native` and `wasm32`. A gap
is explicit when no catalog row cites evidence for that instruction/type/target
combination; type coverage is matched to each row's `type_constraints`. The
report does not turn a gap into an unsupported claim.
```

This closes the bounded G2c seed for the compile-tested subset. It does not
close the broader inventory requirement: the complete opcode/type/target
inventory and deferred-feature rows remain to be cataloged.
