# Basic Next 0.4 Conformance and Security Evidence

Status: **BNDispatch RECOVERY ACCEPTED — 2026-09-02; RELEASE HYGIENE PENDING**.

This record distinguishes executable local evidence from deployment
responsibilities. It does not claim that a kernel, operating system, network,
certificate authority, or process supervisor has been hardened by BNWeb.

## Mandatory quality gate

The following commands are the release evidence for Rust changes:

```text
cargo fmt --check
cargo test --all-targets -- --test-threads=1
cargo clippy --all-targets -- -D warnings
git diff --check
```

The local suite must not require public DNS/HTTP, external certificates,
wall-clock sleeps, or a deliberate entropy failure. Tests that bind TCP may be
run in an environment where local socket admission is permitted; restricted
sandboxes must report that platform limitation rather than convert it into a
false pass.

## Residual-risk decisions

- Optional TLS certificate reload is not part of the base 0.4 acceptance and
  remains deferred until a separate authority decision supplies an atomic
  provider contract.
- Persistent Jupyter Session mode is not part of 0.4; accepting it requires a
  new state, rollback, retention, and capability contract.
- Async BNWeb handlers are not accepted merely because the generic dispatch
  provider works. They require the separate bounded response-ownership and
  cancellation matrix in Activity 5.2; the current transport slice remains
  explicitly in progress and is not part of the closed conformance set.
- Platform limits, deployment TLS key storage, firewall policy, log retention,
  and process supervision remain outside the language/runtime conformance
  claim.
- The native BNDispatch recovery claim is accepted. The overall 0.4 release
  gate remains open until repository-wide diff hygiene and the separately
  scoped release checks are clean.
