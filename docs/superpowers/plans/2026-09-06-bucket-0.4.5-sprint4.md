# Basic Next 0.4.5 Sprint 4 Implementation Plan

> **For agentic workers:** Execute this plan task-by-task with
> `superpowers:subagent-driven-development` or `superpowers:executing-plans`.
> The repository instruction not to commit overrides generic commit steps.

**Goal:** Close the expressive-diagnostics Sprint 4 in `bucket-0.4.5.md` with
complete registry/catalog coverage, lazy CLI/LSP rendering, warning policy,
and the already-scoped companion process log.

**Architecture:** Preserve the shared diagnostic fact model and keep Fluent
prose at the render boundary. All pipeline producers emit registered typed
diagnostic facts; filtering and deduplication happen before rendering; CLI and
LSP project the same rendered model. The existing process log remains a
separate bounded operational record and never replaces the diagnostic store.

**Tech Stack:** Rust workspace, `bn_diag`, Fluent `.ftl` resources, TOML
configuration, CLI integration tests, LSP protocol tests, and existing BN
runtime fixtures.

**Spec:** `todo/proposals/expressive-diagnostics.md`,
`ongoing/bucket-0.4.5.md` §4, and `ongoing/WBS-0.4.5.md` Phase 6.

## Global Constraints

- Scope is Basic Next 0.4.5 only; do not alter the completed legacy
  `ongoing/bucket.md` release bucket.
- BN program `Error` (`Code AS INTEGER`, `Message AS STRING`) remains
  unchanged and separate from toolchain diagnostics.
- Severity and suppression policy remain in Rust/configuration, never Fluent.
- The catalog ships embedded `en-US` shards and supports the locked overlay
  resolution order; overlays cannot change diagnostic identity or severity.
- No production emit site may bypass the registered diagnostic model at G4.
- Keep Rust modules focused, preserve ownership/source spans, and do not add
  `unsafe` code.
- Every behavior change follows TDD: failing test, minimal implementation,
  passing focused test, then refactor.
- Before completion run `cargo fmt --check`, `cargo test`,
  `cargo clippy --workspace --all-targets -- -D warnings`, and
  `git diff --check`.
