# Basic Next 0.3 Vector and LLVM Contract Design

## Scope

This change amends the 0.3 contract in four coordinated areas: declaration-time
vector dimensions, numeric type lowering, explicit LLVM control-flow lowering,
and resilient IR test construction. The vector feature is a one-time allocation:
the dimension expression is evaluated at the binding declaration and the vector
does not resize afterwards.

## Language contract

`LET v AS INTEGER[n]` is valid for local bindings. The expression `n` must
resolve to an integer value, must be non-negative, and is evaluated exactly once
before the vector is initialized. Parameters, fields, and return types continue
to require literal dimensions in this increment. No `RESIZE` operation is added.

The AST preserves each dimension as either a literal or an expression. Semantic
analysis rejects non-integer, negative, and overflowing dimensions with a
source-spanned diagnostic. The IR represents the evaluated dimension as an
operand of the vector-default/allocation instruction, so the interpreter and
LLVM backend consume the same operation.

## Numeric and LLVM contract

The backend maps `INTEGER` and `INT32` to `i32`, `BYTE` to `i8`, `UINT64` to
`i64`, `FLOAT32` to `float`, and `FLOAT64` to `double`. The existing `FLOAT`
alias retains its language-defined semantic type.

LLVM lowering walks the entry block and every reachable `BasicBlock` explicitly,
lowers each instruction, and emits `Jump`, `Branch`, `Return`, and `Stop`
terminators. It never executes the program to manufacture build output.
Integer arithmetic uses checked operations in the interpreter and LLVM overflow
intrinsics (for example `llvm.sadd.with.overflow.*`) with a shared
`NUMERIC_OVERFLOW` trap path. Unsupported instructions, HOST capabilities, and
BN provider calls return `BUILD_LOWERING_UNAVAILABLE` before emitting output.

## Test and metadata contract

The parser test `test_parser_vector_variable_size` proves that the AST retains
the identifier expression `n`. Runtime and semantic tests cover non-integer,
negative, zero, and overflow dimensions. LLVM integration tests cover the exact
integer/float types, CFG terminators, arithmetic overflow, and controlled
unsupported lowering. `Module` implements `Default`, and manual IR tests use
struct update/default construction. The package license is `MPL-2.0`.

## Compatibility and sequencing

The accepted grammar, language prose, keyword registry, positive/negative
fixtures, WBS, and release bucket are updated together. This work is a new
contract gate after the active BNDispatch sprint; existing BNDispatch changes
remain preserved and are not silently marked complete by this design.
