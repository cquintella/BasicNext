# 0.4.5 runtime value leaf cut

## Scope

`bn_value` now owns the interpreter `Value` enum. It depends on `bn_types` for
numeric kinds and `bn_runtime` for the checked opaque allocation handle; it has
no dependency on the frontend, IR, Executor, DataFrame, HTTP or Net modules.
The root runtime consumes this same enum, while existing root module paths
remain compatibility boundaries.

The enum preserves scalar, vector, function/type, error, HOST resource,
record/object, pointer and temporal variants. No behavior was duplicated or
changed by the move.

## Remaining work

The Executor and host-provider modules still depend on the root package and
must be extracted in later runtime slices. This evidence does not close
Activity 3.3, GC-EXT or native BNData/DataFrame binding.
